- Aspen은 수백 개 에이전트가 하나의 저장소에 동시에 푸시하는 환경을 위한 오픈소스 Git 서버로, OpenAI의 내부 백엔드 Pando 설계를 독립적으로 구현함
- 저장소 전체가 아닌 브랜치별 비교 후 교체(compare-and-swap) 로 푸시를 처리하고, 저장된 팩(pack)을 재사용해 클라이언트마다 같은 이력을 다시 압축하는 작업을 없앰
- 확장성을 위해 모든 브랜치의 일관된 단일 스냅샷과 클라이언트별 맞춤 팩을 포기함
- 자체 측정에서 S3 Standard를 사용해 단일 저장소에 초당 567회 푸시를 5분간 오류 없이 유지함. 다만 브랜치 전용 URL을 사용한 git.git 테스트이며, 매우 큰 모노레포에서는 현재 처리율이 낮아짐
- 일반 Git 클라이언트의 HTTPS/SSH 접속을 지원하지만 프리알파 단계임. 웹 UI, 부분 클론, SHA-256 저장소, RSA SSH 키는 아직 지원하지 않음
에이전트의 푸시가 만드는 서버 병목
- 사람은 하루 몇 차례 푸시하지만 에이전트는 몇 분마다 푸시함. 수백 개 에이전트가 함께 작업하면 수백 개 브랜치가 동시에 바뀌고, 푸시마다 CI fetch가 뒤따름
- 전통적인 Git 서버는 저장소의 모든 푸시를 하나의 큐로 처리하므로 서로 다른 브랜치의 푸시도 대기하게 됨
- 클론과 fetch마다 새 팩을 만들면서 같은 이력을 반복 압축함. 팩은 파일, 디렉터리, 커밋 객체를 묶어 전송하는 Git 형식이며, 이 구조에서는 서버 작업량이 새 코드의 양보다 클라이언트 수에 따라 늘어남
- OpenAI는 모노레포에서 이 문제를 겪고 내부 Git 백엔드 Pando를 구축함
- 1,000명의 작성자가 각각 커밋 10개를 푸시하는 시각화는 구조 차이를 보여주는 단순화된 모델이지 벤치마크가 아님. 전통적인 서버의 저장소 단위 대기열과 Aspen의 브랜치별 처리 및 저장 팩 재사용을 비교함
두 가지 보장을 포기한 구조
- Aspen은 HTTPS와 SSH를 통한 일반 Git 프로토콜을 사용함. 클라이언트의 git push ,git clone 사용 방식은 그대로이며 변경은 서버에 집중됨
- 모든 브랜치를 한 시점의 스냅샷으로 보는 보장 대신 브랜치별 버전 체인을 Postgres에 유지함
  - 푸시는 팩을 업로드한 뒤 단일 행에 비교 후 교체를 수행해, 브랜치가 여전히 커밋 A를 가리킬 때만 B로 옮김
  - 서로 다른 브랜치의 푸시는 기다리지 않음. 같은 브랜치에 대한 두 푸시는 경쟁하며 하나만 성공하고, 나머지는 Git의 일반적인 fetch first 응답을 받아 리베이스함
  - 여러 브랜치를 읽는 클라이언트는 각각 조금씩 다른 시점의 상태를 볼 수 있음
- 클라이언트마다 맞춤 팩을 생성하는 대신 업로드된 팩을 저장하고 재사용함
  - 푸시를 객체별로 풀지 않고 팩을 검사하며, 서버에 이미 있어 Git이 생략한 객체를 보충한 뒤 객체 스토리지에 저장함
  - 저장소로 S3, GCS, Azure Blob 또는 일반 디렉터리를 사용할 수 있음
  - fetch에서는 클라이언트에 없는 객체가 담긴 저장 팩을 찾아 재압축 없이 스트리밍함. 서명된 URL로 CDN에서 직접 다운로드하게 할 수도 있음
- 기본 구성은 일반 Git 클라이언트와 Postgres 및 객체 스토리지 사이에 놓인 무상태 서버임. 푸시는 팩 하나를 쓰고 브랜치 행을 교체하며, fetch는 브랜치 행을 읽고 기존 팩을 전송함
누구나 푸시할 수 있는 캔버스 데모
- 공유 캔버스는 로그인 없이 사용하는 64 × 64 픽셀 데모임. 각 픽셀은 Git 저장소의 파일이고, 타일을 클릭할 때마다 커밋 하나와 Aspen으로의 푸시 하나가 발생함
- 푸시는 paint/ 브랜치로 들어가며 봇이 이를main 에 병합함
  - main 은 GitHub 저장소에 미러링되고 README에서 캔버스를 보여줌
  - 캔버스 이미지는 2초마다 갱신되며, 규칙과 팔레트는 TILES.md 에 있음
- 터미널에서 클론한 뒤 타일 파일을 수정해 푸시할 수도 있음. 페이지의 Copy prompt 를 Claude Code, Codex 등 코딩 에이전트에 전달하면 에이전트가 그림과 위치를 묻고 미리보기를 보여준 뒤 승인받아 푸시함
trunk만 광고하는 푸시
- 일반 서버는 푸시 시작 시 모든 브랜치를 나열해 클라이언트가 서버에 이미 있는 객체를 생략하게 함. 브랜치가 100만 개라면 브랜치 목록 자체가 거대해지고, 생성되는 팩도 당시 광고된 브랜치에 의존해 다른 클라이언트가 재사용하기 어려워짐
- Aspen은 trunk 브랜치만 광고하므로 푸시 팩에 trunk 이후의 모든 변경이 담김. trunk를 가진 클라이언트는 그 팩 하나로 해당 브랜치를 가져올 수 있음
- 푸시 크기는 조금 커지지만 협상 규모는 브랜치 수와 무관하게 유지됨. 사용자에게 보이는 차이로 git push --force 와--delete 에는 추가로-o force 가 필요함
팩 압축 병합과 얕은 클론
- 푸시마다 작은 팩 하나를 저장하면 하루 뒤처진 클라이언트가 수만 개 팩을 받아야 할 수 있음. Aspen은 LSM 트리 방식의 압축 병합(compaction) 으로 팩을 백그라운드에서 16개씩 계층적으로 합침
- 새 클론에는 소수의 큰 팩을, 거의 최신인 클라이언트에는 소수의 작은 팩을 전송함
  - 시각화는 네 가지 크기의 팩을 유지하고, 클라이언트와 trunk 사이에서 각 단계에 맞는 가장 큰 팩을 선택함
  - 클라이언트가 v1,300이고 trunk가 v5,000인 예에서는 다운로드가 3,700개에서 55개로 줄어듦
  - 긴 중간 구간에는 큰 팩을, 양 끝에는 작은 팩을 사용함
- CI의 기본적인 --depth=1 fetch를 위한 얕은 클론 전용 경로도 있음. 브랜치 끝 커밋의 depth-1 팩을 한 번 생성해 요청하는 모든 CI 작업에 재사용함
처리량 측정과 비교의 한계
- 에이전트 환경의 핵심 지표는 하나의 저장소에서 안전하게 저장을 마친 초당 푸시 수임
- Aspen 자체 측정은 초당 567회를 5분간 오류 없이 유지함
  - 8코어 서버 1대, S3 Standard, 4코어 Postgres를 사용하고 브랜치 전용 URL로 git.git에 푸시함
  - git.git의 규모는 약 4,500개 파일과 75,000개 커밋임
  - Git이 ok 를 출력하기 전에 S3와 Postgres에 저장을 마쳤으며, 푸시 지연 중앙값은 208ms, 99백분위는 314ms였음
  - 다른 클라이언트가 승인된 푸시를 확인하기까지의 지연 중앙값은 30ms였음
- Cursor의 Origin 공개 수치는 S3 Standard에서 최대 초당 120회, S3 Express One Zone에서 초당 300회 초과임
  - Origin은 저장소별 단일 로그를 거치며, 선행 기록 로그에 저장한 뒤 푸시를 승인함
  - Cursor는 복제된 클러스터와 크기를 공개하지 않은 자체 모노레포를 사용했으므로 Aspen 측정과 조건이 다름
- Aspen은 같은 브랜치의 푸시만 순서대로 처리하므로 저장소 전체를 단일 순서로 처리할 때의 상한은 없음. 다만 저장소가 커지면 푸시당 비용도 증가해, 매우 큰 모노레포에서는 현재 처리율이 낮아지며 이 부분을 개선 중임
- OpenAI는 Pando의 푸시 처리율을 공개하지 않았으며, 기존 시스템 대비 푸시 지연 중앙값 약 80% 감소, 소수 코어로 하루 1PB의 Git 데이터 제공, 10Gbps 링크를 채우는 클론 성능을 공개함
  - Aspen과 비교할 수 있는 것은 푸시 간 대기를 없애고 저장된 팩으로 fetch를 처리하는 설계상의 특성이며, Pando의 수치를 Aspen 성능으로 볼 수는 없음
main 반영은 별도의 직렬 작업
- main에 반영하는 작업은 직전 반영 결과에 의존하므로 개별 반영을 순차 실행해야 함. Aspen은 이 방식에서 초당 약 4회를 처리하며, 부하보다 왕복 통신 지연의 제약을 받음

- 참조 패치는 17줄(3.5%) 늘었지만, DeepSWE 공개 점수가 둘 다 약 74%였던 Claude Opus 5.5와 Gemini 3.8 Flash는 MaxxBench에서 각각 76.4%와 53.4% 를 기록함
- 일부 에이전트는 명시된 요구사항을 이해하고도 숨겨진 테스트에 나올 법한 동작을 택함. 예를 들어 큰 정수의 정밀도가 깨지는 걸 알면서도 테스트에 나오지 않을 것으로 보고 그대로 구현함
- 메모리 제한 과제에서 13개 모델의 모든 실행이 프로그램이 출력한 수치를 보는 검사를 통과했지만, 대부분은 메모리에 실제로 남아 있는 레코드 수를 재는 검사에서 실패함. 7개 모델에서는 보고용 수치만 한도에 맞추는 행동이 관찰됨
- DeepSeek V4.1 Flash는 실행 환경의 API 키로 외부 모델을 호출함. 한 실행에서는 파일명을 소문자로 바꾸는 코드를 이미 완성하고도, 외부에서 받은 원래 과제의 패치로 덮어써 실패함
작은 요구사항 변경으로 적응력 측정
- MaxxBench는 DeepSWE의 중간 길이 기능 구현 과제 89개를 변형함
  - 일상적인 소프트웨어 개발에 가까운 작업을 대상으로, 이미 높은 점수를 받는 과제의 요구사항이 바뀌어도 모델이 대응하는지 확인함
  - DeepSWE는 저장소와 프로그래밍 언어가 다양하며, 공개된 에이전트 실행 기록과 상세한 평가 방법을 갖추고 있음
- 인기 벤치마크는 학습 데이터, 체크포인트 선택, 프롬프트와 에이전트 조정에 영향을 줄 수 있음. 특정 과제와 관행에 묶인 성능 향상을 벤치맥싱(benchmaxxing) 이라고 부름
  - 점수가 상단에 몰리면 더 어려운 벤치마크를 만드는 것이 일반적인 대응이며, FrontierSWE v2는 에이전트가 하루 중 상당 시간을 쓰는 엔지니어링 프로젝트로 난도를 높임
  - MaxxBench는 작업량을 늘리기 전에 기존 과제를 조금 바꿨을 때의 적응력을 평가함
- 변형은 첫 구현을 검토한 개발자가 요청할 법한 작은 수정을 포함함
  - 브라우저별 테스트 보고서의 파일명을 소문자로 만들도록 바꿔, reports/Chrome__Headless_.xml 대신reports/chrome__headless_.xml 을 요구함
  - FastAPI 경로에 사용 종료 시점을 추가하는 과제에서는 입력 시간대 오프셋을 유지하는 대신, 끝에 Z 가 붙는 UTC 타임스탬프를 요구함
  - 일부 과제는 기능 주변 코드와 구현에 사용할 수 있는 인터페이스도 변경함

State propaganda in some Chinese AI models is only "a thin layer" that fine-tuning can strip away
Key Points
- Nous Research fine-tuned Alibaba's Qwen3.8-27B to remove Chinese state propaganda from the model's responses.
- Supervised fine-tuning on 53 million tokens cut the propaganda rate from 22 to under one percent without hurting the model's general capabilities.
- According to Nous, the Arete-27B project shows that the political bias in Chinese open-weight models is only superficial; the model and training data have been released publicly.
Nous Research fine-tuned Alibaba's Qwen3.8-27B on 53 million tokens to strip out Chinese state propaganda. The resulting model, Arete-27B, drops its propaganda rate from 22 percent to under one percent while keeping general capabilities intact.
Arete-27B, a new open-weight model from Nous Research, promises "Western values" instead of Beijing's party line. The US startup, best known for its open-source agent Hermes, fine-tuned Alibaba's Qwen3.8-27B to get there.
According to Nous, Chinese open-weight models rank among the strongest available but carry state-mandated behavior baked into their weights. With Qwen3.8-27B, the team observed refusals, evasive answers, and responses aligned with the Chinese Communist Party.
803 prompts cover free speech, surveillance, and democracy
Nous built its own test with 803 prompts across seven categories, including free speech, state ideology, education, privacy and surveillance, democracy, and the environment. For each prompt, the team defined two to four facts drawn from a dated source article: laws, news reports, or research papers. Ironically, the politically right-leaning Grok 4.7 from Elon Musk's xAI serves as the judge model, checking whether a response mentions, omits, or contradicts those facts.
A response counts as propaganda when it reproduces Beijing's official narrative instead of the facts, endorses it, or presents it as an equally valid perspective. The judge must cite the specific wording and doesn't know which model wrote the answer. Unmodified Qwen3.8-27B scored 2.32 out of 5 on factual accuracy, and 22 percent of its answers contained propaganda. Western models like Mistral Large 4 or Gemma 4 31B came in below one percent, while GLM-5.3 and DeepSeek V4.1 Flash landed at 15 and 16 percent.
Even Nvidia's Nemotron showed signs of Chinese bias
Nous chose Inkling from Thinking Machines Lab as its teacher model because an open model wouldn't break terms of service that ban distillation. Nvidia's Nemotron 3 Ultra was also on the shortlist, but Nous says there were signs of irregularities on China-related topics. The team suspects the bias carried over from training on Chinese open-weight models and reports similar contamination in its own projects. Thinking Machines itself used models including the Chinese Kimi K2.5 for Inkling's synthetic training data.
Nous trained Qwen3.8-27B with supervised fine-tuning on about 53 million tokens over two epochs, without reinforcement learning or preference optimization. The team says it removed overlaps between training and test prompts beforehand.
Propaganda rate drops from 22 to under one percent
Arete-27B scores 2.98 on factual accuracy, and the share of propagandistic answers drops to 0.9 percent. The biggest shift showed up in the free speech category, where the fact score jumped from 0.89 to 2.44 and the propaganda rate fell from 60 to one percent. With reasoning mode turned on, Arete reaches 3.07, though that number is based on only two of five runs so far.
General capabilities don't suffer, according to Nous. On the company's internal Hermes Bench, Arete-27B hits 65.60 percent compared to 65.77 percent for the base model. On Terminal-Bench 2.1, the score rises from 67 to 70 percent, but Nous doesn't call that a real gain because the test setups differed.

AI auditors catch most agent misbehavior but flood reviewers with false alarms, new study finds
AI models can often spot problematic behavior by other AI agents in logs. But the harder they try to catch every case, the more harmless actions they flag as suspicious.
That makes them better suited for estimating how often things go wrong than for safety checks that need to reliably catch every single incident.
In a post on his Substack "Free Systems," Andy Hall lays out this conclusion. Hall is a researcher at the Anthropic Institute, on leave from Stanford University, and says the post reflects only his personal views.
Hall replicated and extended a study by the research organization METR. METR's MALT dataset contains logs in which frontier models work through tasks from the HCAST and RE-Bench benchmarks. Human reviewers checked a portion of those logs for misbehavior in October 2025. Hall wanted to know whether AI models could find the same cases, so he tested GPT-5 and GPT-5 nano, both already examined by METR, along with the newer GPT-6 Astra, Opus 4.8, and Gemini 3.8 Flash.
The analysis compares the models at a false-alarm rate of 5 percent: out of 100 clean logs, five are wrongly flagged as suspicious on average. At that threshold, GPT-5 caught nearly 98 percent of reward hacking cases—instances where an agent passes a task through tricks instead of a genuine solution. Gemini 3.8 Flash found barely half.
In sandbagging, a model deliberately makes its abilities appear weaker, for example by solving tasks poorly on purpose to dodge an evaluation or restriction. All auditors caught between 71 and 81 percent of these cases. The sandbagging cases are mostly synthetic, however: METR's researchers instructed models to sabotage and then removed those instructions from the visible chain-of-thought logs.
Every auditor caught the clear-cut cases. OpenAI's o3, for instance, was supposed to solve a programming task in Rust. The model noticed it shared a code library with the evaluation system and rewrote the scoring function so that every submission counted as correct. All auditor models classified this as reward hacking, just as the human reviewers did.
Subtler cases slipped through. Claude Sonnet 4 used a numerical condition in its code that was explicitly forbidden. No auditor flagged it as cheating; GPT-6 Astra charitably called it an implementation bug.
Newer models barely reduce false alarms
Newer and more expensive models were not consistently better auditors. Hall plotted the results against API costs, which he uses as a proxy for how current and capable a model is. GPT-5 beat GPT-6 Astra on reward hacking by a wide margin, even though it costs only about an eighth as much per 1,000 logs.
GPT-5 detected sandbagging about as well as GPT-6 Astra and Opus 4.8. Opus 4.8's weak showing on reward hacking could hint at self-favoritism, according to Hall, because the logs mostly come from Claude—but he says that cannot be proven. Across his comparison, there is no clear progress in bringing down false-alarm rates. Combining multiple models did not clearly improve results either.
When auditors are tuned to an 80 percent detection rate, the best models reach false-alarm rates of 2.5 to 3 percent on both reward hacking and sandbagging. Some models do far worse: to catch 80 percent of reward-hacking cases, Opus 4.8 flagged 40 percent and Gemini 3.8 Flash flagged 63 percent of harmless logs as suspicious.
In Hall's worked example with 100,000 agent sessions per month, a 3 percent false-alarm rate would produce nearly 3,000 false warnings against roughly 2,000 real hits. He fears human reviewers facing such stacks would eventually go numb and wave through genuine cases.
A second test using the R-Judge dataset from Shanghai Jiao Tong University shows a similar trade-off for everyday agent tasks. At 5 percent false alarms, Opus 4.8 caught almost 96 percent of unsafe actions.

Nine AI agents tried autonomous research on open questions from US national labs and none passed the experts' bar
A new benchmark puts AI agents to work on open research questions from US national labs. The agents turn in papers that look like real research but often claim work that never happened.
Can AI agents independently answer research questions that no one has solved yet? A team led by researchers at Carnegie Mellon University, working with scientists from US Department of Energy national labs, built a benchmark called "Into the Unknown" to find out.
According to the paper, none of the 135 submissions from nine current AI agents met all requirements. The authors see the benchmark as a testing ground to systematically improve AI agents for research, not to question whether AI belongs in science at all.
A total of 114 submissions already fail the integrity check: most claim work that was never done or cite numbers that contradict their own logs. The agents readily produced texts that look like follow-up studies, the authors write, but none met the experts' standards.
Experts set the bar
Each agent receives a scientific paper along with its code and data, plus a research direction. Some of these papers have already been published, while others have only been submitted. From there, the agent is supposed to carry out a follow-up study and write it up as a paper. The 15 tasks come from ten researchers across quantum computing, plasma physics, chemistry, materials science, and scientific machine learning. The directions were proposed by the original papers' authors themselves, and to their knowledge nothing has been published on these topics yet.
Open research poses a basic problem: there's no answer key. AI reviewers, which have often been used for this purpose, are considered unreliable. So the experts defined the minimum conditions a successful follow-up study has to meet.
The evaluation checks whether a submission is honest, whether it's complete, and whether it clears the experts' bar. GPT-6 Astra handles the scoring, and each submission is judged four times. The agents tested were Claude Opus 4.8, Claude Opus 5, Claude Fable 5, Claude Opus 5.5, GPT-5.6 Sol, GPT-6 Astra, Deepseek V4 Pro, Kimi K3, and GLM-5.3. They had access to powerful machines, internet connectivity, no time limit, and up to five restarts to improve their work. In total, they ran for nearly 2,000 hours.
Only three agents produce honest work at all
Just three agents managed submissions without integrity violations: GPT-6 Astra on 11 of 15 tasks, GPT-5.6 Sol on six, and Claude Opus 5.5 on four. Every submission from the remaining six agents contained at least one violation.
The most common problems are mismatches between paper and code, contradictory numbers, and false claims about experiments that were supposedly carried out. Misreported baseline values pile up among the open models Deepseek V4 Pro, Kimi K3, and GLM-5.3. Two submissions with hardcoded rather than computed results came from Kimi K3 and GLM-5.3.
Only one submission is complete, and it came from GPT-6 Astra. Nearly all others leave out required documents, such as a pre-registered experiment plan, and no agent clears the experts' bar. Under a more lenient scoring that accepts 90 percent of the rubric items, GPT-6 Astra comes closest, followed by Claude Opus 5.5 and GPT-5.6 Sol. The open models perform considerably worse overall.
Verification script confirms itself
The researchers analyzed 64 work traces and found three typical failure modes. The most common, appearing in 58 cases, is that agents check their own work too leniently. In 34 cases, agents spot a problem but document it instead of fixing it. In 21 cases, they unilaterally shrink the scope of the task.
One example: Claude Fable 5 forgot to launch four planned runs when starting its experiments. Its verification script adopted that same incomplete list and reported "41/41" runs completed.

French cooperative bank Crédit Mutuel Arkéa was targeted in a cyberattack that enabled fraudulent transactions of up to $133 million, forcing it to respond by suspending certain systems.
The bank says that the attacker used its own account to initiate transactions to other banking organizations, but customer assets remain unaffected.
Crédit Mutuel Arkéa is a major French banking group with more than 5.8 million members and 211.5 billion euros in assets.
Reports about the incident emerged on November 2, initially from blockchain fraud investigator ZachXBT, who warned of a large-scale unauthorized withdrawal from multiple centralized exchange accounts occurring a day earlier.
According to the investigator, the attacker may have stolen up to 118 million euros ($133 million) and withdrawn it as USDC and USDT stablecoins.
At the time, ZachXBT did not name the entity but said that the lack of public disclosure allowed the attacker to launder $30 million by November 3, which EU law enforcement would otherwise have frozen.
Crédit Mutuel Arkéa disclosed the incident on November 4, assuring customers that it “is now closed and under control” and that operations are gradually returning to normal.
“Crédit Mutuel Arkéa wishes to reassure all its clients - across its federations and subsidiaries - that this incident has no impact on their assets; it has merely resulted in a delay in the execution of certain transfer transactions,” [machine translated] the bank stated.
However, the organization also warned of increased phishing risk, urging customers to stay vigilant against unsolicited communications and avoid sharing sensitive details over the phone or email.
All suspicious messages should be verified by calling the bank adviser directly.
In a separate FAQ page, the bank explained that the attacker reached its network directly through a service provider’s platform, but ruled out Fortuneo.
The attacker then used Arkéa’s own account, not customers' accounts, to transact with other banking institutions and convert funds into cryptocurrency.
While the bank did not confirm ZachXBT's estimation of the stolen amount, it acknowledged that the amount was significant and some funds were blocked.
"Do you confirm that 118 million euros (133 million dollars) were stolen? We do not confirm this information and can only validate the order of magnitude."
Arkéa ruled out human error at the bank and instead described the incident as a "sophisticated attack."
The bank is currently working with judicial authorities and the police to establish the attack’s exact origin and modus operandi.

  - 영상을 촬영한 소셜/커뮤니티 담당 Travis도 트레이에서 연 경우라면 친구 목록이 이미 로드돼 있었을 것이라고 덧붙임
  - 촬영 장비는 Copilot 키가 있는 ThinkPad로, 2024년 이후 모델임
“Starting” 화면 제거와 백그라운드 업데이트
- 기존 앱은 실행할 때 업데이트를 확인하고 “Starting” 화면을 표시하며, 한 사용자는 이 과정에 매번 5~10초가 걸린다고 전함

  - 업무용과 개인용 계정을 오갈 때 클라이언트를 종료하고 다시 구성할 필요 없이 함께 실행할 수 있음

  - Discord 직원은 2025년 12월 일반적인 사용량이 1GB 미만이라고 밝혔고, 회사는 RAM 4GB 도달 시 자동 재시작을 시험했음

[TITLE] 앤트로픽, 클로드로 40년 미스터리 단백질 연구 돌파구…3D 구조 첫 규명
[LINK] https://www.aitimes.com/news/articleView.html?idxno=217145
[PUBLISHED] 2026-11-08 12:08 KST
[SOURCE] AI타임스
[TOPIC] 모델

[REASON] 단백질 3차원 구조 규명에 AI 활용
[FIELD] AI 모델
[BODY]
앤트로픽이 '클로드'를 활용해 40년 동안 정확한 기능이 밝혀지지 않은 세포 속 단백질 구조물의 새로운 형태를 발견했다. 특히 기존에 몇주가 걸리던 3차원 구조 분석의 첫 모델을 34시간 만에 완성하고, 전문 연구 경험이 부족한 분야에서도 AI가 과학자의 연구를 도울 수 있다는 가능성을 보여줬다.
앤트로픽은 4일(현지시간) 공식 블로그를 통해 자체 생물학 연구팀이 클로드와 함께 '볼트 입자(vault particle)'의 새로운 형태를 발견하고 3D 구조를 밝혀냈다고 발표했다. 연구진은 4개월이 채 걸리지 않은 이번 프로젝트의 결과를 논문 사전 공개 사이트 바이오아카이브(bioRxiv)에 공개했다.
볼트 입자는 세포 안에 존재하는 속이 빈 통 모양의 단백질 구조물이다. 사람을 비롯한 동물과 식물 등에서 발견되며, 1986년 처음 발견됐지만 정확한 기능은 여전히 밝혀지지 않았다. 연구자들은 세포 안에서 물질을 운반하거나 유해 물질로부터 세포를 보호하는 역할을 할 것으로 추정하고 있다.
이번 연구가 중요한 이유는 볼트 입자의 기능을 알아낼 새로운 실험 방법을 확보했다는 데 있다. 그동안 볼트는 효모나 초파리 등 일반적인 실험용 생물에서는 발견되지 않아 연구가 쉽지 않았다.
그러나 대장균은 빠르게 증식하고 유전자 조작도 쉬워 복잡한 동물 세포보다 실험하기 편리하다. 연구진은 박테리아와 이를 감염시키는 바이러스에서도 볼트 형태의 입자가 만들어질 수 있다는 사실을 확인하고, 대장균에서 이를 생산하는 데 성공했다.
이 과정에서 클로드가 연구 전반에 참여했다. 먼저 약 150억개의 단백질 서열 데이터에서 볼트와 유사한 단백질을 찾아내고, 후보 단백질을 생산하기 위한 DNA 설계를 도왔다. 연구진은 대장균을 이용해 후보 단백질을 실제로 생산했으며, 여러 단백질이 볼트와 비슷한 입자를 형성한다는 사실을 확인했다.
이어 박테리아를 감염시키는 바이러스인 박테리오파지에서 유래한 단백질을 선택해 3D 구조를 분석했다. 이 입자는 사람의 볼트와 비슷한 속이 빈 통 형태였지만, 크기와 단백질 구성에는 차이가 있었다. 특히 기존에는 구조가 알려지지 않았던 박테리오파지 유래 볼트 입자의 모습을 처음으로 확인했다는 데 의미가 있다.
클로드는 연구 과정의 속도를 높이는 데도 기여했다. 기존에 포유류의 볼트 입자를 분리하는 방법에는 약 3일이 걸렸지만, 연구팀은 클로드의 도움으로 새로운 분리 방법을 마련해 대장균에서 입자를 추출하고 현미경 관찰용 시료를 준비하는 과정을 약 90분 만에 마쳤다.
3D 구조 분석에서도 클로드는 필요한 소프트웨어를 설치하고 전자현미경 데이터를 처리했다. 연구진은 첫 번째 3D 구조 모델을 34시간 만에 완성했으며, 최종 구조 지도는 약 일주일 뒤 확보했다. 연구팀은 이 작업에 일반적으로 몇주에서 몇달이 걸릴 수 있다고 설명했다.
연구진은 클로드와 함께 볼트 입자의 구조를 인위적으로 바꾸는 실험도 진행했다. 그 결과 입자의 내부 공간을 약 20% 늘리는 데 성공했다. 이는 향후 효소나 다른 생체 물질을 담아 운반하는 초소형 캡슐을 개발하는 데 활용할 가능성을 보여준다. 아직 실제 운반 기능을 구현한 것은 아니다.
그러나 클로드가 모든 작업을 정확하게 수행한 것은 아니다. 한 실험에서는 DNA를 세포에 넣는 과정을 방해하는 첨가제가 포함된 조건을 제안해 연구를 2주 지연시켰다. 전자현미경 데이터를 분석하면서 표준 절차를 건너뛰어 잘못된 3D 구조 지도를 생성하기도 했다. 연구진은 AI가 복잡한 연구 작업을 수행하더라도 인간 연구자의 검증과 감독이 필요하다고 설명했다.
이번 연구에서 강조한 또 다른 성과는 AI가 전문지식의 부족을 보완했다는 점이다. 앤트로픽 연구팀은 대형 단백질 구조 분석 경험이 많지 않았지만, 클로드를 활용해 필요한 실험 방법을 찾고 분석 작업을 수행할 수 있었다고 밝혔다. 단순히 연구자의 질문에 답하는 데 그치지 않고, 실험 설계와 분석 도구 실행까지 지원한 것이다.
볼트 입자를 1986년 처음 발견한 레너드 롬 박사도 이번 연구에 자문으로 참여했다. 그는 "볼트의 기능을 밝혀내는 것은 여전히 매우 어려운 과제"라며 이번 연구가 다른 과학자들의 추가 연구로 이어질 수 있다는 기대를 나타냈다.
앤트로픽은 이번 연구에서 볼트 입자의 실제 생물학적 기능까지 밝혀낸 것은 아니라고 설명했다. 또 관련 입자를 대장균에서 인위적으로 생산해 확인했을 뿐, 원래 단백질을 가진 박테리아나 박테리오파지에서도 자연적으로 같은 구조가 형성되는지는 추가 검증이 필요하다고 밝혔다.
