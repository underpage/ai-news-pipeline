[TITLE] Amazon Uncovers AI Agent Campaign Targeting LiteLLM, Dify, and Other Apps for API Keys
[TITLE_KO] 아마존, API 키 탈취 위해 LiteLLM, Dify 등 노린 AI 에이전트 공격 캠페인 적발
[LINK] https://thehackernews.com/2026/11/amazon-uncovers-ai-agent-campaign.html
[PUBLISHED] 2026-11-16 16:34 KST
[SOURCE] The Hacker News
[TOPIC] 에이전트, 개발, 모델
[SCORE] 9
[REASON] 공격자 AI 에이전트가 다른 AI 앱 API 키 탈취 악용
[FIELD] 보안
[BODY]
Attackers' AI agents have been hunting for weak spots in internet-exposed AI apps such as LiteLLM, One API, and Dify to steal the AI provider keys stored inside, according to the agents' own records.
The records, which Amazon's threat intelligence team captured with decoy servers, describe stolen keys being used to run the AI models that powered the search for more keys.
The team said this week that it cannot verify the outcomes reported by the agents. It has moderate confidence that the agents ran on ARTEX, an open-source AI tool for penetration testing.
The records include a playbook of known entry points for each targeted product. It lists default administrator credentials such as LiteLLM's default master key, unfinished installs that an outsider could take over, and known flaws in Langflow and RAGFlow.
In a separate case reported this week, Cloudflare's incident responders saw ARTEX gain access to a compromised API token that had been used for CI/CD. The token had no IP restrictions or rate limiting, and the activity that followed included 400 database dump requests in an hour. The company has not said whether those requests returned any data.
An operator gives ARTEX a target and a goal, and a planner agent splits the goal into tasks for worker agents that run security tools. To decide each next step, the agents send their work to a large language model (LLM).
The decoy servers, part of a network called MadPot, posed as popular LLM services. From October 3 to late last week, the agents sent it requests that often carried a campaign's full history, including the operators' instructions and the agents' reported findings.
Those captured agent records describe work done on systems MadPot does not watch. "Amazon Threat Intelligence did not observe that activity as it happened and cannot verify the outcomes the agents reported, but the records show what the actors were pursuing," the team said.
The team assessed, with moderate confidence, that the operators were separate China-linked groups, citing Simplified Chinese prompts and China time zone settings, among other evidence.
In the main campaign, the agents looked for internet-exposed AI apps, extracted the provider keys stored inside, verified that the keys worked, and added them to a shared pool. They focused on apps that hold keys for many providers, because one weak admin page there can expose many accounts.
Targets named in the records include LLM gateways and proxies such as One API, New API, Veloera, Sub2API and LiteLLM, and AI app builders such as Dify, FastGPT, Langflow, RAGFlow, Open WebUI, LobeChat and Ollama.
The playbook also covers management and provider settings endpoints that need no login, an authentication bypass through the isCliRequest header in One API family systems, and server-side request forgery (SSRF) through URL-fetch features to reach cloud metadata services. Other entries cover secrets left in client-side JavaScript, source maps, debug routes and environment files.
When the agents found cloud credentials, they targeted managed services that host AI models, secret stores, and application identities, prioritizing premium AI models over general cloud access.
To find leaked keys, the agents used internet scanning services and certificate transparency logs, and searched GitHub repositories and event archives, npm and PyPI packages, container image layers, notebooks, model-hosting spaces, paste sites, and Telegram channels.
The records cover hundreds of targets across AI app platforms and other systems. The team notified AWS customers who may have been affected.
Microsoft reported last week that attackers were using agentic AI tools such as ARTEX for GitHub secret hunting, looking for exposed credentials that included API keys for AI inference.
On August 26, the company described an earlier RAGFlow attack, in which a hidden hook captured AI provider keys as users entered them, and a compromise of a LiteLLM gateway that exposed provider keys.

엔비디아가 사람의 작업 영상을 보고 새로운 동작을 학습하는 데 이어, 자신의 행동으로 주변 환경이 어떻게 변할지까지 예측하는 차세대 로봇 AI 모델 '그루트 2(GR00T 2)'를 공개했다. 새로운 작업 50개를 대상으로 한 실험에서 추가 시연 없이 평균 40%의 성공률을 기록했으며, 작업당 5회의 시연과 30분간의 추가 학습으로 성공률을 95%까지 높였다.
엔비디아는 지난 9일(현지시간) 미국 오스틴에서 열린 로봇 학습 학회(CoRL)에서 그루트 2를 발표했다. 핵심은 로봇의 동작뿐 아니라 동작 이후 주변 환경이 어떻게 변할지까지 함께 예측하는 '월드 액션 모델(WAM)'을 도입했다는 점이다.
엔비디아는 지난해 3월 첫 범용 휴머노이드 모델인 '그루트 N1'을 공개한 뒤 N1.5와 N1.6, N1.7을 거치며 명령 이해와 동작 정확도, 다양한 로봇에 대한 적용 능력을 개선해 왔다. 기존 모델이 주변 상황과 언어 명령을 이해해 로봇의 동작을 생성하는 데 집중했다면, 그루트 2는 동작과 그에 따른 미래 영상을 동시에 예측하도록 설계를 바꿨다.
예를 들어 로봇이 물체를 집을 때 단순히 팔과 손의 움직임을 생성하는 것이 아니라, 물체가 어떻게 움직이고 주변 상황이 어떻게 달라질지까지 예측하는 방식이다. 이를 통해 사람이나 다른 로봇의 작업 경험을 새로운 로봇에 적용하는 능력을 높였다.
그루트 2는 사람의 1인칭 시점 작업 영상 40만시간 이상을 비롯해 휴대형 그리퍼 시연과 로봇 원격 조작 데이터 등을 학습했다. 사람의 행동과 다양한 로봇의 움직임을 함께 학습해 특정 로봇이 직접 수행한 적 없는 작업에도 대응하도록 설계됐다.
실제로 대상 로봇이 경험하지 못한 50개 작업에서 별도 시연 없이 평균 40%의 성공률을 기록했다. 작업당 1회의 시연 데이터를 추가해 미세조정하면 성공률이 71%로 올라갔고, 5회 시연에서는 95%를 기록했다. 5회 시연에 필요한 로봇 데이터는 작업당 3분 미만이었으며, 엔비디아 RTX 5090 한 대에서 약 30분간 추가 학습했다.
사람의 시연만으로 기술을 익히는 실험도 진행했다. 사람이 실험용 깔때기에 여과지를 끼우고 세척액을 적시는 작업을 보여주자, 로봇은 해당 작업에 대한 직접적인 조작 시연 없이 65%의 성공률을 기록했다. 휴대형 그리퍼로 시연한 장난감 덤프트럭 조립 기술도 다른 로봇 팔에 전이해 60%의 성공률을 보였다.

이전 모델과 비교한 실험에서도 성능 개선이 확인됐다. 시뮬레이션 학습 데이터를 추가해 유니트리 G1 휴머노이드가 낯선 환경에서 작업을 수행하도록 한 평가에서 기존 그루트 1.7의 성공률은 40.0%였지만, 그루트 2 터보는 63.3%를 기록했다.
추론 AI와 결합하면 여러 동작이 필요한 복잡한 작업도 수행할 수 있다. 추론 모델이 작업 순서를 결정하고 진행 상황을 확인하는 동안 그루트 2가 실제 물체를 조작한다. 오류가 발생하면 추론 모델이 복구 방법을 판단해 다시 작업을 지시한다. 장난감 비행기와 트랙터, 자동차를 연속 조립하는 실험에서는 각각 100회 중 97~98회 성공했다.
휴머노이드용 경량 모델 '그루트 2 터보(GR00T 2 Turbo)'도 공개했다. 20억개 매개변수 기반으로, 유니트리 G1에 탑재된 엔비디아 '젯슨 토르(Jetson Thor)'에서 직접 실행할 수 있도록 설계했다. 실제 시연에서는 팝콘을 담아 서빙하는 작업을 48회 모두 성공했으며, 다양한 물체가 놓인 테이블을 정리하는 작업에서도 93%의 성공률을 기록했다.
산업 현장에서의 적용도 시작되고 있다. 폭스콘은 서버 제조 공정 자동화에 그루트 2를 활용하고 있으며, 지멘스는 산업 현장에 적용할 수 있는지 평가하고 있다. 넥수니는 세탁물 취급 작업을 시험 중이고, 마이크로AGI는 로봇 팔을 이용한 이더넷 케이블 교체 작업에 활용하고 있다.
그루트는 엔비디아가 차세대 성장 시장으로 육성하는 로봇 AI 플랫폼의 핵심이기도 하다. 엔비디아는 로봇의 행동을 담당하는 그루트와 물리 세계 학습을 위한 '코스모스(Cosmos)', 가상 훈련 환경인 '아이작 랩(Isaac Lab)', 로봇 탑재용 컴퓨팅 장치인 젯슨을 결합해 로봇 개발 전 과정에 필요한 기술을 공급하고 있다.
이는 로봇 제조사들이 엔비디아의 AI 모델로 로봇을 학습하고, 시뮬레이션 환경에서 성능을 검증한 뒤 실제 로봇에서도 엔비디아의 반도체를 활용하도록 하는 사업 전략이다. 로봇 시장이 성장하면 AI 학습용 GPU뿐 아니라 로봇에 탑재되는 컴퓨팅 장치의 수요도 확보할 수 있다.
엔비디아는 그루트 2를 통해 로봇마다 특정 작업을 반복적으로 가르쳐야 하는 부담을 줄이고, 사람의 경험과 다른 로봇의 데이터를 활용하는 범용 로봇 AI 개발을 가속한다는 계획이다. 이번 성능은 연구팀이 설정한 작업과 시험 환경에서 얻은 결과로, 실제 제조 현장에서의 안정성과 경제성은 추가 검증이 필요하다.

[FIELD] 보안

An 11-year-old Linux kernel vulnerability, dubbed NoisyTCP, affects almost all Linux distributions and lets attackers crash systems running Nginx, Apache, and SSH servers with default configurations.
According to Hyunwoo Kim, the security researcher who discovered it, this pre-authenticated remote corruption flaw (tracked as CVE-2026-99288) stems from a NULL pointer dereference weakness in the Linux kernel's TCP networking subsystem.
Unauthenticated attackers can trigger it remotely via maliciously crafted TCP packets that exploit the timing between SYN cookie handling and socket hashing to crash the kernel and operating system on targeted servers.
However, while CVE-2026-99288 exploits cause a kernel panic and take down the host, they don't allow threat actors to alter data or gain arbitrary code execution.
Kim added that although attackers can exploit this vulnerability against any Linux system that receives TCP packets directly and runs Nginx, Apache, or an SSH server, "the race window is narrow, so triggering it against a quiet bare-metal server can take a long time."
"Due to a race condition during lockless socket lookups, recycled socket memory can be accessed before it is properly initialized and hashed. A remote attacker could exploit this issue by generating network traffic that drives socket reuse, triggering a NULL pointer dereference and kernel crash that results in a Denial of Service (DoS)," the Red Hat security team explained.
"To trigger this vulnerability, a stale ehash lookup and the freeing and reallocation of an existing request socket must proceed concurrently in different RX contexts. Packet processing has to be spread out by using the difference in receive hash between IPv4 fragments and regular TCP packets, so it can be triggered against servers that have two or more RX queues, or where RPS distributes packets across multiple CPUs," the researcher said.
While a CVE-2026-99288 patch is already available and a fix was already merged into the mainline Linux kernel two weeks ago, the researcher advised those who can't apply it or upgrade immediately to disable SYN cookies (which will unfortunately lower protection against SYN flood attacks) and serialize to a single RX queue to block the race required for successful exploitation.
In May, Kim also disclosed Dirty Frag, a Linux local privilege escalation flaw that chains RxRPC (CVE-2026-43500) and xfrm-ESP (CVE-2026-43284) page-cache write flaws to gain root access on major distributions, including Ubuntu, Red Hat Enterprise Linux, CentOS Stream, and Fedora.
More recently, in July, he also disclosed Januscape, a 16-year-old Linux kernel vulnerability that enables attackers to escape a virtual machine and run arbitrary code on the host.

You can now self-host Kitesurf, Cloudflare’s open-source browser for AI agents
Kitesurf is Cloudflare’s browser for AI agents, built to load web pages and run their JavaScript on Cloudflare Workers without starting up a full desktop browser. Cloudflare has published its source code so developers can inspect it, modify it, test it on their own machines, and deploy a copy to their Cloudflare account.
A browser without Chromium
Kitesurf needs no browser container, and it can return screenshots of the pages it loads. It supports the Chrome DevTools Protocol (CDP), the interface automation tools use to control a browser, so clients such as Puppeteer can connect to it. Cloudflare built it to use less CPU and memory than Chromium and to scale across its Workers network.
Kitesurf splits the work three ways. The Engine handles sessions and incoming connections, PageScript executes the page and its scripts, and PageRenderer turns the result into an image. Underneath, Kitesurf relies on open-source Rust packages compiled to WebAssembly: Blitz for HTML parsing, the DOM, layout, and painting; Stylo for CSS; Linebender libraries for text layout and 2D graphics; and Krilla for PDF output. Boa runs JavaScript inside WebAssembly, but only as a last resort, when a page’s scripts can’t run in Dynamic Workers.
Running it yourself
After meeting the repository’s build requirements, a local copy takes four commands: clone the repository, change into it, install dependencies with pnpm, and run pnpm run dev. The first build compiles the Rust core and its dependencies, so expect a wait; later builds reuse the cache.
Wrangler then serves the engine at 127.0.0.1:8787, where a Puppeteer script can connect. An agent harness can be pointed at the same CDP port. In Cloudflare’s words, “agents love CDP.”
Deploying takes pnpm run deploy from the repository root. “A Workers Paid plan is required because Kitesurf uses Dynamic Workers to create isolated Workers for pages,” the Cloudflare team noted.
Kitesurf is available for free on GitHub.

[TITLE_KO] 우버의 보안 AI 프레임워크, 자율 AI 에이전트 전 생애주기 거버넌스 지원

[SOURCE] InfoQ
[TOPIC] 에이전트, 개발
[SCORE] 7
[REASON] 자율 에이전트 전 생애주기 보안 통제 프레임워크 공개
[FIELD] AI 에이전트
[BODY]
In a recent article, Uber Engineering highlights the limitations of traditional identity and API controls in securing AI agents that dynamically reason over external content and take real-world actions. To address this challenge, Uber developed a framework to determine whether an agent's action is appropriate given the user's request, the agent's intended purpose, its permissions, and the context of the interaction.
Identity and authorization systems can determine whether a user or service has permission to access a resource, but they can't determine whether an agent's proposed action is appropriate in context.
This creates multiple risks, including prompt injection, tool and memory poisoning, goal hijacking, behavioral drift, and hallucination-driven actions, which Uber's framework addresses through three layers spanning the entire agent lifecycle, from pre-deployment to runtime enforcement to post-deployment continuous assurance.
At provisioning time, agents must be registered in the Uber AI Registry, establishing identity, ownership, persona, permitted intents, constraints, dependencies, and risk classification. This process is automated using Argus, which analyzes the agent's source code, prompts, configurations, dependencies, exposed endpoints, and tool-invocation paths to identify security weaknesses. The same approach is enforced for MCP servers and tools used by the agents.
At runtime, the framework extends the traditional security model based on policy administration, policy decision, and policy enforcement to incorporate behavioral authorization, which evaluates whether an agent's actions are appropriate in a given context.
Behavioral authorization is implemented through three components: the AI Registry, AI guards, and Agent Guard runtime hooks. The AI Registry defines and manages agent policies, personas, intents, and constraints, while AI Guards evaluate interactions and proposed actions against established policies. Agent Guard runtime hooks invoke AI Guard "at critical checkpoints and applying its verdict before an interaction or action is allowed to proceed".
After deployment, the focus shifts to Continuous Assurance, which relies on end-to-end observability, auditing, explainability, and replay. This layer comprises two main main components: a unified execution trace that connects agent actions, tool calls, and security decisions; and recorded interactions that can be replayed whenever policies and guardrails are updated to assess their effectiveness in the new context.
Uber also identified several challenges in implementing security controls in production, including balancing policy restrictiveness to avoid both excessive false positives and insufficient protection, minimizing runtime latency, reducing developer friction during framework setup, and moving beyond generic controls towards agent-specific policies, which "made enforcement more contextual and precise".
Commenting on Uber's approach on LinkedIn, UN senior information technology officer Tristan G. raised several concerns, noting that while "per-agent personas, intents, constraints and calibration" is what adds the most value, they also come at a significant cost, as "the effort scales with the number of workflows". Additionally,
By its own account, the strongest control was restricting agents to explicit constraints, which is least privilege rather than a new idea. For me, the open question is how this works for agents you don't build, such as vendor or SaaS agents where you can't insert your own enforcement hooks.
On similar lines, AI architect Pratik Dhanave also observes that:
The lesson they call least glamorous is the one they rate most effective: explicit intents and constraints per agent. Not generic thresholds, which failed because every agent has a different purpose and risk profile. The cost is flexibility, and they say it is worth paying.

[FIELD] 신기술
[BODY]
앤트그룹이 로봇이 손끝의 촉각 정보를 이해하고 물체를 잡는 힘까지 판단할 수 있도록 하는 AI 모델을 공개했다. 시각과 언어, 동작 생성에 이어 촉각까지 로봇 AI에 결합한 것으로, 열쇠로 자물쇠를 열거나 치약을 적절한 힘으로 짜는 등 섬세한 손동작을 구현할 수 있도록 했다.
앤트그룹 산하 로비앤트(Robbyant)는 10일 촉각 기반 로봇 파운데이션 모델 '링봇 터치(LingBot-Touch)'를 오픈소스로 공개했다. 이 모델은 약 5000시간에 달하는 실제 촉각 데이터를 학습해 접촉 위치와 압력, 힘의 분포 및 시간에 따른 변화를 파악한다.
가장 큰 특징은 서로 다른 원리로 작동하는 촉각 센서의 데이터를 하나의 표현 체계로 통합했다는 점이다. 자기식, 압저항식, 시각 기반 촉각 센서 등 3종류의 신호를 공통된 촉각 정보로 변환해 다양한 로봇 손과 센서 환경에서 활용할 수 있다.
기존에는 촉각 센서의 종류나 로봇 손이 바뀌면 데이터를 다시 수집하고 모델을 재학습해야 하는 일이 많았다. 링봇 터치는 사람의 촉각 장갑과 로봇 손에서 수집한 정보를 함께 학습해 이러한 개발 부담을 줄이고, 기존 로봇 제어 AI에도 촉각 인식 기능을 추가할 수 있도록 했다.
실제 로봇을 이용한 26개 작업 평가에서도 성능 개선이 확인됐다. '샤르파 웨이브(Sharpa Wave)'와 'X핸드(XHand)' 등 두 종류의 로봇 손을 대상으로 기존 제어 AI 모델 4종에 링봇 터치를 적용한 결과, 평균 작업 수행 평가 점수가 기존보다 13.9~24.8%포인트 높아졌다. 이 평가는 작업의 중간 단계에도 부분 점수를 부여하는 방식으로, 전체 작업을 완수한 비율과는 차이가 있다.
샤르파 웨이브 로봇 손으로 병뚜껑을 여는 작업에서는 촉각 정보를 사용하지 않았을 때 평가 점수가 56.25%였지만, 링봇 터치를 적용하자 90%로 상승했다. 지퍼백 닫기와 SD카드 꺼내기 등에서도 성능 개선이 나타났다.
열쇠를 자물쇠에 넣고 돌리거나 치약을 적절한 압력으로 짜는 작업도 시연했다. 카메라만으로는 정확히 파악하기 어려운 접촉 상태와 힘의 변화를 촉각 정보로 보완한 결과다.
이번 발표는 앤트그룹이 최근 집중해 온 로봇 사업과도 연결된다. 앤트그룹은 2024년 말 로봇 전문 자회사 로비앤트를 설립하고 지난해에는 요리와 서비스 업무를 수행하는 로봇 'R1'을 공개했다. 유니트리 등 중국 로봇 기업에도 투자하며 관련 사업을 확대해 왔다.
올해 들어서는 로봇의 시각 인식과 동작 생성을 담당하는 '링봇 VLA', 물리 세계의 움직임을 예측하는 '링봇 월드' 등 로봇 AI 모델을 잇달아 공개했다. 이번 링봇 터치는 이러한 모델에 촉각 정보를 추가해 실제 물체를 더 정밀하게 다룰 수 있도록 하는 기술이다.
로비앤트는 약 550만개 매개변수를 갖춘 경량 모델 '링봇 터치 타이니(Tiny)'를 비롯해 두 가지 모델 크기를 제공한다. 자체 개발한 링봇 VLA뿐 아니라 π0.5, 디퓨전 폴리시(Diffusion Policy), T-Rex 등 외부 로봇 제어 모델과도 연동할 수 있다. 코드와 사전 학습 가중치는 깃허브와 허깅페이스에 아파치 2.0 라이선스로 공개됐다.

미국과 한국, 일본 등 9개국이 중국의 영향력으로부터 AI 공급망을 보호하기 위한 공동 선언에 서명했다. 반도체와 핵심 광물, 에너지 등 AI 산업에 필요한 기술과 인프라 가운데 보호가 필요한 분야를 공동으로 선정하고, 중국에 대한 공급망 의존도를 낮추기 위한 협력을 강화하기로 했다.

독일과 스웨덴, 네덜란드, 유럽연합(EU) 집행위원회도 다음 주 서명에 참여할 예정이다.
이번 선언은 미국이 주도하는 AI 공급망 협력 구상인 '팍스 실리카(Pax Silica)'의 일환이다. 미국과 협력국들은 중국과의 기술 경쟁이 심화하는 가운데 반도체부터 희토류 등 핵심 광물, 에너지, 물류 인프라까지 AI 산업에 필요한 공급망을 다변화하고 공동 보호 체계를 구축한다는 계획이다.
헬버그 차관은 "반도체를 설계하는 기술과 제조 장비, 제품을 운송하는 항구가 모두 서로 다른 국가에 있을 수 있다"라며 "이번 선언이 역사적인 이유는 팍스 실리카 참여국들이 이러한 기술과 인프라의 보안을 공동 책임으로 다루기로 합의했기 때문"이라고 말했다.
참여국들은 AI 관련 민감 기술과 핵심 인프라 가운데 공동 보호가 필요한 대상을 선정하고, 공급망 다변화가 필요한 분야에 관한 정보를 공유하기로 했다. 특히 기술 탈취나 불법 이전, 적대 세력의 확보가 군사·정보 역량에 중대한 이점을 줄 수 있는 기술을 우선 보호 대상으로 삼는다. AI 관련 투자를 유치하기 위한 경제 거점 조성과 공급망 강화를 위한 실무그룹도 운영할 예정이다.
이번 선언은 도널드 트럼프 미국 대통령과 시진핑 중국 국가주석이 오는 19일 중국 선전에서 열리는 아시아태평양경제협력체(APEC) 정상회의에서 회담을 앞둔 가운데 나왔다. 미국은 중국이 지난해 말 합의한 무역 갈등 완화 약속을 제대로 이행하지 않고 있다고 비판해 왔으며, 중국에 미국과 일본 등 동맹국에 대한 희토류 수출 확대를 요구하고 있다.
이번 협력도 중국이 큰 영향력을 행사하는 희토류 등 핵심 광물 공급망을 다변화하려는 미국의 전략과 맞닿아 있다. 중국에 대한 의존도를 줄여 경제적 압박에 대응하고, AI 산업에 필요한 핵심 기술과 인프라를 안정적으로 확보하겠다는 것이다.

참여국들은 앞으로 실무그룹을 통해 공동 보호 대상과 공급망 강화 방안을 구체화할 예정이다. 이번 선언에서 새로운 수출 통제 조치나 법적 구속력이 있는 규제 방안이 발표된 것은 아니다.

Unpatched GeoVision camera software gave cryptojackers a side door into 13 organizations
Attackers used GeoVision camera management software to break into Windows machines at 13 organizations and turn them into cryptocurrency miners, Huntress warned in a threat advisory.
GeoVision is a Taiwanese surveillance and access control company with customers in 110 countries. The victims work in various industries, and most of the intrusions happened between November 8 and 10. Every time, the activity started with a service that belongs to GeoVision’s software, and a Shodan search of the victims’ external IP addresses turned up GeoVision devices and management interfaces exposed to the internet.
Antivirus disabled, miner installed
After getting in, the attackers ran a series of scripts that checked whether Microsoft Defender was running. One of them downloaded a kernel driver that had been abused before in bring-your-own-vulnerable-driver (BYOVD) attacks to tamper with antivirus software.
“At this stage of the attack, we also observed attackers configuring three IFEO Debugger hijacks, which abuse a Windows troubleshooting feature. Image File Execution Options (IFEO) lets administrators configure a “debugger” to start when a particular executable is launched. The setting is stored in the Windows Registry under a key named for that executable,” the researchers wrote.
The hijacks redirected three Windows security processes to systray.exe, most likely to stop them from starting. The attackers then installed a custom loader, which on some machines was set to run every 15 minutes and at boot. The loader downloaded XMRig, an open-source cryptominer popular with threat actors.
An outdated build with known flaws
The advisory didn’t name a vulnerability, CVE or product version. Past in-the-wild exploitation of GeoVision products, such as CVE-2024-6047 and CVE-2024-11120, targeted end-of-life embedded devices, so Help Net Security asked Huntress whether the affected hosts were running supported, up-to-date GeoVision releases, and whether the attacker used a known flaw, an undisclosed one, or weak or default credentials.
A review of a sample of the affected hosts found they were running GV-VMS 17.4.8.0, a build compiled on April 24, 2024, Anthony Gibbs, Security Operations Analyst at Huntress, told Help Net Security. That version is older than V17.4.8.58, GeoVision’s fixed release.
“GeoVision’s April 2026 advisory identifies three unauthenticated remote-code-execution vulnerabilities in the WebCam Server functionality affecting this version (GV-VMS 17.4.8.0), making exploitation of a known flaw the most likely explanation,” said Austin Worline, Senior Security Operations Analyst at Huntress.
“We haven’t determined at this time, which of the three CVEs was used or confirmed whether GeoVision considered these installations supported,” Worline added.
A loader built to outlast its servers
The loader includes a BitTorrent Mainline DHT client and a PKARR resolver, which let the operator find current server addresses through a public key and move to new infrastructure without losing access to the infected machines. We asked Huntress whether it had seen this technique in other cryptomining campaigns, and whether it suggests the operator wants to keep these footholds for other purposes, such as selling access.
“We’d describe the loader as botnet-like: its DHT and PKARR capabilities let the operator find updated server addresses and deliver new payloads. The resilience goal is similar to EtherHiding, though the mechanism differs: this loader uses BitTorrent DHT and PKARR for server discovery,” Gibbs explained.
“In this activity, we observed it downloading XMRig. The ability to retrieve other payloads could support uses beyond mining, including potentially selling access, but we have not seen evidence that access was sold or used for another purpose in these incidents.”
