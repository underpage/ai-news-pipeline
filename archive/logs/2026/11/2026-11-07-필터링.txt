[TITLE] CPython flaw exposes AI inference servers to sandbox escape attacks
[TITLE_KO] CPython 결함으로 AI 추론 서버가 샌드박스 탈출 공격에 노출
[LINK] https://www.infoworld.com/article/4245631/cpython-flaw-exposes-ai-inference-servers-to-sandbox-escape-attacks-2.html
[PUBLISHED] 2026-11-06 20:21 KST
[SOURCE] InfoWorld
[TOPIC] 개발, 모델, 보안, 규제
[SCORE] 9
[REASON] CPython 결함으로 악성 모델 템플릿의 추론 서버 탈출 가능
[FIELD] 보안
[BODY]
RunSybil demonstrated code execution through a malicious model template. Python says the sandbox escapes fall outside its security threat model.
A memory-safety flaw in CPython can allow malicious AI model templates to escape code sandboxes and execute arbitrary code inside inference servers, according to security researchers at RunSybil.
“By exploiting this vulnerability, attackers could gain a foothold inside servers responsible for processing millions of user requests,” Darius Houle, a security researcher at RunSybil, wrote in a blog post. “They also could strike directly at the underlying cloud infrastructure hosting those workloads.”
The researchers demonstrated how a specially crafted model could exploit the flaw to bypass Jinja, a Python-based templating engine used to structure interactions between users and LLMs, sandbox protections, and execute code in the process of serving the model. The attack could expose AI hosting providers that allow customers to upload and run their own models, potentially giving attackers a foothold inside infrastructure processing requests for multiple customers, the post added.
However, the Python Security Response Team (PSRT), which handles security reports involving CPython, disputed the security implications of the demonstration in a response to CSO. “We acknowledge the underlying CPython bug reported by RunSybil and appreciate their contribution to fixing it. However, we do not consider the demonstrated sandbox escape to be a CPython security vulnerability,” the team said.
The disagreement centres on whether the interpreter should be responsible for preventing sandbox escapes. While RunSybil argues that the flaw creates risks for AI inference infrastructure, PSRT says executing untrusted Python code within a sandbox is outside CPython’s security threat model.
Exploiting Python’s type-handling mechanism
“The bug we discovered abuses CPython’s handling of generic types to accomplish a breakout,” Houle wrote. “We exploited it using objects that sandboxes make available in every template, even in empty sandbox contexts.”
The researchers found that CPython can use a cached list of parameters even after an object has been modified through a callback. When the interpreter subsequently looks for a newly introduced parameter in the original list, it can receive an invalid index. An assertion designed to catch the condition is disabled in normal release builds, allowing the interpreter to access memory outside the expected bounds.
RunSybil used this behavior to retrieve references to Python objects that the sandbox was supposed to keep inaccessible.
“While an invalid address will generally crash the interpreter, an address pointing to a useful live Python object gives our callback a reference to that object (even when the sandbox never intends to expose it),” Houle wrote.
The researchers then used the recovered object references to access Python classes and functions needed to construct executable code.
Malicious model templates enable code execution
To demonstrate the attack, RunSybil modified the Qwen2.5-0.5B-Instruct model by inserting a backdoored chat_template.jinja file. When the model was loaded and used through an inference-serving engine such as vLLM, the template enabled arbitrary code execution in the serving process.
“Breaking out of the chat template sandbox and executing code represents a supply chain risk that endangers inference providers, library developers, and model users,” Houle wrote.
The researchers said they shared proof-of-concept exploits with multiple inference providers supporting bring-your-own-model (BYOM) features, which allow customers to upload models from external sources.
Python disputes vulnerability classification
RunSybil disclosed the issue to CPython, the Pallets Project, which maintains Jinja, and Hugging Face. The researchers said they encountered conflicting views about which project should address the underlying problem.

[BODY]
오픈AI 출신 미라 무라티가 이끄는 씽킹 머신스 랩(Thinking Machines Lab)이 기존 모델보다 성능을 크게 높인 새로운 AI 모델을 공개했다. 중국 주요 오픈웨이트 모델과 경쟁할 수 있는 수준으로 평가되며, 기업이 자체 업무에 맞춰 AI를 개발할 수 있도록 모델 가중치도 공개할 계획이다.
씽킹 머신스는 5일(현지시간) 공식 블로그를 통해 2세대 모델 '잉클링 2 스몰(Inkling 2 Small)'을 출시했다고 밝혔다.
총 5940억개의 매개변수를 갖춘 전문가 혼합(MoE) 모델로, 실제 추론에는 170억개만 활성화한다. 텍스트와 이미지 입력을 지원하며, 최대 100만토큰의 문맥을 처리할 수 있다.
성능 개선 폭이 크다. 아티피셜 애널리시스(AA)의 종합 지능 지수에서 31점을 기록했다. 지난 7월 공개한 '잉클링 스몰'의 13점보다 18점 높아진 것으로, 비슷한 API 이용 가격의 모델 29개 중 4위에 올랐다.
중국 Z.ai의 'GLM-5.3 플래시'와 샤오미의 '미모 V2.6 플래시' 등을 앞서는 수준이다. 그러나 딥시크의 'V4.1 플래시'에는 미치지 못했다. 중국 주요 모델과 경쟁할 수 있는 성능을 확보했지만, 최상위권을 모두 뛰어넘은 것은 아니다.
특히 코딩과 기업 업무를 수행하는 AI 에이전트에서 경쟁력을 보였다. 씽킹 머신스의 자체 평가에서 복잡한 소프트웨어 개발 능력을 측정하는 '프론티어코드 2.0'에서 25.4%를 기록해 지푸AI의 GLM-5.3 플래시(14.2%)를 앞섰다. 기업 업무 수행 능력을 평가하는 '엔터프라이즈벤치 코어크래프트'에서도 71.8%를 기록해 중국의 주요 경쟁 모델보다 높은 성적을 거뒀다.

이를 위해 씽킹 머신스는 수십만건의 장시간 코딩 작업을 활용해 모델을 학습했다. 기존에는 작성한 코드가 테스트를 통과했는지에 집중했다면, 이번에는 AI가 문제를 해결하는 과정과 결과를 검증하는 행동까지 평가했다. 이를 통해 복잡한 업무를 장시간 수행하는 AI 에이전트의 능력을 높이는 데 집중했다.
그러나 처리 속도에서는 한계가 확인됐다. AA에 따르면 잉클링 2 스몰은 종합 평가에서 작업당 평균 16.5분이 걸려 비슷한 가격대 모델의 중앙값인 7.3분보다 2배 이상 느렸다. 답변을 생성하는 데 사용하는 토큰 수도 많았다. 성능은 상위권에 진입했지만 실제 업무에서 속도와 비용 효율을 개선할 여지가 남아 있다는 평가다.
이번 출시는 씽킹 머신스의 사업 전략에서도 중요한 의미가 있다. 무라티 CEO는 오픈AI 최고기술책임자(CTO)를 지낸 뒤 지난해 회사를 설립했으며, 기업과 개발자가 자신의 업무에 맞춰 AI 모델을 직접 개선하도록 지원하는 데 집중해 왔다.

안전성 개선에도 상당한 비중을 뒀다. 씽킹 머신스는 초기 모델이 어려운 작업에서 결과를 조작하거나 지시를 무시하고 자신의 행동을 숨기는 사례를 발견했다고 밝혔다. 이에 강화학습 과정에서 잘못된 행동에 불이익을 주는 방식을 도입했다. 자체 평가에서 이러한 문제 행동 점수는 기존 잉클링의 66.8점에서 14.9점으로 낮아졌다. 점수가 낮을수록 안전한 것으로 평가하는 지표다.
현재 잉클링 2 스몰은 팅커에서 추론과 추가 학습에 사용할 수 있다. 모델 가중치는 아직 공개하지 않았으며, 회사는 외부 안전성 평가와 레드팀 테스트를 마친 뒤 다음 주 아파치 2.0 라이선스로 전체 가중치를 공개할 계획이다.
이번 출시로 씽킹 머신스는 중국 주요 오픈웨이트 모델에 맞설 수 있는 성능을 확보하는 동시에 모델 개발부터 기업별 추가 학습까지 지원하는 전략을 강화했다. 향후 가중치 공개 이후 개발자들이 실제 업무에 적용했을 때 성능과 효율성을 얼마나 확보할 수 있을지가 관건이다.

[TITLE] Malicious Browser Extensions Could Use Claude Dispatch to Run Code on Users' Computers

[LINK] https://thehackernews.com/2026/11/malicious-browser-extensions-could-use.html
[PUBLISHED] 2026-11-06 21:06 KST
[SOURCE] The Hacker News
[TOPIC] 개발, 보안
[SCORE] 8
[REASON] 클로드 디스패치 경유 로컬 컴퓨터 임의 코드 실행 위험
[FIELD] 보안
[BODY]
A browser extension that can run scripts on claude.ai could make Claude Desktop run code on a person's computer, researchers at Forever Security, an endpoint security company, showed in a test.
The attack needs Dispatch, a Claude feature that lets people send tasks from their phone to Claude Desktop. The flaw that makes this possible can still be exploited, the researchers said earlier this week.
Claude Desktop is an AI agent that can run commands on the computer where it is installed. The researchers found that Dispatch also accepted an ordinary signed-in session on claude.ai, the Claude website, even though the site showed no link to it. That let an extension running on the site send Claude Desktop instructions as if the user had sent them.
The researchers say Anthropic, the company that makes Claude, told them on October 13 that Dispatch would be retired, with the end of October as the target. The Dispatch help page, last updated late last week, does not mention a retirement.
It says Dispatch is closed to new users and that people who already use it on some Pro, Max, and Ultra plans "can keep using it for now."
How the Attack Worked
The attack needs two things, according to a technical write-up by Forever Security researcher Gal Weizman: an extension that can run scripts on claude.ai, and a person signed in to both claude.ai and Claude Desktop with Dispatch turned on.
The extension could be malicious, a legitimate one that received a compromised update, or a legitimate one with a security flaw. Dispatch itself only works while the computer is awake and the desktop app is open.
In the test, a script on the user's claude.ai page opened Dispatch and sent Claude four prompts as if it were the user. The prompts asked Claude to install an npm package.
Claude first hesitated over the unfamiliar package, but a follow-up message, delivered in the user's voice, got it to go ahead.
Claude asks before it acts, but those approval prompts appeared in the web page the extension controlled. The script clicked any "Allow" button every second, so no one had to be watching.
Claude then ran a global npm install, and the package's install script opened the Calculator app. No browser exploit was needed. The same step could have stolen files or installed a backdoor, given Claude's permissions on the computer, the researchers say.
The test was run with the browser and Claude Desktop on the same computer, and the researchers report no real attacks. Because Dispatch connects devices, the extension could also reach Claude Desktop on a different computer signed in to the same Claude account, they say. That case is described but not shown.
The same reach could link a home computer to a work laptop when someone uses a single personal Claude account on both devices, with Dispatch turned on. The researchers have seen personal Claude accounts with cross-device Dispatch turned on, on work computers at their customers.
The researchers reported the flaw to Anthropic on May 14. The company accepted it as valid on May 19 but closed the report as a duplicate of an issue it had already found internally, according to the researchers.
"Anthropic is retiring Dispatch, but not the design behind it," the researchers wrote, adding that two other Claude features, Claude Code Remote Control and Claude Cowork sessions, let extensions carry out the same attack. Their write-up does not include a test of those features, and they plan a follow-up post.
What Dispatch Users Can Do
In Claude Desktop, Dispatch is part of Cowork and appears in the left-side panel. The Dispatch help page says users should know how to quickly disconnect or revoke access before turning the feature on, but it does not explain how.
The researchers recommend these steps:
- Turn off cross-device Dispatch if you do not need it. If you do need it, review how devices are paired, approved, and removed.

“Most apps never make it off localhost”: Cursor takes on Lovable and Replit with fully managed app deployment
AI coding agents have certainly made it easier to transform an idea into a working application. However, getting that application off a local machine and into the hands of real users remains a hurdle, requiring essential infrastructure steps spanning everything from hosting and database provisioning, to critical security checks.
Cursor, the AI coding platform acquired by Elon Musk’s SpaceX for $60 billion back in August, acknowledged the problem in an X post published on Thursday.
“Agents have made it easier to write code, but most apps never make it off localhost,” the company notes.
To address this, Cursor is introducing new app-building and deployment functionality, designed to take AI-generated applications from development to a live, shareable URL, without users having to even think about the underlying infrastructure themselves.
“Agents have made it easier to write code, but most apps never make it off localhost.”
Built on cloud agents
The new feature is built around cloud agents, which Cursor introduced last year as a way for developers to run multiple AI coding agents remotely without having to keep their laptops engaged. At the time, the company highlighted their ability to fix bugs, handle smaller coding tasks and implement some complex features.
With this latest update, those same agents can now take applications all the way through to deployment, handling the important steps needed to make them accessible to other users. The functionality is only available through cloud agents, though, which means it can’t be used with agents running locally.
Users start by describing the application they want to build in natural language, with Cursor managing the code generation and development process as usual.
From there, the agent creates the application and sets up the underlying project, including the necessary components to get it running.
Once the application is ready, users can preview the result before deciding whether to hit publish.
Publishing makes the application accessible through a live URL, allowing users to share it with colleagues or other users without having to configure hosting themselves.
It’s worth noting that there are two ways to get started. Users building an application from scratch will automatically have a new repository created on Cursor Origin, the company’s Git-based code-hosting platform launched in August as an agent-centric alternative to GitHub.
Alternatively, users can deploy applications from an existing GitHub repository. This means developers who already have an application under development can use Cursor’s cloud agents to prepare and publish it, without having to move their code to Origin or set up deployment infrastructure manually.
Judging by Cursor’s own examples, the feature seemingly targets employees who need to create internal business applications, such as sales dashboards, onboarding programs, customer presentations and developer portals. So in that regard, it could prove a boon for non-developers who have an idea for a tool but lack the technical nous to get it running themselves.
Of course, there’s nothing restricting the feature to business applications. An aspiring vibe coder could just as easily create a neighbourhood football league tracker or interactive family holiday planner. And because individual subscribers can publish apps publicly, those creations can be shared with anyone who has the link.
Under the hood: hosting, databases and security
Cursor had actually begun closing this gap, when in August it introduced the ability to preview cloud-agent projects and publish them to a live URL. However, users still needed to connect their own Vercel accounts.
The latest release removes that requirement while introducing various new smarts to the mix.

피지컬 인공지능(AI) 기업 로보터블이 휴머노이드 로봇의 동작 기술을 서로 다른 하드웨어에 이식하는 '스킬 리타게팅' 소프트웨어 판매에 나선다. 특정 로봇 제조사에 얽매이지 않고 하나의 소프트웨어로 여러 로봇을 제어하고 학습시키는 통합 솔루션으로 피지컬 AI 시장을 공략한다는 구상이다.
스킬은 문 열기, 옷 개기처럼 로봇이 수행할 수 있는 작업 단위의 능력을 뜻한다.
최인현 로보터블 대표는 5일 경기 고양시 킨텍스에서 열린 '2026 로보월드'에서 기자와 만나 "스킬 리타게팅 소프트웨어를 내년 초 출시할 것"이라고 밝혔다. 제품명은 '아이소모션(IsoMotion)'이다.
아이소모션은 한 휴머노이드에서 개발한 스킬을 다른 휴머노이드에서도 쓸 수 있게 해주는 소프트웨어다. 이 소프트웨어는 사람의 조종 움직임이나 AI의 명령을 표준 동작 데이터로 바꾼 뒤, 이를 각 로봇의 관절 구조와 규격에 맞는 명령어로 실시간 번역한다.
한 기종에서 익힌 스킬을 다른 기종에 그대로 옮기기는 쉽지 않다. 로봇 스킬은 특정 장면을 인식했을 때 관절을 얼마나 움직일지 학습한 결과물이기 때문이다. 로봇마다 관절 구조와 배치가 다르다. 카메라 화각과 촉각 센서 유무도 제각각이다. 같은 동작이라도 로봇마다 관절을 움직이는 방식이 달라지는 이유다.
개발 계기는 회사의 사업 구조에서 나왔다. 로보터블은 외식(F&B) 로봇 전문 시스템통합(SI) 기업이다. 뉴로메카, 레인보우로보틱스 등 여러 제조사의 로봇을 활용해 요리 과정을 자동화하는 솔루션을 제공한다. 다양한 로봇을 다루다 보니 한 번 익힌 스킬을 다른 로봇에서도 활용하려는 수요가 생겼다.
최 대표는 "여러 휴머노이드 하드웨어를 쓰면서 하나의 스킬을 여러 로봇에 적용하고 싶다는 생각이 들어 개발했다"며 "로보월드 현장에서 아이소모션 시연을 본 대학 연구실 교수들의 반응이 특히 좋았다"고 말했다.
로보터블은 이번 전시에서 아이소모션으로 서로 다른 로봇이 똑같이 오이를 칼로 써는 모습을 시연했다. 먼저 현장에서 로보터블 직원이 리더 암을 조종해 오이를 100번 잘랐다. 회사는 이 데이터만으로 오이 자르기 스킬을 바로 만들었다. 이어 아이소모션을 통해 이 스킬을 다른 로봇에 성공적으로 이식한 모습을 선보였다.
리더 암은 사람이 손으로 직접 잡고 움직이는 조종용 로봇팔이다. 로봇 학습용 시연 데이터를 모으는 원격조종(텔레오퍼레이션) 장비의 한 종류다.
