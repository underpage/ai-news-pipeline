[TITLE] 국내 최대 고성능 GPU 8,496개 갖춘 슈퍼컴퓨터 6호기 '가동'
[LINK] https://zdnet.co.kr/view/?no=20261102111935
[PUBLISHED] 2026-11-02 11:19 KST
[SOURCE] ZDNet Korea
[TOPIC] 신기술, 규제
[SCORE] 8
[REASON] 고성능 연산 연구진은 국가 슈퍼컴 6호기 자원 신청 계획 수립 필요
[FIELD] 신기술
[BODY]
국내 최대인 최신 GPU 8496개를 갖춘 국가 슈퍼컴퓨터 6호기 '한강'이 다음 달 정식 서비스에 들어간다.
과학기술정보통신부와 한국과학기술정보연구원(KISTI)은 2일 대전 KISTI 본원에서 슈퍼컴퓨터 6호기 ‘한강’ 가동식을 개최했다.
가동식에는 김성수 과기정통부 연구개발정책실장, 이식 KISTI 원장을 비롯한 산·학·연 및 유관기관 관계자 등 200여 명이 참석했다.
한강에는 엔비디아 CPU-GPU 통합 가속기 칩인 ‘GH200’ 등 최신 GPU 8,496개와 CPU 9,936개가 탑재됐다.
5호기 누리온 대비 한강의 이론연산성능은 614페타플롭스(초당 6.14×10의 17승회 연산)로 24배, 저장공간은 205페타바이트로 10배, 네트워크 성능은 400Gbps로 4배 성능을 갖췄다.
구입 및 설치, 구축에 총 3825억원이 투입됐다.
이식 원장은 "오는 11월 초 국제슈퍼컴퓨팅컨퍼런스(SC2026)에서 발표될 전 세계 슈퍼컴퓨터 성능순위(Top500)에서도 10위권급에 등재될 것"이라며 "한강은 5호기가 지원해 온 CPU 기반 대규모 계산과학·시뮬레이션 연구 지원 기능은 물론, 최신 GPU를 활용한 AI 기반 과학연구까지 새롭게 지원할 수 있도록 성능을 대폭 강화했다"고 말했다.
한강은 향후 K-문샷 등 국가전략 R&D를 중점 지원하는 한편, 대학·출연연의 도전적 연구부터 기업의 기술개발까지 폭넓게 뒷받침하는 핵심 연구 인프라로 활용될 예정이다.
KISTI는 이를 위해 지난 9월부터 연구자 모집을 거쳐 현재 시범서비스를 운영 중이다. 공식 서비스 개시일은 오는 12월 16일이다.

한편 이날 행사에서는 또 국가 초고성능컴퓨팅 발전과 6호기 구축에 기여한 ▲홍태영 KISTI 슈퍼컴퓨팅 인프라센터장(부총리 표창) ▲KISTI 권오경 HPC응용팀장· 조완우 선임기술원·오자연 행정원(이상 KISTI 원장 표창) ▲전은지 KAIST 교수, 박환열 순천향대 교수, 이환규 단국대 교수, 백서인 고려대 교수, 곽상규 고려대 교수(이상 공로패)에 표창과 공로패가 수여됐다.
김성수 과기정통부 연구개발정책실장은 “한강은 AI와 과학기술 융합을 지원, 새로운 과학적 발견을 이끌어 갈 핵심 기반”이라며, “K-문샷 등 국가적 난제 해결과 산·학·연의 혁신적인 연구를 적극 지원해 대한민국 과학기술 경쟁력을 높여 나갈 것"이라고 밝혔다.

[REASON] AI 플랫폼 운영팀은 격리 우회 취약점 샌드박스 보안 조치 시급
[FIELD] 보안
[BODY]
AI 모델과 서버리스 작업을 실행하는 베타9(Beta9)에서 사용자 격리를 우회해 작업 실행 서버에 접근할 수 있는 치명적인 취약점 3건이 공개됐다. 작업공간 접근 토큰을 가진 공격자가 같은 서버에 저장된 다른 고객의 데이터를 읽거나 변조할 수 있는 문제로, 세 취약점 모두 CVSS 3.1 기준 9.9점으로 평가됐다. 관련 취약점 정보는 11월 1일 공개됐다.
파일 경로 검증 허점…관리자 권한 탈취로 확대 가능
CVE-2026-120307은 파일 관리 기능이 접근 가능한 경로를 충분히 제한하지 않아 발생한다. 공격자는 실행 중인 샌드박스와 작업공간 토큰을 이용해 자신의 격리환경 밖에 있는 파일을 조회·수정·삭제할 수 있다.
검증 과정에서는 작업 실행 서버의 쿠버네티스(Kubernetes) 서비스 계정 토큰을 읽는 데 성공했다. 특히 프로젝트가 제공하는 원격 노드 배포 설정에서는 해당 계정에 클러스터 전체 관리자 권한인 ‘cluster-admin’이 부여돼 있어, 구성에 따라 피해가 클러스터 관리 영역으로 확대될 수 있다.
CVE-2026-120308은 저장공간을 연결할 때 경로와 소유권을 제대로 검증하지 않는 문제다. 공격자가 연결 경로를 조작하면 작업 실행 서버의 파일시스템을 자신의 샌드박스에 읽기·쓰기 가능한 상태로 연결할 수 있다. 같은 서버에 저장된 다른 고객의 볼륨도 영향을 받을 수 있다.
이미지 생성 과정도 격리 부족…수정 버전 적용 필요
CVE-2026-120306은 컨테이너 이미지 생성 과정에서 발생한다. 빌드 작업이 실행 서버와 주요 실행환경을 공유하고 루트 권한으로 동작해, 사용자가 제출한 이미지 빌드 명령으로 서버 파일과 컨테이너 실행 프로그램 등에 접근할 수 있는 문제다.
파일 접근과 이미지 생성 취약점은 Worker 0.1.756, 저장공간 연결 취약점은 Gateway 0.1.776과 Worker 0.1.756에서 수정됐다. 개발팀은 파일 접근 범위 제한, 볼륨 소유권 검사, 이미지 빌드 격리 강화 등을 적용했다. 관련 수정 코드는 CVE 공개에 앞선 9월 15일 병합됐다.
이번 취약점은 일반 사용자 권한이 다른 고객의 데이터와 인프라 관리 영역으로 확대될 수 있다는 점에서 위험하다. 베타9 운영자는 게이트웨이와 워커의 수정 버전 적용 여부를 확인하고, 작업 실행 계정에 과도한 쿠버네티스 권한이 부여돼 있는지도 점검할 필요가 있다.

[TITLE] 딥시크, 코딩 '슈퍼 에이전트' 공개…6개월 만에 추격 기반 구축
[LINK] https://www.aitimes.com/news/articleView.html?idxno=216865
[PUBLISHED] 2026-11-01 20:11 KST
[SOURCE] AI타임스
[TOPIC] 에이전트, 개발
[SCORE] 8
[REASON] 개발 도구 팀은 딥시크의 복수 작업 관리 코딩 슈퍼 에이전트 아키텍처 분석 필요
[FIELD] AI 에이전트
[BODY]
딥시크가 여러 코딩 작업을 자동으로 관리하는 '슈퍼 에이전트'를 공개하며 앤트로픽의 '클로드 코드'와 오픈AI의 '코덱스' 추격에 나섰다. 지난 5월 전담팀 구성 이후 약 6개월 만에 자체 개발 도구와 팀 단위 업무 자동화 기술까지 선보였지만, 아직 연구용 프로토타입으로 실제 제품 경쟁력은 검증되지 않았다.
딥시크 하네스 개발팀은 31일(현지시간) 공식 위챗 계정을 통해 '슈퍼 에이전트 설계 탐구: 더 자율적인 에이전트 시스템을 향해'라는 기술 문서를 발표했다. 이와 함께 새로운 구조를 구현한 'DSH 슈퍼에이전트(dsh-superagent)'의 소스 코드를 깃허브에 공개했다.
이번 발표는 올해부터 추진해 온 코딩 에이전트 개발 전략의 후속 성과다. 지난 5월 앤트로픽의 클로드 코드를 경쟁 대상으로 삼아 하네스 전담팀을 구성한 사실이 알려진 바 있다.
전담팀은 제인스트리트 출신 엔지니어 추이톈이가 이끌고 있다. 지난 6월 개발 인력 채용을 확대했으며, 8월에는 오픈소스 개발 환경인 '딥시크 하네스'를 공개했다. AI 모델 공급에 집중했던 딥시크가 개발자가 실제 사용하는 코딩 도구까지 직접 구축하기 시작한 것이다.
이번 슈퍼 에이전트는 한 단계 더 나아가 여러 에이전트의 작업을 자동으로 관리하는 데 초점을 맞췄다. 딥시크는 AI 모델의 코딩 능력이 높아져도 개발자가 개별 에이전트에 일일이 지시하고 진행 상황을 확인해야 한다면 생산성 향상에 한계가 있다고 판단했다.
이를 해결하기 위해 작업을 관리하는 '라우터(Router)'와 실제 업무를 수행하는 '워커(Worker)'를 분리했다. 라우터는 개발팀의 대화와 깃허브에서 발생하는 이벤트를 확인해 작업을 배분하고, 여러 워커는 독립된 환경에서 코드 수정과 오류 해결을 병렬로 처리한다.
예를 들어 개발팀의 대화방에서 소프트웨어 오류가 언급되면, 사전에 허용된 규칙에 따라 에이전트가 문제를 분석하고 수정 작업에 착수할 수 있다. 작업을 마치면 깃허브에 코드 변경을 제안하는 풀 리퀘스트(PR)를 제출하고 개발자에게 검토를 요청한다. 딥시크는 내부에서 운영 중인 슈퍼 에이전트가 실제 오류 수정과 코드 리뷰 대응에도 참여하고 있다고 밝혔다.
자체 실험에서는 작업 처리 시간이 크게 줄었다. 약 300개의 메시지와 20개의 작업 요청이 발생하는 상황을 모의로 구성한 결과, 슈퍼 에이전트는 전체 작업의 95%를 15.7분 이내에 처리했다. 기존 단일 세션 방식의 29.5분과 비교하면 약 47% 단축됐다.
다만 이번 실험은 실제 코딩 성능이 아닌 다중 작업 처리 효율을 측정한 것이다. 클로드 코드나 코덱스와 직접 비교한 결과도 아니어서 경쟁 제품보다 성능이 뛰어나다고 판단하기 어렵다. 두 경쟁 제품도 이미 하위 에이전트와 병렬 실행, 백그라운드 자동화를 지원하고 있다.
딥시크도 깃허브에서 해당 코드를 정식 제품이 아닌 연구용 프로토타입이라고 명시했으며, 실제 내부 시스템과 공개 버전에도 차이가 있다고 밝혔다. 현재 공개 버전은 하나의 소프트웨어 프로젝트를 대상으로 여러 코딩 작업을 자동 처리하도록 설계됐으며, 일부 자동화 기능은 아직 구현되지 않았다.
그럼에도 이번 발표는 딥시크의 사업 영역이 AI 모델에서 코딩 에이전트 플랫폼으로 넓어지고 있다는 점에서 의미가 있다. 특히 소스 코드를 상업적으로 활용할 수 있는 MIT 라이선스로 공개하고, 다양한 AI 모델을 연결할 수 있도록 설계해 외부 개발자와 기업의 참여를 유도하고 있다. 이를 통해 자체 개발 도구 생태계를 확보하려는 전략으로 해석된다.
이처럼 딥시크는 6개월 동안 전담팀 구성과 인력 확보, 개발 도구 출시를 거쳐 팀 단위 업무 자동화 기술까지 공개했다. 클로드 코드와 코덱스가 앞서 있는 시장에서 경쟁할 기술 기반을 갖춰가고 있지만, 아직은 실제 개발 현장에서 성능과 안정성, 운영 비용을 검증해야 하는 초기 단계다.

크래프톤(대표 김창한)의 로보틱스 연구법인 루도 로보틱스(Ludo Robotics)가 사람과 소통하며 협력하는 로봇용 AI 시스템 ‘루디 0.2(Ludi 0.2)’를 공개했다.

Adobe is testing how well AI agents can use editing tools like a Photoshop professional would
Key Points
- Adobe Research and UC San Diego built EditAgent, an AI system that breaks image editing tasks into sub-steps and pairs a general-purpose editor with specialized tools for things like sharpening or zooming.
- A standard language model evaluates image variants generated in parallel, using measured statistics and close-up crops. With this data, it outperforms evaluation models that were specifically trained for the job.
- EditAgent produces more accurate results than previous AI agents but needs about ten times the compute. The verified output can then be used to train faster editing models.
Adobe researchers built an AI agent for image editing that pairs a general-purpose editor with specialized tools. A standard language model compares results using measured data and picks the best one.
AI agents for image editing break complex requests into steps and typically retry failed steps with the same tools, while a separate model judges the output by eyeballing it.
Researchers at Adobe Research and UC San Diego want to change that with EditAgent, a system that works more like a pro in Photoshop, according to a new paper. It picks the right tool for each task and compares the result against the original using hard numbers.
General-purpose editors fail at too many tasks
In a test of 600 image edits, blind-rated by five professionals, the general-purpose editor Flux-2-Klein-9B failed to produce a usable result 42.7 percent of the time. Specialized tools solved roughly two-thirds of those failures, especially for sharpening, rotation, and zooming. More retries with the same editor barely helped.
The researchers also tested whether an agent does better by refining results step by step or by generating multiple variants in parallel. Iterative refinement piles up small errors because each round builds on an already altered image. Professionals preferred the parallel variants generated from the original in 78.5 percent of the comparisons where they picked a side. The agent needed only half as many evaluation passes. EditAgent is built on these two findings.
Hard numbers turn standard models into better judges
EditAgent plans a request in steps and, for each step, pits the general-purpose editor against matching specialized tools. A standard language model then compares all variants in a single pass.
For each variant, the model gets a verification record with a close-up of the edited area, a change map of altered regions, and measured statistics on brightness and color. In one example, a photo was supposed to be gently brightened. The numbers showed the general-purpose editor overexposed it and shifted the colors warmer. The specialized tool stayed within spec.
The researchers tested this on their 600-edit benchmark. The judge model had to pick the best result from several candidates, and they counted how often it chose an image the professionals also rated as usable. For comparison, they ran models like EditScore that were fine-tuned on human ratings of image edits.
Without the verification record, none of the seven language models tested could match the best fine-tuned model. With it, all seven beat every fine-tuned model. Qwen3.8-27B made a usable pick 81.3 percent of the time, compared to 74.8 percent for EditScore-72B. For the researchers, this suggests that what a judge model sees can matter more than how it was trained.
After each round, EditAgent also checks whether later edits accidentally undid earlier ones. In the paper's example, the instruction "let in more daylight" makes a previously frosted window clear again. The agent catches the conflict and fixes it.
EditAgent improved the open-source editors Qwen-Image-Edit-2511 and Flux-2-Klein-9B across three benchmarks and outperformed seven other AI agents.

언어 평등 AI 연구 연합이 소수 언어 사용자의 비용 부담 실태를 분석했다.

언어 평등 AI 연구 연합(Coalition for Language Equity in AI Research)이 발표한 새 연구에 따르면, AI 모델이 특정 언어를 처리할 때 다른 언어보다 훨씬 많은 토큰이 필요한 것으로 나타났다. 레스트 오브 월드(Rest of World)는 이런 격차 탓에 소수 언어 사용자가 같은 서비스에 더 많은 비용을 낼 위험이 있다고 보도했다.
연구진은 대규모 언어 모델의 토크나이저가 텍스트를 블록, 즉 토큰으로 분해하는데, 디지털화된 데이터가 풍부한 언어일수록 훨씬 효율적으로 처리한다고 설명했다. 웹 비중이 가장 큰 20개 언어를 분석한 결과, 상대적으로 덜 쓰이는 언어는 같은 프롬프트를 영어로 입력할 때보다 1.5~5배 많은 토큰을 사용했다. 조사 대상을 200개 언어로 넓히자 분석 모델 중 하나에서는 격차가 최대 17배까지 벌어졌다.
대다수 대규모 언어 모델 사업자가 사용한 토큰 수에 따라 요금을 부과하기 때문에 비용도 크게 늘어난다. 토큰이 많아질수록 응답 시간이 길어지고, AI 모델의 컨텍스트 윈도우에 담을 수 있는 정보량도 줄어든다.
연구진은 이런 현상을 숨겨진 ‘토큰 세금’이라 부르며 디지털 불평등을 악화시킨다고 경고했다.
연구진은 이런 격차가 사용 인구가 적은 언어에만 국한되지 않는다고 짚었다. 연구는 화자 수 기준으로 정렬하면 펀자브어(약 2억 명), 벵골어(약 2억 6,600만 명), 우르두어(약 2억 8,800만 명), 버마어(약 3,600만 명), 암하라어(약 3,600만 명) 등 막대한 인구가 세금을 떠안는다고 분석했다. 수억 명이 같은 수준의 지능을 얻으면서 영어의 몇 배에 달하는 요금을 내는 셈이라고 전했다.
AI 모델의 훈련 데이터에서 흔치 않은 문자 체계를 쓰는 언어가 특히 큰 영향을 받는다. 버마어, 티베트어, 크메르어, 라오어가 대표적이다. 반면 라틴 알파벳을 쓰는 언어는 사용 인구가 비교적 적어도 유리한 경우가 많다.
옥스퍼드대학교 연구진이 2023년 신경정보처리시스템학회(NeurIPS)에서 발표한 논문에 따르면, 같은 문장을 여러 언어로 번역했을 때 토큰 길이가 최대 15배까지 차이 났다. 다국어 지원을 염두에 두고 훈련한 토크나이저에서도 격차는 사라지지 않았다. 연구진은 이런 차이가 상용 서비스 이용 비용, 처리 시간과 지연, 컨텍스트로 넣을 수 있는 콘텐츠 분량 측면에서 특정 언어 사용자에게 불리하게 작용한다고 지적했다.
워싱턴대학교와 카네기멜런대학교 등의 연구진은 2023년 자연어 처리 경험적 방법 학회(EMNLP)에서 오픈AI의 API를 22개 언어로 분석한 결과를 공개한 바 있다. 다수 언어의 화자가 더 많은 요금을 내면서도 낮은 성능의 결과를 얻고 있으며, 이들이 상대적으로 API 이용 비용 부담이 큰 지역 출신인 경우가 많다는 내용이다.

AI 학습에 투입하는 그래픽처리장치(GPU)를 늘리는 대신, 학습 효과가 높은 데이터를 선별하고 여러 GPU에 효율적으로 배분하는 방식이다. KAIST 전산학부 이재길 교수 연구팀이 대형언어모델(LLM)의 미세조정 과정에서 학습 데이터의 중복 효과를 줄이고 GPU 활용 효율을 높이는 기술인 ‘클러스터(CluSTER)’를 개발했다고 2일 밝혔다.
연구팀은 코딩과 의료 분야의 LLM을 대상으로 실험한 결과, 전체 학습 데이터의 약 31%만 사용해도 모델 성능을 거의 유지하면서 학습 시간을 최대 69.6% 단축하는 성과를 확인했다. 기존 방식으로 10시간이 소요되던 추가 학습을 약 3시간으로 줄일 수 있다는 의미다.
이번 연구의 핵심은 AI 학습에 필요한 데이터를 무조건 많이 사용하는 기존 접근에서 벗어나, 실제 학습에 기여하는 정보의 다양성과 GPU 간 작업 배분을 동시에 최적화했다는 점이다.
LLM을 의료 상담 지원이나 소프트웨어 개발 등 전문 분야에 적용하려면 해당 분야의 데이터를 추가로 학습시키는 미세조정(Fine-tuning) 과정이 필요하다. 이 과정에서는 여러 GPU가 학습 데이터를 나눠 처리하는 데이터 병렬화(Data Parallelism) 기술이 활용된다.
그러나 학습 데이터를 무작위로 분배하면 서로 다른 GPU가 유사한 학습 효과를 가진 데이터를 반복적으로 처리할 수 있다. 데이터의 양이 많더라도 모델이 새롭게 습득하는 정보는 제한적이어서 계산 자원과 학습 시간이 불필요하게 소모되는 문제가 발생한다.
연구팀이 개발한 클러스터는 이러한 비효율을 해결하기 위해 학습 데이터가 모델에 미치는 영향을 기준으로 유사한 데이터를 군집화한다. 단순히 문장에 포함된 단어나 주제의 유사성을 비교하는 것이 아니라, 실제 모델 학습 과정에서 비슷한 영향을 발생시키는 데이터를 찾아 묶는 방식이다.
예를 들어, 서로 다른 표현으로 작성된 코딩 문제라도 모델이 학습하는 해결 방식이 유사하다면 같은 군집으로 분류할 수 있다. 이후 각 군집에서 대표 데이터를 선별해 중복 학습을 줄이고, 다양한 유형의 학습 정보가 여러 GPU에 균형 있게 배분되도록 조정한다.
이를 통해 학습 데이터의 규모를 줄이면서도 특정 유형의 정보에 학습이 편중되는 현상을 완화할 수 있다. 데이터 선택과 GPU 작업 분배를 별도로 처리하는 대신 하나의 최적화 과정으로 결합했다는 점에서 차별성을 갖는다.
연구팀은 기술의 효과를 검증하기 위해 코딩·의료 분야의 데이터셋 3종과 약 70억 개 및 130억 개의 매개변수를 가진 LLM을 활용했다. 총 8개 성능 평가 시험을 실시한 결과, 전체 데이터의 약 31%만 활용하는 조건에서도 기존 모델과 유사한 성능을 확보했다.
학습 시간은 실험 조건에 따라 최대 69.6% 감소했다. GPU 4개를 활용한 환경을 중심으로 효과를 검증했으며, GPU 8개를 사용하는 환경에서도 기존 방식보다 우수한 결과를 확인했다.
이번 성과는 AI 모델의 성능을 유지하면서 학습에 필요한 계산량을 줄일 수 있다는 점에서 의미가 있다. 특히 이미 개발된 범용 AI 모델을 기업이나 기관의 업무에 맞게 추가 학습시키는 과정에서 GPU 자원의 활용 효율을 높일 수 있을 것으로 기대된다.
기업별 고객 상담 시스템이나 코딩 지원 AI, 의료진의 정보 확인을 지원하는 전문 AI 등 특정 분야의 데이터를 반복적으로 학습해야 하는 환경에서 활용 가능성이 있다. 학습 시간이 줄어들면 모델 개발과 개선 주기를 단축할 수 있으며, GPU 사용에 따른 계산 비용을 절감하는 데도 도움이 될 수 있다.
다만 이번 연구에서 확인된 최대 69.6%의 시간 단축률은 특정 실험 조건에서 얻어진 결과다. 실제 산업 현장에서의 절감 효과는 모델 규모와 학습 데이터의 특성, GPU 구성 등에 따라 달라질 수 있다.
이재길 교수는 “AI 학습의 효율을 높이기 위해서는 GPU를 더 많이 사용하는 것뿐 아니라, 어떤 데이터를 학습할지 똑똑하게 선택하는 것도 중요하다”며 “이번 연구는 기존 GPU 자원을 더 효율적으로 활용해 대규모 AI 모델의 학습 부담을 줄일 수 있다는 점에서 의미가 있다”고 말했다.
이번 연구는 KAIST 전산학부 김현진 박사과정 학생이 제1저자, 이재길 교수가 교신저자로 참여했다. 토론토대학교(University of Toronto) 남영은 박사후연구원과 KAIST 데이터사이언스대학원 한재민·최원혁 석사과정 학생이 공동저자로 이름을 올렸다.
연구 결과는 지난달 24일부터 29일까지 헝가리 부다페스트에서 열린 자연어처리 분야 국제학술대회인 ‘2026 자연어처리의 경험적 방법론 학술대회 EMNLP 2026(Conference on Empirical Methods in Natural Language Processing)에서 ‘데이터 병렬 처리를 활용한 클러스터링 기반 균형 샘플링 및 할당을 통한 고성능 미세 조정(Clustering-Based Balanced Sampling and Allocation with Data Parallelism for High-Performance Fine-Tuning-다운)’이란 제목으로 발표됐다.

[TITLE] 앤트로픽 사칭한 피싱 초대장, 구글·마이크로소프트 계정 노린다

앤트로픽의 비공개 AI 프리뷰 초대를 사칭한 피싱 메일이 고투웨비나 초대장으로 위장해 기업 직원의 구글·마이크로소프트 로그인 정보를 빼내고 있다.
endif; ?>
모두가 앤트로픽의 행보를 궁금해하는 상황을 해커들이 신나게 악용하고 있다.
사이버보안 기업 코펜스(Cofense)의 신규 연구에 따르면, 한 피싱 캠페인이 앤트로픽의 초청 전용 비공개 프리뷰에 초대받았다고 믿게 만들어 성급한 기업 사용자를 끌어들이고 있다.
실제로는 공격자가 영상 화상회의 소프트웨어 고투웨비나(GoTo Webinar)의 브랜드를 도용해 구글과 마이크로소프트의 로그인 자격 증명을 훔치려는 시도다.
딕슨리서치의 프랭크 딕슨은 특별함을 파는 수법이라고 평가하며, 기회를 놓칠까 두려운 심리가 가장 오래된 미끼라고 설명했다.
딕슨은 모든 기업이 AI를 어디에 접목할지 고민하는 만큼, 앤트로픽의 최신 기술을 미리 볼 수 있는 비공개 프리뷰는 의욕적인 직원이 마다할 이유가 없는 초대라고 짚었다. 공격자가 앤트로픽을 무작위로 고른 것이 아니라 현재 가장 유명한 브랜드이기 때문에 의도적으로 선택했다는 것이다. 공격자가 그때 그때 화제에 오른 기업을 골라 쓰므로 다음 달에는 사칭 대상이 바뀔 수도 있다.
앤트로픽 사칭 초대장으로 유인하는 방식
고투웨비나는 널리 쓰이는 플랫폼이어서 보통 이 플랫폼의 회의 초대 이메일은 보안 도구에 차단되지 않는다. 코펜스 연구진은 공격자가 이 점을 악용해 정상 발신자가 보낸 듯한 초대 이메일을 발송하고, 사용자가 가짜 웨비나 등록 링크를 클릭하면 침해된 URL로 연결되게 했다는 사실을 확인했다.
이메일은 연구진이 ‘솔깃한’ 제안이라고 표현한 문구를 담고 있다. 비공개 초청 전용 가상 세션에서 선별된 참가자들을 모아 AI 시스템, 연구, 프런티어 모델의 미래를 집중적으로 논의한다는 내용이다.
공격자는 URL 단축 서비스로 이메일 보안 도구를 우회하고, 서브도메인과 대시(-)를 활용해 악성 URL을 감춘다. 링크 자체는 클로드, 챗GPT 등 모델 컨텍스트 프로토콜(MCP)과 호환되는 AI에 맞춰 도구를 설계하는 합법적 기업 재피어(Zapier)에서 생성된 것으로 보인다.
이메일 발신 주소는 customercare@gotowebinar[.]com으로 표시된다. 고투웨비나의 실제 웹사이트는 www.goto.com이다. 본문에는 눈에 띄는 맞춤법 오류가 없고 고투웨비나 브랜드도 들어가 있다. 다만 연구진은 발신자 이름이 ‘Austin from nthropic’으로, ‘A’가 빠져 있다고 지적하며, 작은 오타지만 유용한 경고 신호라고 강조했다.
피싱 링크를 클릭하면 클라우드플레어 캡차 페이지가 나타나며, 이를 완료해야 로그인 창이 표시된다. 보안 도구가 공격자의 웹사이트를 스캔하지 못하도록 막는 두 겹의 검문 중 첫 번째 단계다.
연구진은 캡차가 정상 웹사이트에서도 흔하기 때문에 피싱 대상자가 모든 것이 안전하다고 믿을 수 있다고 설명했다.
캡차를 통과하면 피해자는 줌을 사칭한 초대 페이지로 이동한다. 가짜 행사에 참석하려면 먼저 등록해야 하며, 업무용 이메일 주소를 입력하라는 안내가 나온다. ‘Continue with Google’ 또는 ‘Continue with 마이크로소프트’ 버튼을 클릭하면 또 하나의 캡차 페이지가 나타난다.
연구진은 두 캡차 페이지가 VPN 서비스, 스캐너, 토르 브라우저 등 보안 도구의 분석을 탐지해 차단하는 데 능숙한 것으로 보인다고 밝혔다. 캡차 페이지가 둘로 나뉘어 있어 보안 도구가 공격의 모든 단계를 추적하지 못할 가능성도 있다.
딕슨은 캡차가 원래 봇을 막기 위해 만들어졌지만, 이번 공격에서는 보안 스캐너를 막고 피해자를 들여보내는 역할을 한다고 꼬집었다.
다만 가짜 구글 로그인 페이지와 마이크로소프트 로그인 페이지는 차이가 있다. 구글 사칭 페이지는 비밀번호 없이 사용자 이름만 수집하는데, 연구진은 설정 오류 때문으로 추정했다. 마이크로소프트 사칭 페이지는 사용자 이름과 비밀번호를 모두 수집한다.
두 페이지 모두 정상 페이지와 ‘놀랄 만큼 비슷’하며, 서브도메인도 ‘교묘’하다. 가짜 구글 URL은 goo[.]gle-access-eventregister[.]icu이고, 마이크로소프트 URL은 office[.]com-access-sharepoint[.]com을 사용해 실제 오피스와 셰어포인트 도메인을 면밀히 흉내 낸다.
자격 증명을 제출해도 두 로그인 페이지 모두 확인 메시지를 띄우지 않고, 정상 업체 페이지로 리디렉션하지도 않는다. 그 시점에 공격자는 이미 자격 증명 탈취에 성공한 상태다. 연구진은 공격자가 계정을 장악하고, 계정 내 민감 문서에 접근하거나, 기업 내부로 더 깊이 침투하는 최초 공격 경로로 활용할 수 있다고 설명했다.
연구진은 이메일부터 로그인 페이지까지 메시지의 브랜드가 일관되는지 확인하고, 사소한 오타 같은 미세한 불일치를 찾으며, URL과 도메인이 로그인 페이지의 진위를 가른다는 점을 직원에게 상기시키라고 권고했다.
연구진은 로고와 디자인이 정상처럼 보여도 공격자는 모방에 능숙하며, 특히 AI를 활용하는 최근에는 더욱 그렇다고 경고했다.
직원 개인의 잘못이 아니다
딕슨은 AI 업계의 제한적 프리뷰와 대기자 명단 관행이 이런 상황에 도움이 되지 않으며, 사람들이 바로 이런 초대를 기대하도록 길들인다고 지적했다. 공격자가 드러낸 허점부터 살펴보라는 조언도 덧붙였다. 발신자는 ‘nthropic’에서 왔다고 했고, 이메일에는 고투웨비나 브랜드가 붙어 있었으며, 등록 페이지는 줌 회의 페이지를 흉내 냈고, 로그인 페이지는 구글 또는 마이크로소프트의 것이었다. 클릭 3번에 3개의 브랜드가 등장한 셈이다.
office[.]com-access-sharepoint[.]com 같은 가짜 로그인 도메인은 꼼꼼히 읽는 대신 대충 훑어보도록 설계됐다. 딕슨은 구글 페이지가 사용자 이름만 수집한 것도 설정 오류일 수 있지만, 이번 캠페인의 배후 공격자가 조만간 수정할 가능성이 크다고 내다봤다.
물론, 보안 교육도 도움은 된다. 그러나 금요일 오후 퇴근 시간만을 기다리며 URL 주소를 쳐다보는 직원에게 전적으로 방어를 맡기고 싶지는 않을 것이다. 탈취된 비밀번호의 가치를 얼마로 볼 것인가는 직원이 통과하지 못하는 시험이 아니라 경영진이 결정할 사안이다.
또한 딕슨은 패스키 같은 피싱 방지 다중 인증(MFA)을 적용하면 탈취한 비밀번호의 가치가 크게 떨어진다고 언급했다. 다만 이런 사기로부터 스스로를 지키기 위해 기업이 실행해야 할 체크리스트는 그다지 복잡하지 않다.
• AI 프리뷰 초대는 계정 담당 팀이나 신뢰할 수 있는 기존 연락처를 통해 확인한다.
• 이메일, 회의 페이지, 로그인 페이지로 넘어가며 브랜드가 바뀌면 위험 신호로 간주한다.
• 피싱 방지 다중 인증을 도입한다. 이런 피싱 로그인 페이지에 자격 증명을 입력한 직원이 있다면 비밀번호를 재설정하고 해당 계정의 활동 내역을 점검한다.
딕슨은 이번 캠페인이 신뢰받는 도구를 이용해 신뢰에 기반한 방어를 무력화한다는 점이 핵심이라고 결론지었다. 직원이 마지막 방어선이 되어서는 안 된다는 주장이다.
