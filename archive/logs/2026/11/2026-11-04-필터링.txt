Cryptocurrency exchange Binance says North Korean hackers used a fake job interview to trick an employee into installing malware that ultimately let them compromise the company's wallet infrastructure and steal about $6.34 billion in digital assets.
This new information was shared in an incident report published today, which details how the attackers used social engineering, malicious software, and compromised internal systems to carry out the October 29 crypto theft.
As previously reported by BleepingComputer, the FBI attributed the attack to North Korean state-sponsored hackers known as TraderTraitor, also tracked as Lazarus Group, Jade Sleet, and APT38.
Binance says the attack began in September when a software engineer was contacted through a legitimate job-hunting platform by someone impersonating a Project Director at a fictitious company.
The employee's profile referenced his experience at Binance, making him a valuable target for attackers looking to breach the cryptocurrency exchange.
The fake recruiter scheduled two interviews for the employee, first with someone posing as a human resources representative, then with another individual claiming to be the company's CEO.
During the first interview, the fake HR representative held a live video call and shared a social media account with personal photos and videos to build trust.
The second interview took place through a popular social chat application where the employee was instructed to download a coding assignment from an online code repository.

"The malware employed sophisticated obfuscation and evasion techniques, including replacing a legitimate development tool component with a malicious version to execute commands and establish communication with an attacker-controlled external server," explained Binance.

Binance explained that the malicious script created a replacement executable named pyenv_ in the macOS Homebrew installation directory.
The script then deleted the legitimate pyenv executable, renamed the malicious file to pyenv, modified its symbolic link, and used it to spawn a Z shell (zsh) process.
The malicious replacement allowed the attackers to execute commands received from an attacker-controlled server.
By October 20, the attackers had used the compromised engineer's computer and an internal AI tool to compromise two additional employees working on Binance's wallet infrastructure, obtaining credentials and a container deployment token.
On October 29, the hackers used the stolen credentials to deploy a malicious script and gain unauthorized access to Binance's wallet signing service, allowing them to transfer billions of dollars in cryptocurrency across multiple blockchains.
The attackers also abused Ethereum's EIP-7702 authorization mechanism, allowing them to continue stealing cryptocurrency even after the exchange suspended withdrawals.
Binance says it has since rebuilt affected systems, replaced compromised devices, and revoked stolen credentials.
As of November 3, approximately $2.85 billion in stolen assets had been frozen or intercepted, while 98% of impacted token assets had been replenished as of October 31.
Binance says it is continuing to investigate the breach and has brought in independent security firms to review its findings.

A critical Android flaw could allow an attacker to run code on a phone without any user action remotely, Google said in its November security bulletin.
The flaw, CVE-2026-58868, affects Android 14 through 17. Phones get the fix with security patch level 2026-11-01 or later, which phone makers and carriers send on their own schedules.
As of November 4, Google's bulletin did not report any attacks exploiting its flaws. None of them was in the Known Exploited Vulnerabilities catalog, kept by the U.S. Cybersecurity and Infrastructure Security Agency, as of its November 3 update.
The flaw is a possible out-of-bounds write caused by a heap buffer overflow in the onOutputReceived function of the file FrameDecoder.cpp. Neither the bulletin nor the flaw's CVE record says how an attacker would reach that code.
Google's Critical rating assumes that the protections built into Android and Google's services are turned off or bypassed.
Older versions, such as Android 12 and 13, are not listed as affected by the flaw. Google's records do not say whether they contain it.
How to Check Your Phone
Google's help page gives these steps:
- Open the Settings app.
- Tap About phone, or About tablet, then Android version.
- Find the dates for the Android security update and the Google Play system update.
The Android security update date is the phone's security patch level. A date of 2026-11-01 or later covers CVE-2026-58868 and the other flaws in the Framework, System, and Android runtime components.
A date of 2026-11-05 or later covers every flaw in the November bulletin, including those in the kernel and in parts from Arm, Imagination Technologies, MediaTek, Unisoc and Qualcomm.
Google sets two dates so phone makers can ship a set of fixes common to all Android devices sooner. It encourages them to include every fix in the bulletin.
Phones running Android 10 or later may also receive some fixes through Google Play system updates. This month's list for those updates includes another Critical flaw, CVE-2026-58876.
CVE-2026-58868 is not on that list, so the date to check for it is the Android security update.
The bulletin gives no workaround for phones that cannot install the update yet.
A Remote Denial-of-Service Flaw in Android's Text-Message Code
Another Critical flaw, CVE-2026-58882, could allow a remote denial-of-service attack with no user interaction, according to its CVE record. It is in decodeWapPdu, a function in Android's code for WAP Push messages that arrive via SMS.
On October 29, a researcher who publishes as Mark B posted a write-up called "SMS of Death" about a bug in the same function. Neither the bulletin nor the CVE record says whether CVE-2026-58882 is that bug.
One malformed WAP Push message crashes com.android.phone and ends any active call, including emergency calls, according to the write-up. In tests on several phone models, the crash happened every time.
The attacker needs only the target's phone number, and the message never shows up in the inbox. The phone retries the message each time it starts, so it can crash on startup until the message is removed.
A proof-of-concept app that sends such a message from one phone to another is public. Phones running Android 12 and 13 run the same code but do not receive the fix that newer versions do, the researcher says.
Other Critical Flaws
Google's November bulletin lists 216 vulnerabilities, 23 of them rated Critical. Two more Critical flaws could allow remote code execution: CVE-2026-58876 and CVE-2026-58936, both in Android's System component.
Six Critical flaws are in the kernel, two of them in Bluetooth code. The most severe kernel flaw could allow a remote attacker to gain elevated privileges without user interaction.
The 2026-11-05 patch level also fixes Critical flaws in MediaTek modem code and in a closed-source Qualcomm component. In its November bulletin, MediaTek describes its Critical modem flaws as out-of-bounds writes and says it is not aware of any active exploitation.

Attackers exploit critical Node-RED flaw to deploy Linux bot and backdoors (CVE-2026-58115)
Attackers are exploiting an authentication flaw (CVE-2026-58115) in Node-RED, a programming tool built into some industrial control products, to install a Linux bot and backdoors on unprotected servers, VulnCheck has found.
Node-RED is a flow-based programming tool built on Node.js that lets users wire together event-driven applications in a browser-based editor. It can run on small devices such as the Raspberry Pi or in the cloud, and it is used in manufacturing, healthcare, and home and industrial automation.
The tool is also part of critical infrastructure, embedded in commercial ICS/OT products such as Siemens’ SIMATIC IoT2050 Advanced, which is affected by the flaw. Siemens disclosed it in August and gave it a CVSS score of 10.0, warning that devices running Industrial OS with Node-RED installed, in versions before V4.3.4.1, are vulnerable.
The bug “could allow an unauthenticated remote attacker to create malicious flows and execute arbitrary code on the underlying server with maximum privileges,” Siemens said at the time of disclosure.
Caught by a decoy
More than two months after Siemens’ disclosure, the flaw is being exploited in the wild.
“On October 30, 2026, one of our canaries caught an attacker exploiting CVE-2026-58115,” wrote VulnCheck researcher Patrick Garrity.
“The attacker’s request was a complete exploit. It deployed a Node-RED flow, triggered it automatically, and pulled a binary from an attacker-controlled server, all behind three layers of encoding,” added Garrity.
“Two built-in node types make this trivial to weaponize. An inject node fires a message on a schedule or once at startup, and an exec node runs a shell command. Wire one to the other and the flow executes a command as soon as it is deployed, with no further interaction,” he explained.
The flow downloaded a file named bot-linux-amd64 from a separate server, saved it under a hidden name in a memory-backed location and ran it in the background. VulnCheck did not retrieve the binary, so the company can’t say whether it is a cryptominer, a DDoS bot, a reverse shell or something else.
One address, eight CVEs
The request came from an IP address in Microsoft’s network that geolocates to Brazil. “It didn’t just scan us. It sent the complete exploit, flow and dropper, in a single POST /flows,” Garrity stated.
The same address went after the Node-RED flaw 16 times between October 30 and November 1, and in VulnCheck’s wider canary data it logged 125 hits against 8 different CVEs, old and new, in Apache Solr, Camunda, Gitea, MLflow, Traefik and Joomla.
Garrity describes this as opportunistic mass scanning, and notes that an address in a large cloud provider’s range is usually a rented or compromised virtual machine and says little about who is behind the attacks.
Later requests brought new payloads. One fetched a shell script from the same download server, and another pulled a file from a second server and saved it under a name made to look like a kernel worker thread. Several requests installed webshells that let the attackers come back and run commands at will. The bot is stored in memory and is lost on reboot unless it sets up persistence some other way, while the webshells stay in place after a restart.
The exploitation activity (Source: VulnCheck)
Check your instances
VulnCheck added the flaw to its KEV catalog after spotting the in-the-wild attempt and noted that CISA had not listed it in its own KEV catalog at the time of writing.
“Node-RED instances without adminAuth are being found and exploited automatically,” Garrity warned.
“If you run Node-RED anywhere, including inside OT environments, check today whether it’s reachable from outside your network, apply updates where available and implement detections to reduce the risk of exploitation,” he added in a LinkedIn post.

◇ 병목은 모델에서 ‘운영 통제’로 옮겨갔다
기업용 AI 에이전트의 걸림돌은 모델 성능보다 운영 쪽으로 이동하는 분위기다. 가트너에 따르면, 내년까지 기업의 40%가 자율형 AI 에이전트를 강등하거나 폐기할 것으로 전망됐다. 실제 운영 환경에서 사고가 난 뒤에야 거버넌스의 구멍이 드러난다는 이유다. 가트너 측은 기업이 에이전트 거버넌스를 전면 차단 아니면 전면 신뢰로 양분해 다룬 것이 실패 원인이라고 짚었다.
결국 에이전트 도입 경쟁은 어떤 모델을 고르느냐보다, 사고가 났을 때 누가 어디까지 되짚을 수 있느냐로 무게중심이 옮겨가는 모양새다. 이미 기업의 데이터와 권한 체계를 쥔 플랫폼 업체에는 그 체계를 에이전트에도 그대로 입힐 수 있다는 점이 무기가 된다. 이 같은 배경에서 스노우플레이크는 엑스페디션을 통해 카드를 꺼냈다.
스노우플레이크는 기업 데이터와 비즈니스 맥락, AI 모델 선택, 소프트웨어·앱 연동을 AI 데이터 클라우드 위에서 묶는 에이전틱 컨트롤 플레인 구상을 제시했다. 크리스티안 클라이너만(Christian Kleinerman) 제품 담당 수석부사장은 대부분의 기업이 AI 시대에 맞게 설계돼 있지 않다고 진단했다. 부서 경계 때문에 질문이 인사이트가 되고 다시 행동으로 이어지기까지 시간이 오래 걸린다는 것이다. 이를 위해 스노우플레이크는 제품 개발팀이 고객 현장에서 직접 지원하는 프론티어 엔지니어링 조직도 운영한다.
◇ 용어는 하나로, 에이전트의 통행로도 하나로
이번 발표에서 신뢰를 맡은 것은 비즈니스 온톨로지다. 온톨로지는 비즈니스 개념과 그 관계를 체계적으로 정의한 지식 지도를 뜻한다. 스노우플레이크 관계자는 고객사들이 도메인별로 에이전트를 수십 개씩 만들면서 시맨틱 뷰를 따로 구축하다 보니, 같은 개념을 조금씩 다르게 정의하는 문제가 나타났다고 밝혔다.
온톨로지는 핵심 용어의 공식 의미를 담당자 승인을 거쳐 한 번 정의하고, 이를 하위 테이블과 뷰에 연결하는 방식이다. 기존 시맨틱 뷰를 대체하지 않고 보완하므로 이전 작업은 필요 없다. ‘코텍스 센스’가 추론해 메우되, 추론이 충돌하면 승인된 공식 정의가 우선한다.
코텍스 AI 게이트웨이는 기업이 운영하는 모든 에이전트가 거치는 단일 통로다. 에이전트의 모든 도구 호출에 사람과 같은 접근 정책과 권한이 적용되고, 승인되지 않은 호출은 민감한 시스템에 닿기 전에 막힌다. 격리된 환경에서 에이전트의 코드를 실행하는 ‘코텍스 샌드박스’와 개별 프롬프트가 아니라 실행 과정 전체를 분석해 권한 남용을 가려내는 ‘에이전트 어뷰즈 디텍션’도 공개됐다.
에이전트의 모든 활동을 고객 계정에 기록하는 옵저버빌리티와 사용자·팀·에이전트별 지출 한도를 거는 코스트 거버넌스는 정식 출시됐고, 프롬프트 인젝션과 탈옥을 막는 가드레일은 공개 예정이다. 스노우플레이크는 오픈AI와 개인정보 보호형 안전성 신호를 위험 활동 탐지에 접목하는 협력도 진행한다.
◇ 파이프라인은 에이전트, 승인은 사람
자율형 데이터 엔지니어링은 에이전트가 파이프라인 구축·운영·수정을 맡고 엔지니어는 프로덕션 반영 여부만 결정하는 구조다. ‘코코 클라우드 에이전트’는 엔지니어 노트북이 아니라 스노우플레이크가 관리하는 격리 컨테이너에서 돌아 로그오프 뒤에도 작업이 이어진다. ‘코코 오토메이션’을 쓰면 파이프라인 상태 점검이나 실패 원인 분석을 자연어로 설명하고 실행 주기만 정해 두면 된다. 문제가 발견되면 코코가 원인을 추적해 수정안을 내놓고, 엔지니어가 검토해 반영한다.
‘파이프라인 빌더’는 시각 편집기에서 단계를 연결하는 방식이며, 회사는 에어플로 같은 외부 오케스트레이터를 대체할 수 있다고 설명한다. 아파치 스파크 파이프라인은 코드 변경을 최소화해 옮길 수 있고, 코코가 기존 코드를 스노우플레이크용으로 재작성한다. 실시간 분석은 데이터 수집부터 활용까지를 하나의 거버넌스 아래 두는 것이 골자다. 회사에 따르면, 초당 최대 20GB를 스트리밍하고 데이터는 중앙값 기준 3초 안에 쓸 수 있는 상태가 된다.
‘코코·코워크 봇’도 눈에 띄었다. 봇은 사용자와 같은 데이터 접근 권한과 역할, 실행 권한을 그대로 적용받으며 고객 미팅 브리핑 준비나 파이프라인 상태 관리 같은 큰 목표를 받아 백그라운드에서 계획하고 수행한다. 중요한 결정이나 최종 승인이 필요할 때만 사용자를 호출한다.
정식 출시된 오토메이션으로는 영업 총괄이 매주 실적 분석 보고서를 이메일로 받는 식의 반복 업무를 맡길 수 있고, 모든 실행에는 감사 추적과 작업 이력이 남는다. ‘스노우플레이크 포 슬랙’, 엑셀·시트용 코코, 모바일 앱이 더해져 업무 도구를 바꾸지 않고도 쓸 수 있다. 공유와 맞춤 기능도 늘었다. 검증된 워크플로우를 조직 전체에 배포하는 스킬스·플러그인 공유는 정식 출시됐다. 코워크는 분석 결과를 HTML 보고서나 대시보드로 팀에 공유할 수 있다.
◇ 비용, 모델을 바꿔 끼우고 직접 키운다
에이전트가 늘수록 토큰 비용이 쌓인다는 점은 이번 발표의 또 다른 축이다. 라우팅 기능은 대량의 백그라운드 작업에는 경량 모델을, 복잡한 질의에는 고성능 추론 모델을 자동으로 연결한다.
스노우플레이크 관계자는 최신 모델이 늘 필요한 것은 아니라는 인식이 고객 사이에 퍼지고 있다고 전했다. ‘코텍스 트레이닝’은 오픈 웨이트 모델을 기업 고유 데이터로 후속 학습시키는 서버리스 서비스다. 스노우플레이크는 자체 벤치마크에서 기존 서버리스 학습 옵션보다 최대 61% 낮은 비용으로 학습할 수 있었다고 밝혔다.
‘스노우플레이크 프랙티셔너’는 고객과 파트너에게 무료로 제공하는 2일 과정이다. 데이터 분석가, 데이터 엔지니어, 플랫폼 관리자 세 트랙으로 나뉘고, 모든 실습에 코코를 쓴다. 스웨드뱅크는 2027년까지 정기 교육을 운영할 계획이다.
앞서 지난달 27일 스노우플레이크는 오라클과 자사 AI 데이터 클라우드를 오라클 클라우드 인프라(OCI)의 퍼스트파티 서비스로 제공하기로 했다고 발표했다. 고객은 오라클을 통해 구매·청구하며 오라클 유니버설 크레딧도 쓸 수 있다.

[TITLE] "AI가 다른 AI의 가중치 직접 수정"…재학습 없이 수학 평가 점수 6배 상승
[LINK] https://www.aitimes.com/news/articleView.html?idxno=216971
[PUBLISHED] 2026-11-04 12:40 KST
[SOURCE] AI타임스
[TOPIC] 개발, 모델
[SCORE] 6
[REASON] AI가 다른 모델 가중치 직접 수정해 성능 향상
[FIELD] AI 모델
[BODY]
첨단 AI 모델이 다른 AI의 신경망 가중치를 직접 분석하고 수정해 성능을 크게 높일 수 있다는 연구 결과가 나왔다. 기존처럼 데이터를 추가 학습시키지 않고 전체 가중치의 0.016%만 변경해 수학 평가 점수를 6배 이상 높인 것으로, AI가 다른 AI의 내부 구조를 직접 수정하는 새로운 모델 개선 방법을 제시했다.
MIT 연구진은 2일(현지시간) AI가 신경망의 가중치를 직접 분석하고 수정하는 '가중치공간 프로그래밍(Weight-Space Programming)' 연구 결과를 공개했다. 벤처비트는 이를 신경망의 '유전자 편집'에 비유했다.
가중치는 AI가 입력된 정보를 처리하고 답변을 생성하는 방식을 결정하는 수치다. 일반적으로 모델 성능을 개선하려면 추가 데이터를 학습하거나, 정답과 오답의 차이를 계산해 가중치를 조정하는 미세조정 과정을 거친다. 그러나 이번 연구에서는 첨단 AI 모델이 다른 모델의 가중치를 분석하고 문제가 발생하는 부분을 직접 찾아 수정했다.
연구진은 오픈AI의 'GPT-6 아스트라'에 알리바바의 소형 모델 '큐원3.5-0.8B'의 수학 성능을 개선하라는 목표를 제시했다. 아스트라는 파이썬 도구로 큐원의 가중치를 분석하고 수정한 뒤 실제 문제를 풀도록 해 결과를 확인했다. 이 과정에서 기존의 경사하강법이나 별도의 추가 학습은 사용하지 않았다.
분석 결과, 큐원은 수학 문제를 풀다가 같은 추론을 반복하면서 답을 완성하지 못하는 문제가 있었다. 아스트라는 특정 신경망 계층의 가중치가 이러한 반복과 관련이 있다고 판단하고, 15번째와 19번째 계층의 가중치 13만1072개를 수정했다. 이는 전체 약 8억개 가중치의 0.016%에 불과하다.
그 결과 수학 문제 해결 능력을 평가하는 'MATH-500' 점수는 기존 7.9%에서 48.1%로 약 6.1배 높아졌다. 또 다른 수학 평가인 'GSM8K'도 13.8%에서 67.1%로 상승했으며, 지시 이행 능력을 평가하는 'IFEval'도 21.0%에서 62.3%로 개선됐다.
수학적 추론 능력 자체가 6배 높아졌다는 의미는 아니다. 기존 모델은 수학 문제를 풀다가 같은 내용을 반복해 출력 한도에 도달하는 일이 잦았다. MATH-500에서 출력 한도에 도달한 비율은 수정 전 93%에서 수정 후 33.1%로 낮아졌다. 연구진은 모델이 이미 갖추고 있던 문제 해결 능력을 제대로 발휘하지 못하도록 방해하던 결함을 제거한 결과로 분석했다.
연구진은 다른 실험에서도 AI가 신경망의 가중치를 직접 분석하고 수정할 수 있다는 사실을 확인했다. 아스트라는 브레이크아웃과 퐁, 팩맨 등 4개 게임용 신경망의 가중치만 보고 각각 어떤 게임을 위해 학습된 모델인지 모두 맞혔다.
또 자동차가 경사로를 넘지 못하는 시뮬레이션에서는 전체 가중치의 3.5%만 수정해 성공률을 0%에서 100%로 높였다. 기존 모델은 경사로에 곧바로 진입하다 멈췄지만, 수정된 모델은 먼저 후진해 가속 거리를 확보한 뒤 경사로를 통과했다. 일부 게임에서는 신경망 가중치를 추가 학습 없이 처음부터 작성해 기존 강화학습 모델보다 높은 점수를 기록하기도 했다.
하지만 모든 실험이 성공한 것은 아니다. 구글의 소형 모델 '젬마 3 270M'에서도 수학 성능 개선을 시도했지만, 뚜렷한 성과를 얻지 못했다. 큐원과 달리 반복 출력 문제가 거의 없었으며, 일반적인 계산이나 추론 오류는 가중치 일부를 수정하는 것만으로 해결하기 어려웠기 때문이다.
이번 연구는 AI 모델의 내부 구조를 분석하는 '기계적 해석 가능성(Mechanistic Interpretability)' 연구가 실제 모델 수정으로 이어질 수 있다는 점에서 의미가 있다. 지금까지 신경망의 특정 가중치가 어떤 역할을 하는지 파악하는 데 집중했다면, 앞으로는 AI가 문제를 일으키는 부분을 직접 찾아 수정하거나 새로운 기능을 구현하는 데 활용할 가능성을 보여준 것이다.
연구진은 "앞으로 신경망 가중치는 가중치 자체를 분석하고 추론하는 LLM에 의해 직접 최적화될 것"이라고 전망했다.
그러나 이번 연구는 제한된 모델과 실험 환경에서 나온 초기 성과로, 가중치 수정에 여러 차례의 분석과 평가가 필요했다. 기존 미세조정보다 시간이나 비용이 적게 든다는 사실도 입증하지 못했으며, AI가 스스로의 성능을 지속적으로 높이는 자율적 자기 개선 능력까지 보여준 것은 아니라는 평이다.

[TITLE] 연세대, 차세대 양자컴퓨터 가동…회로 처리량 25배↑
[LINK] https://zdnet.co.kr/view/?no=20261104110101
[PUBLISHED] 2026-11-04 11:38 KST
[SOURCE] ZDNet Korea
[TOPIC] 신기술, 산업
[SCORE] 6
[REASON] 대학 자체 시설에 IBM 양자프로세서 첫 구축
[FIELD] 신기술
[BODY]
연세대학교가 차세대 양자프로세서(QPU) 'IBM 퀀텀 나이트호크 r2'를 도입하고 바이오 난제 연구를 확대한다.
이번 도입은 IBM 퀀텀 네트워크 참여 기관 중 자체 시설에 구축한 세계 첫 사례다. 연세대는 슈퍼컴퓨터와 연계해 질병 기전 규명과 신약 개발 연구에 활용할 계획이다.
연세대학교와 IBM은 4일 인천 연세대학교 송도 국제캠퍼스에서 차세대 양자컴퓨팅 플랫폼 가동식을 개최했다.
이번 업그레이드는 연세대가 2024년 127큐비트 이글 기반 'IBM 퀀텀 시스템 원'을 도입한 이후 2년 만에 진행됐다.
나이트호크 r2는 프로그래머블 큐비트 120개를 탑재한 IBM의 최신 QPU다. 큐비트 수는 기존보다 줄었지만 큐비트 간 연결성과 초기화 속도를 개선해 복잡한 회로를 효율적으로 실행하도록 설계됐다.
특히 연산을 마친 큐비트를 초기 상태로 되돌리는 시간을 단축해 초당 10만개 이상 회로를 실행한다. 헤론 대비 회로 처리량이 25배 높아 연구자가 같은 시간에 더 많은 측정 결과를 확보할 수 있다.
큐비트 연결 구조도 바뀌었다. 나이트호크 r2는 대부분 큐비트가 인접한 큐비트 4개와 연결되는 정사각 격자 구조를 적용했다. 떨어진 큐비트 사이에서 연산하기 위해 정보를 옮기는 스왑 게이트를 줄여 회로 구성 효율을 높이고 오류 누적 부담을 낮출 수 있다는 설명이다.
IBM은 나이트호크 r2를 활용해 게이트 7500개 이상으로 구성된 회로에서 정확한 관측량 추정 결과를 얻었다고 밝혔다.
제리 차우 IBM 펠로우 겸 양자중심슈퍼컴퓨팅 최고기술책임자(CTO)는 중성자 산란 시뮬레이션에서 12배 속도 향상을 확인했다고 소개했다. 고객과 파트너가 수행한 일부 작업에서도 전체 처리시간을 기준으로 3배에서 최대 19배까지 속도가 개선됐다고 설명했다.
연세대는 새로운 프로세서를 양자·인공지능(AI)·바이오 융합 연구에 활용할 방침이다. 정재호 연세대 양자사업단장은 지난 2년간 교육과 개방형 생태계 구축에 집중했다면, 앞으로는 더 복잡한 연구 과제에 도전하기 위해 계산 역량과 국제 협력을 확대하겠다고 밝혔다.

Anthropic's Message Threads cut time to first token by 35 percent for long conversations
Anthropic released Message Threads as a public beta on its Claude platform. Until now, every API request had to resend the entire conversation history. Message Threads only transmits what's changed since the last message, cutting time to first token by about 35 percent for requests between 500,000 and one million tokens, according to Anthropic.
Coding agents, computer-use agents, and workflows processing lots of documents or images benefit the most, the company says. The thread stays encrypted in memory between requests and expires after five minutes of inactivity. Token usage doesn't change since Claude still reads the full conversation history. [FIELD] 보안
[BODY]
Barracuda has disclosed details of two vulnerabilities affecting its products that, if chained together, could allow an attacker to bypass authorization controls and gain root access to a susceptible device.
The vulnerabilities, a pre-authentication authorization bypass vulnerability and a command injection vulnerability, have been assigned the CVE identifiers CVE-2026-116606 (CVSS score: 9.3) and CVE-2026-111560 (CVSS score: 8.6), respectively.
While CVE-2026-116606 only affects Email Security Gateway, CVE-2026-111560 impacts the following Barracuda products -
- Email Security Gateway
- Load Balancer Application Delivery Controller
- Message Archiver
- WAF Control Center
- Web Application Firewall
- Web Security Gateway
"Successful exploitation requires an attacker to have access to the administrative interface of an affected product," Barracuda said. "If exploited in combination, these vulnerabilities could allow an attacker to bypass authorization controls and obtain root access to the device."
Barracuda said that organizations that do not expose their administrative interfaces to the internet are less vulnerable to the attack path, urging customers to follow the steps below -
- Restrict access to administrative interfaces to trusted internal networks
- Use appropriate network access controls to limit exposure
"Customers using these products should verify that their systems are running the latest firmware versions and have received all security patches," it added. "If firmware on a device is multiple versions out of date, customers may need to perform more than one update."
