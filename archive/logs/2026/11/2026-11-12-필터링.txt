[FIELD] 신기술

차세대 양자 프로세서 ‘나이트호크 r3’ 공개 계획…520큐비트에서 양자 연산 1만 회 수행 목표
IBM이 기존 양자 프로세서보다 최대 19배 빠른 연산 성능을 확보하고, 2027년까지 1,000큐비트 이상의 대규모 양자컴퓨터를 구축하겠다는 계획을 발표했다. 양자컴퓨터의 성능 경쟁을 단순한 큐비트 수 확대에서 실제 연산 속도와 정확성, 산업 현장 활용 능력으로 확장하겠다는 전략이다.
IBM은 11일(미국 현지시간) 차세대 양자 프로세서 'IBM 퀀텀 나이트호크 r3(IBM Quantum Nighthawk r3)' 개발 계획과 기존 나이트호크 r2의 성능 검증 결과를 공개했다. 새로운 프로세서는 520개의 프로그래밍 가능한 큐비트에서 1만 회의 양자 연산을 정확하게 수행하도록 설계되며, 2027년 두 개의 프로세서를 연결해 총 1,040큐비트 규모의 시스템을 구축하는 것이 목표다.
이번 발표에서 주목할 부분은 양자컴퓨터의 처리 속도와 실제 응용 성능이다. 지난 9월 도입된 나이트호크 r2는 120큐비트에서 7,500회 이상의 양자 연산을 지원하며, 초당 최대 10만 개의 측정 샘플을 생성할 수 있다.
양자컴퓨터는 연산 회로를 실행할 때마다 측정 결과를 하나씩 얻기 때문에 복잡한 문제를 해결하려면 수백만 개에서 수십억 개의 샘플을 수집해야 한다. 따라서 연산 정확도뿐 아니라 반복 실행 속도가 실제 활용 가능성을 결정하는 핵심 요소다.
IBM은 고속 큐비트 초기화 기술을 적용해 연속적인 양자 회로 실행 사이의 대기 시간을 크게 줄였다. 이를 통해 대규모 연산에 필요한 샘플을 더 빠르게 확보하면서 과학적 계산에 요구되는 정확도를 유지하도록 했다.
독일 에너지 기업 이온(E.ON), 핀란드 양자 소프트웨어 기업 알고리드미크(Algorithmiq), 호주 양자기술 기업 큐컨트롤(Q-CTRL) 등 고객사와 협력기관은 나이트호크 r2에서 총 340억 회 이상의 양자 회로를 실행했으며, 기존 IBM 양자 프로세서 대비 최대 19배의 성능 개선을 보고했다.
산업별 적용에서도 구체적인 성과가 나타났다. 이온은 전력망 최적화를 위한 인공지능(AI) 기술인 양자 머신러닝 연산에서 기존 대비 15배의 속도 향상을 확인했다. IBM은 미국 오크리지국립연구소(Oak Ridge National Laboratory)와 수행한 자성 물질 시뮬레이션 실험에서도 이전 헤론(Heron) 프로세서 기반 실험보다 12배 빠른 처리 속도를 달성했다. 해당 시뮬레이션 결과는 중성자 산란 실험에서 관찰된 결과와 일치했다.
알고리드미크와 진행한 비균질 양자 물질 시뮬레이션에서는 기존 헤론 기반 실험보다 양자 회로 실행 속도가 8배 향상됐다. 특히 새로운 양자 회로를 선도적인 고전 텐서 네트워크 기법으로 비슷한 정확도로 시뮬레이션하려면 기존 실험 대비 약 240배의 메모리가 필요할 것으로 추정됐다.
이는 양자컴퓨터가 고전 컴퓨터로 모사하기 어려운 복잡한 계산 영역으로 확장되고 있음을 보여주는 사례다. 다만 특정 실험 조건과 시뮬레이션 기법에 따른 비교 결과로, 모든 산업 문제에서 양자컴퓨터가 고전 컴퓨터보다 우수하다는 의미는 아니다.
IBM은 차세대 나이트호크 r3에 총 2,034개의 물리적 큐비트를 배치하고, 이 가운데 520개를 프로그래밍 가능한 큐비트로 활용하도록 설계할 계획이다. 또한 프로세서 간 연결을 위한 10개의 '엘 커플러(l-coupler)'를 도입해 여러 양자 칩을 하나의 대규모 시스템으로 통합한다.
이러한 모듈형 설계는 단일 반도체 칩의 크기와 집적도에 의존하지 않고 양자컴퓨터의 연산 규모를 확대하기 위한 접근이다. IBM은 올해 나이트호크 r1 프로세서 두 개를 4개의 엘 커플러로 연결하는 실험에서 양자 상태 전달 충실도 99.3%를 달성했다. 현재 목표는 이를 99.9%까지 높이는 것이다.
또한 두 개의 극저온 모듈을 하나의 시스템으로 연결해 5일 이내에 작동 온도에 도달하고, 온도를 15밀리켈빈 이하로 낮추는 데 성공했다. 양자 프로세서의 안정적인 작동에 필요한 극저온 환경을 여러 모듈에 걸쳐 구현했다는 점에서 대규모 시스템 구축을 위한 기반 기술로 평가된다.
IBM은 양자 하드웨어의 성능 개선과 함께 고전 컴퓨팅 자원을 통합하는 'IBM 퀀텀 플랫폼(IBM Quantum Platform)'도 강화하고 있다. 이 플랫폼은 양자컴퓨터와 고성능컴퓨팅(HPC) 자원을 하나의 관리 환경에서 활용하도록 설계됐다. 연구자는 개인용 컴퓨터부터 슈퍼컴퓨터까지 다양한 고전 컴퓨팅 자원을 양자 연산 과정에 연결할 수 있다.
실제로 IBM과 일본 이화학연구소(RIKEN)는 새로운 환경에서 샘플 기반 양자 대각화(SQD) 작업을 수행해 기존 연구보다 약 100배 많은 계산을 처리하면서 실행 속도를 약 5배 높였다.

이는 양자 연산 과정에서 발생하는 오류를 분석하고 보정하는 데 고전 컴퓨팅 자원을 활용하기 위한 것으로, 향후 오류 내성 양자컴퓨터 구현을 위한 핵심 기술 기반이 될 전망이다.

Their search covered only the default branches of public repositories, so the true total is higher, the researchers say.

More pull requests with the same title were opened early today, after the company's own GitHub search ended on Wednesday, a check by The Hacker News found. Three that were checked, opened between 05:04 and 05:38 UTC, came from wfx-docs branches. It is not clear whether the stealer followed.

SafeDep's researchers advise owners of affected repositories to revoke the commit author's tokens, OAuth app grants, SSH keys, and sessions, and to turn on 2FA. Owners should also rotate every secret and variable the repository can read. Anyone who ran npm install on an affected commit should treat that machine as compromised and rotate its keys.
In most other repositories that received a test, nothing was pushed afterward, or the stealer did not run due to the repository's settings or the account's permissions. The figures cover only the public repositories the company could see.
The tests also reached repositories that the compromised accounts did not own. Of the test pull requests, 10,431 were submitted via collaborator or organization access, and 92% of those were still open when the company checked.

[FIELD] 보안
[BODY]
A critical flaw in Apache HTTP Server's HTTP/2 module, mod_http2, can let a remote attacker run code on the server. Tracked as CVE-2026-119618, it affects versions 2.4.55 through 2.4.70 and is fixed in version 2.4.71, released yesterday.
Only servers with HTTP/2 enabled are affected, according to Red Hat, which ships the server as part of Red Hat Enterprise Linux.
An attacker who can reach the server needs no authentication to exploit the flaw and could take full control of the server process, the Linux vendor says. It rates the flaw 9.8 out of 10 on the CVSS scale.
The vendor's assessment, published yesterday, also says "public research has demonstrated a reliable exploit" against a server in its default configuration with mod_http2 enabled. It does not name or link that research. Security company Wiz said later that day that no exploit was available and that no exploitation in the wild had been reported.
HTTP/2 runs only where the Protocols directive turns it on, as the module documentation explains. The directive uses h2 for HTTP/2 over TLS and h2c for HTTP/2 over plain TCP. It can be set for the whole server or for a single virtual host, so admins should check the server-wide setting and every virtual host.
Standalone builds of the module, released on GitHub as mod_h2, are affected from version 2.0.8 through 2.0.42.
Admins who run the Apache HTTP Server project's own releases should move to version 2.4.71, the fixed release named in its security advisory. That release also fixes a crash in mod_md, rated important, and a one-byte overwrite of stack memory in mod_vhost_alias, rated low.
The distributions in the table below ship their own builds of the server, with their own package version numbers. On Red Hat Enterprise Linux 9, for example, the fix ships as mod_http2-2.0.26-7.el9_9.1.
Red Hat shipped fixes for Red Hat Enterprise Linux 9 and 10 yesterday and rates the flaw Important on those releases rather than Critical. Their mod_http2 packages give each HTTP/2 stream its own memory allocator, which makes an attack much harder, according to the vendor's severity assessment. Red Hat Enterprise Linux 8 and earlier do not contain the vulnerable code.
The Debian rows come from Debian's security tracker, and the Amazon row from the Amazon Linux tracker. Ubuntu's CVE tracker had no page for the flaw when The Hacker News checked it today.
The Apache HTTP Server advisory offers no workaround. In its vulnerability analysis, Wiz advises admins who cannot update yet to remove h2 and h2c from the Protocols directive, leaving Protocols http/1.1.
The standalone mod_h2 project has published no fixed release so far. Its release list on GitHub ends at 2.0.42, the last affected version, and its repository has been read-only since it was archived on June 9. The Protocols change above also applies to servers that use those builds.
The flaw was reported on October 26 by Anthropic's OSS Scanner, a free scanning service for open-source projects that uses the company's AI models. Anthony Weems and Simon Scannell of Google Cloud Vulnerability Research reported it last week.
An earlier HTTP/2 flaw, CVE-2026-23918, was fixed in version 2.4.67, released on May 4. Servers updated to that release, or to any later one up to 2.4.70, still run a version that the new flaw affects.

구글 딥마인드가 DNA 변이가 어떤 세포에서 유전자 활동에 영향을 미치는지 예측하는 AI 모델 '알파게놈 2(AlphaGenome 2)'를 공개했다. 기존 모델이 주로 조직 단위로 유전자 활동을 분석했다면, 새 모델은 개별 세포의 유형과 상태까지 구분하며 원인 변이 식별 성능도 약 2배 높였다.
구글 딥마인드는 11일(현지시간) 공식 블로그를 통해 알파게놈 2를 발표했다. 지난해 공개한 첫 번째 알파게놈의 후속 모델로, DNA 염기서열의 작은 변화가 유전자 발현과 세포 기능에 미치는 영향을 예측한다.
가장 큰 변화는 분석 대상을 조직 단위에서 개별 세포 유형과 상태로 세분화한 것이다. 기존 알파게놈은 최대 100만개 염기로 구성된 DNA 서열을 입력받아 여러 조직과 세포주의 특성을 한꺼번에 예측했다. 그러나 여러 세포의 특성이 섞인 조직 데이터를 활용하는 방식이어서 특정 세포에서만 나타나는 미세한 변이 효과를 포착하는 데 한계가 있었다.
알파게놈 2는 DNA 서열과 함께 분석할 세포 유형이나 상태를 지정하는 '조건부 모델'로 설계를 바꿨다. 같은 DNA를 가진 세포라도 면역세포와 심장세포처럼 활성화되는 유전자가 서로 다르다는 점을 반영한 것이다. 이를 통해 동일한 유전자 변이가 어느 세포에서, 어떤 조건일 때 영향을 미치는지 구분할 수 있다.
이를 위해 인간과 생쥐의 68개 조직에서 얻은 1억700만개 이상의 개별 세포 데이터를 활용해 학습했다. 연구자가 새로운 단일 세포 실험 데이터를 입력하면 모델을 다시 학습시키지 않고도 해당 세포 상태에서 DNA 변이가 미치는 영향을 예측할 수 있다.
성능 개선은 면역세포 데이터를 활용한 평가에서 확인됐다. 28개 면역세포 유형을 포함한 'TenK10K' 데이터셋에서 알파게놈 2는 90%의 정밀도를 유지하면서 유전자 활동에 영향을 미치는 원인 변이의 30%를 찾아냈다. 기존 알파게놈을 단일 세포 데이터로 추가 학습한 모델의 16%보다 약 1.9배 높은 수치다.
변이가 유전자 활동을 증가시키는지 감소시키는지 구분하는 능력도 개선됐다. 높은 예측 정확도를 유지하면서 영향의 방향까지 식별한 변이의 비율은 기존 23%에서 43%로 높아졌다. 이는 특정 면역세포 데이터에서 측정한 결과로, 모든 질병 관련 변이를 같은 수준으로 찾아낸다는 의미는 아니다.
이러한 기술은 질병과 관련된 DNA 변이를 발견하더라도 실제 영향을 받는 유전자와 세포를 알아내기 어려웠던 유전학 연구에 도움이 될 수 있다. 구글 딥마인드는 염증성 장질환과 관련된 DNA 변이가 장내 면역세포인 대식세포에서 'ETS2' 유전자를 과도하게 활성화한다는 기존 연구 결과를 알파게놈 2로 재현했다. 해당 변이가 다른 세포에서는 거의 영향을 미치지 않으면서 특정 세포에서만 유전자 활동을 증가시킨다는 사실까지 예측했다.
이는 질병과 연관된 DNA 영역을 찾는 데서 나아가 원인으로 작용할 가능성이 높은 변이와 영향을 받는 유전자, 세포를 함께 좁혀낼 수 있다는 의미다. 이를 바탕으로 추가 실험 대상을 선정하거나 신약 개발에 필요한 치료 표적 후보를 찾는 데 활용할 수 있다. 이번 사례는 이미 실험으로 밝혀진 결과를 재현한 것으로, 새로운 질병 원인을 독자적으로 발견한 것은 아니다.
학습하지 않은 세포 상태도 재학습 없이 분석할 수 있다. 코로나19 mRNA 백신 연구 데이터를 활용한 실험에서는 특정 유전자 변이가 휴지 상태보다 활성화된 면역 T세포에서 더 큰 영향을 미친다는 사실을 예측했다.

[FIELD] AI 모델
[BODY]
중국 AI 기업 미니맥스(MiniMax)가 4K 이미지를 약 10초 만에 생성하는 오픈웨이트 모델 'H3-이미지(H3-Image)'를 출시했다. 하나의 모델로 이미지 생성과 편집을 처리하고 최대 16장의 참조 이미지를 활용할 수 있는 것이 특징이다.
미니맥스는 11일 공식 발표를 통해 H3-이미지를 공개하고, 모델 가중치와 관련 코드를 허깅페이스와 깃허브에 배포했다고 밝혔다. 미니맥스 API와 AI 개발 도구 '미니맥스 코드(MiniMax Code)', 영상·이미지 생성 서비스 '하이뤄 AI(Hailuo AI)'에서도 이용할 수 있다.
H3-이미지는 별도의 업스케일링 없이 4096×4096 해상도의 약 1600만 화소 이미지를 직접 생성하도록 설계됐다. 미니맥스는 주요 상용 모델보다 최대 5배 빠른 속도로 고품질 이미지를 만들 수 있다고 강조했다.
회사가 공개한 API 지연시간 비교표에 따르면 4K 이미지 생성에는 표준 모드 16초, 고속 모드 10.3초가 걸렸다. 같은 해상도에서 구글의 '나노 바나나 2.1'은 48~64초가 소요됐다.
그러나 저해상도에서는 속도 우위가 뚜렷하지 않았다. 1K 이미지 생성에서는 H3-이미지의 표준 모드가 10.6초로, 'GPT 이미지 2.6'의 중간 모드(9초)보다 느렸다.
이미지 생성뿐 아니라 기존 이미지 편집도 동일한 모델에서 지원한다. 최대 16장의 참조 이미지를 입력해 여러 이미지의 요소를 결합하거나 특정 인물과 사물의 외형을 유지하면서 새로운 결과물을 만들 수 있다. 별도의 편집 모델이나 추가 어댑터 없이 다양한 창작 작업을 수행하도록 설계했다.
이미지 품질 측면에서는 자연스러운 질감과 세밀한 표현을 강조했다. 기존 AI 생성 이미지에서 자주 나타나는 지나치게 매끄럽고 인공적인 느낌을 줄이고, 실제 사진에 가까운 결과물을 구현하는 데 초점을 맞췄다. 프롬프트의 세부 지시와 참조 이미지의 특징을 정확하게 반영하는 능력도 주요 강점으로 내세웠다.

가격 경쟁력도 강조했다. API 비용은 이미지 한 장을 생성하는 데 1K는 약 0.022달러, 2K는 0.023달러, 4K는 0.069달러가 든다. 고속 모드는 4K 기준 약 0.130달러로 비용이 높아진다.
오는 17일까지는 4K 이상 이미지 생성 요청에 50% 할인이 적용된다. 미니맥스는 할인 전 가격도 주요 경쟁 서비스의 50~70% 수준이라고 설명했다.

이번 출시로 미니맥스는 영상·음성 생성 모델 H3에 이어 고해상도 이미지 생성까지 제품군을 확대했다. 회사는 빠른 생성 속도와 높은 이미지 품질을 내세웠지만, 프롬프트 이해도와 이미지 품질에 대한 독립적인 벤치마크는 아직 확인되지 않았다.

[PUBLISHED] 2026-11-12 17:20 KST
[SOURCE] The Hacker News
[TOPIC] 보안
[SCORE] 7
[REASON] 노드 서버 운영자는 HTTP/2 결함 수정 버전 적용 필요
[FIELD] 보안
[BODY]
A flaw fixed in Node.js this week lets unauthenticated clients crash servers that use the runtime's built-in HTTP/2 support on the 24.x and 26.x release lines. A second HTTP/2 flaw can cause a server to send a client pieces of its memory, including responses intended for other connections.
Fixed versions were released for all three supported lines: 22.23.5, 24.22.3, and 26.13.1.
The crash flaw, CVE-2026-123863, needs only a default HTTP/2 server that replies before the request body has fully arrived. The Node.js project calls that behavior typical. The crash works over both TLS and cleartext connections.
The memory flaw, CVE-2026-123866, affects all three lines. From 24.22.0 and 26.9.0 onward, a client alone can trigger it. On 22.x and older 24.x and 26.x builds, it can still be triggered when the server itself closes a stream partway through a response, for example after an idle timeout.
A separate flaw in Node.js HTTPS servers, CVE-2026-123864, can allow an unauthenticated client to read memory from other connections, "including TLS private keys and other users' requests," the project says. It affects all three supported lines.
The flaw needs a handler that calls res.flushHeaders() before the request body has fully arrived and later calls res.end() with data. Reading the leaked memory also needs a route that sends back or stores a request body. Plain HTTP servers built with node:http are not affected.
The release fixes 16 vulnerabilities in Node.js itself, seven of them rated high. The other four high-rated flaws, and the servers they affect, are:
- CVE-2026-123865: a client can make any default HTTP/2 server hold memory and file descriptors permanently, on all three lines.
- CVE-2026-123874: a client can corrupt server memory on 24.x and 26.x when the server serves files with stream.respondWithFile() or stream.respondWithFD(). On all three lines, canceling such downloads can also crash the server (CVE-2026-123875, rated medium).
- CVE-2026-126051: a client can crash a TLS server on 24.x and 26.x if the server uses the SNICallback, OCSPRequest, newSession or resumeSession hooks, or server.addContext().
- CVE-2026-123872: on a TLS server with stricter client-certificate rules for some hostnames, a client approved for another hostname can switch to a stricter one during TLS 1.2 renegotiation without meeting its rules. All three lines are affected.
The eight flaws above are all in Node.js's own HTTP/2, HTTPS and TLS server code, so they matter where a Node.js process accepts those connections itself.
Updating to the fixed version for each line is the only fix in the project's security advisory. It lists no workaround for servers that cannot update yet.
End-of-life lines, including 20.x and 25.x, get no fix in this release, and the project says such versions are always affected.
The advisory does not report any attacks using the flaws. It also does not say whether servers that met the conditions for the HTTPS flaw should replace their TLS keys or other secrets after updating.
Five of the flaws, including CVE-2026-123863 and CVE-2026-123864, were reported by Chris Rohlf in collaboration with Claude and Anthropic Research, according to the advisory.

AWS Emulator: Open-source tool for testing AWS apps locally, built by autonomous AI agents
Amazon Web Services has released AWS Emulator, a free tool that simulates AWS services on a developer’s laptop, a development server or in a continuous integration (CI) pipeline. The company says autonomous AI agents wrote the tool entirely, with no code written or reviewed by its engineers. There is no additional service fee, users pay for AWS resources when they deploy applications on AWS.
How three teams of AI agents build AWS Emulator
Three teams of AI agents build and improve AWS Emulator, each with a specific role. AWS says agents perform better when given specific, well-defined tasks.
“The emulator was written entirely by autonomous agents. Our team hasn’t written or reviewed any of the code. We could do this because the guardrails we’ve put in place gave the agents space to work independently and us the trust that they don’t color outside these lines,” Matthew Goldberg, a senior principal engineer at AWS, explained.
A graphic showing how teams of AI agents work together to run tests and solve issues. (Source: AWS)
The first team creates tests from publicly available AWS API specifications and verifies them against real AWS services. The tests cover actions such as creating a message queue, sending and receiving a message, and deleting the queue. The growing collection contains tens of thousands of tests that can be replayed without contacting AWS again.
The second team runs those tests against the emulator to identify differences between its behavior and that of AWS. It reports failures and groups problems that appear to share an underlying cause.
The third team fixes the reported issues, with each agent responsible for one problem. Before a change enters the main codebase, it must pass build checks and reviews by other agents for coding standards, security and fidelity. Changes that fail any of these checks go back for revision.
AWS says hundreds of agents work on the code simultaneously, fixing thousands of issues each day. The checks help maintain code quality as the agents make changes.
Local testing, CI and AI-assisted prototyping
There are four ways to get started with AWS Emulator. Through an AI coding agent, a Linux package, Docker or embedded mode. Each has its own prerequisites. The Linux package runs as a local process, while Docker supports Windows, macOS and Linux. Embedded mode runs the emulator inside a Rust test process.
Developers can use the emulator to test how their code interacts with AWS services, including calls across services, on their own machines. They can run integration tests in a CI pipeline without an AWS account or resources, or prototype applications locally with AI coding agents before deploying them on AWS.
Limitations, telemetry and source code
AWS Emulator is not intended for production workloads. It does not evaluate AWS Identity and Access Management (IAM) or resource-based policies as AWS does, so it should not be used to test security.
The documentation advises using one region and one account for all requests to an emulator instance because it does not keep resources separate by region or account. Its fidelity varies by service and feature. AWS checks behavior against AWS in US West (Oregon), except for global services, which it checks in US East (N. Virginia).
All emulated resources are stored in memory and disappear when the emulator stops. AWS has not tested the tool for long-running use or load testing.
By default, the emulator sends anonymous usage and error data to AWS, though users can disable this reporting. It does not send requests, responses or resource data to AWS.
The source code and fidelity tests are available on GitHub. AWS has released the emulator under the CC0 public-domain dedication. The code repository contains every issue filed by the agents, organized into fixed and unresolved folders. AWS says it publishes per-service fidelity scores with each release.

[TITLE] AI, 프리랜서 업무 41.3% 전문가 수준 수행…1년 전 2.5%서 급상승

[SCORE] 6
[REASON] 에이전트의 실무 수행 능력이 1년 만에 급상승
[FIELD] AI 에이전트
[BODY]
AI가 실제 프리랜서 업무의 41.3%를 인간 전문가와 동등하거나 더 높은 수준으로 수행할 수 있다는 분석이 나왔다. 단순한 지식이나 추론 능력이 아닌, 경제적 가치가 있는 실무 프로젝트를 처음부터 끝까지 완수하는 역량을 평가한 결과다. 1년 전 같은 지표에서 최고 자동화율이 2.5%에 머물렀던 것과 비교하면 AI의 실무 수행 능력이 크게 향상된 셈이다.
미국 AI 안전센터와 스케일 AI는 지난해 처음 공개한 실제 프리랜서 프로젝트 기반 AI 에이전트 평가 지표 ‘원격 노동 지수(RLI·Remote Labor Index)’의 최신 결과를 발표했다.
평가에는 게임 개발과 제품 디자인, 건축, 데이터 분석, 영상 제작 등 여러 분야의 작업이 포함됐다.
RLI는 실제 전문가가 완료한 240개 프로젝트를 바탕으로 구성됐다. 이 가운데 230개는 비공개 평가에 사용하고, 10개는 공개 예시로 제공한다. 전체 작업량은 6000시간을 넘고, 프로젝트의 총가치는 14만달러 이상이다. 일부 과제는 작업 시간이 100시간 이상 소요되거나 비용이 1만달러를 웃돌 정도로 난도가 높다.
AI에는 작업에 필요한 자료와 도구가 제공됐으며, 프로젝트당 실행 비용은 최대 30달러로 제한됐다. AI의 결과물은 전문가가 만든 완성본과 대조해 실제 고객에게 납품할 수 있는 수준인지 3명의 평가자가 직접 평가했다.
최신 평가에서는 앤트로픽의 ‘클로드 페이블 5.2’가 41.3%로 가장 높은 자동화율을 기록했다. '클로드 오퍼스 5.5'는 21.3%, 'GPT-6 아스트라'는 20.8%로 뒤를 이었다. 페이블 5.2의 성능은 직전 세대인 '페이블 5.1'의 17.9%보다 두 배 이상 높다.
AI가 성공적으로 수행한 작업은 음향 효과 제작과 이미지 생성, 보고서 작성, 데이터 검색 등에 집중됐다. 반대로 결과물의 품질이 부족하거나 작업을 끝내지 못하고, 요구된 파일 형식을 지키지 못하는 등의 문제도 나타났다.
RLI가 처음 공개된 2025년 당시 최고 기록은 마누스의 2.5%였다. 이후 모델 성능이 꾸준히 개선되면서 실제 프로젝트를 사람 수준으로 완수하는 비율도 빠르게 상승했다. 이는 AI가 개별 지식이나 코딩 문제를 푸는 능력을 넘어 복잡한 실무 작업을 통째로 수행하는 방향으로 발전하고 있음을 보여준다.
그러나 41.3%는 프리랜서 일자리 전체의 41.3%가 사라진다는 의미는 아니다. 평가 대상 프로젝트 가운데 AI 결과물이 인간 전문가의 작업물과 동등하거나 더 나은 수준으로 인정받은 비율이다. 실제 업무에는 고객과의 소통이나 팀 협업처럼 이번 지수에서 다루지 않은 작업도 포함된다.
