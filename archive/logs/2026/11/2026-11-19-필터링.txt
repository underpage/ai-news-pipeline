[TITLE] 티오리, 세계적 웹 서버 'nginx' 취약점 5건 발견…AI 자율 발굴
[LINK] https://www.etnews.com/20261119000034
[PUBLISHED] 2026-11-19 09:09 KST
[SOURCE] 전자신문
[TOPIC] 보안
[SCORE] 9
[REASON] 전 세계 NGINX 웹서버 관리자는 비인증 RCE 즉시 패치 필요
[FIELD] 보안
[BODY]
국내 보안기업 티오리가 세계적으로 널리 사용되는 웹 서버 소프트웨어 '엔진엑스(nginx)'에서 치명적인 보안 취약점 5건을 발견했다. 이 중 4건은 자체 개발한 인공지능(AI) 보안 플랫폼이 사람의 개별적인 지시 없이 자율적으로 찾아냈다.
티오리는 별도 인증 없이 원격으로 악성코드를 실행할 수 있는 nginx 취약점 5건을 발견했다고 19일 밝혔다.
'nginx2Root'로 명명된 이번 취약점은 공격자가 서버에서 임의의 코드를 실행할 수 있다는 공통점이 있다. 별도로 발견된 리눅스 커널 취약점과 연계하면 최고 관리자(root) 권한까지 탈취할 수 있다. 취약점 중 하나는 2015년부터 약 11년간 존재한 것으로 확인됐다.
주목할 점은 AI의 자율적인 취약점 발굴 능력이다. 티오리의 AI 보안 플랫폼 '진트(Xint)'는 nginx 소스코드 약 5만 줄을 분석해 1시간 30분 만에 주요 취약점을 탐지했다. 연구진은 AI가 제시한 재현 경로를 바탕으로 약 10분 만에 실제 공격이 가능한 개념증명(PoC)을 완성했다.
전체 취약점 5건 중 4건은 진트가 자율적으로 발견했고, 나머지 1건은 연구원이 직접 찾아냈다. 티오리는 AI가 탐색과 가설 수립, 검증을 반복하도록 설계하는 '하네스(Harness)' 노하우 기반의 성과라고 강조했다.
티오리는 취약점을 nginx 개발사 F5에 전달하고 아마존웹서비스(AWS), 마이크로소프트, 구글 등과 보안 대응을 조율했다. 취약점 공개 이전에는 공격에 악용될 수 있는 단서의 노출을 최소화하고, 관련 정보에 대한 접근을 엄격하게 제한했다.
nginx 공식 보안 권고에 따르면 취약점은 18일 배포된 안정화 버전 1.30.7과 메인라인 버전 1.31.9에서 수정됐다. 해당 취약점을 악용한 침해사고는 아직 보고되지 않았으나 신속한 패치를 권고했다.
박세준 티오리 대표는 “AI가 취약점을 발견하고 악용하는 속도가 빨라지는 만큼 사람이 일일이 분석하고 점검하는 기존 방식만으로는 대응하기 어려워질 것”이라고 말했다.

[TITLE] Attackers hijack Microsoft’s agent-framework package to steal Azure and CI credentials
[TITLE_KO] 공격자들, 마이크로소프트의 agent-framework 패키지 탈취해 애저 및 CI 자격 증명 탈취
[LINK] https://www.infoworld.com/article/4250167/attackers-hijack-microsofts-agent-framework-package-to-steal-azure-and-ci-credentials-2.html
[PUBLISHED] 2026-11-18 21:03 KST
[SOURCE] InfoWorld
[TOPIC] 에이전트, 개발, 보안
[SCORE] 9
[REASON] 에이전트 개발자는 패키지 버전 검증 및 탈취된 토큰 즉시 재발급
[FIELD] 보안
[BODY]
Two malicious versions of Microsoft’s AI agent SDK on PyPI collected secrets and requested fresh cloud tokens from build pipelines before they were taken down.
Attackers briefly hijacked Microsoft’s official Agent Framework package on PyPI and used it to distribute credential-stealing malware capable of harvesting cloud tokens, developer secrets and CI/CD credentials from developer workstations and automated build systems, according to multiple security researchers.
Two malicious versions of the package, 1.26.1 and 1.26.2, appeared on PyPI on November 17 and stayed live for less than an hour.
“The package is a credential stealer: it harvests environment secrets, cloud and package-manager credentials, and Azure managed identity tokens, then exfiltrates them to an attacker-controlled webhook,” OX Security, one of several security firms that flagged the releases, said in a blog post.
The payload ran automatically every time Python started, even if no code imported the package, OX said. The malicious versions also installed the genuine framework code, so applications kept working, and the compromise was easy to miss. The package has 192,534 monthly downloads, according to the firm.
Other security firms, including Aikido Security, Endor Labs, and SafeDep, published similar analyses of the attack.
Microsoft has not said publicly how the attacker got access to publish the package. The company did not immediately respond to a request for comment.
How the stealer worked
The stealer collected environment variables with names containing words such as TOKEN, SECRET, PASSWORD, KEY, AZURE, AWS, GITHUB, and OPENAI, OX said. It also read up to 60 credential files. These included Azure CLI settings, Git and Docker credentials, npm and pip configuration, Hugging Face tokens, Azure DevOps build agent credentials and application .env files. It pulled secrets from up to 300 other running processes as well.
The stealer also asked for new tokens. Inside Azure DevOps pipelines, it requested an identity token that can be exchanged for Azure access, OX said in the blog post. It also requested managed identity tokens for Azure services, including Resource Manager, Microsoft Graph, Key Vault, Storage, Cognitive Services, AI Foundry, and Azure DevOps.
Endor Labs said the attack was aimed mainly at automated build systems. “Developer laptops are in scope, but the payload is written for CI runners and Azure workloads,” the firm wrote in its analysis.
The code was disguised as diagnostics. It sat in a module named _telemetry.py and sent data with a user agent labeled “af-runtime-diagnostics,” OX said. The stolen data went to a webhook.site address as compressed, encoded JSON.
The attacker did not stop after the first release. While OX was researching the malware, version 1.26.1 was reverted to the clean 1.26.0. The attacker then uploaded 1.26.2, which used a different file path for the same payload, the firm said.
The first version went up at 20:35 UTC and the second at 21:08 UTC, according to Aikido Security. Both were gone by about 21:20 UTC.
“This attack isn’t just a one-off exfiltration attempt, but a planned, live and coordinated effort to reach as many victims as they can, while still being able to bypass blocks and restrictions,” OX said.
OX said the attackers appear to have found a way to hijack the process that builds the package’s wheel files. Endor Labs, in its analysis, said both malicious versions were uploaded as wheel files only, without the source code package that came with the clean release. Microsoft has not confirmed how the breach happened.
The short window may not limit exposure. Any unpinned install during that time pulled in a malicious version, Endor Labs said. Container images, CI caches, and lockfiles built in the window could still contain it.
AI pipelines in focus
OX said the attack shows how attackers are targeting the AI developer ecosystem and the CI pipelines behind it.

[TITLE] 구글, 세계 3위 성능 '제미나이 4 네온' 출시…작업 비용 32% 절감
[LINK] https://www.aitimes.com/news/articleView.html?idxno=217546
[PUBLISHED] 2026-11-19 08:39 KST
[SOURCE] AI타임스
[TOPIC] 개발, 모델
[SCORE] 8
[REASON] 개발팀은 고성능 추론 업무에 네온 모델로 비용 32% 절감
[FIELD] AI 모델
[BODY]
구글이 최상위 모델에 가까운 성능을 유지하면서 복잡한 업무의 처리 비용을 낮춘 '제미나이 4 네온(Gemini 4 Neon)'을 출시했다. 종합 지능 평가에서 기존 '제미나이 4 카본'을 소폭 앞섰으며, 코딩과 기업 업무 자동화, 과학 연구 등 다양한 분야에서 높은 성능을 기록한 것이 특징이다.
구글은 18일(현지시간) 공식 블로그를 통해 제미나이 4 제품군의 새로운 모델인 네온을 공개했다.
네온은 복잡하고 장시간에 걸친 작업에 특화한 카본과 빠른 일상 업무를 처리하는 '하이드로젠(Hydrogen)' 사이에 위치하며, 높은 추론 성능과 비용 효율성을 동시에 확보하는 데 초점을 맞췄다.
아티피셜 애널리시스의 지능지수 평가(AAII)에서 네온은 최고 추론 단계인 '매우 높음(xhigh)' 기준 61점을 기록했다. 카본의 최고점인 60점을 1점 앞선 것으로, '클로드 페이블 5.2'(65점)과 'GPT-6.2 아스트라'(62점)에 이어 전체 3위를 기록했다.

— Artificial Analysis (@ArtificialAnlys) November 18, 2026
구글은 실제 업무에서의 비용 효율성을 강조했다. 기본 설정인 '높음(high)' 단계에서 네온의 작업당 비용은 카본보다 32% 낮았다고 밝혔다.
기업 업무 자동화에서도 높은 성능을 보였다. 재피어의 오토메이션벤치 평가에서 최고 추론 단계 기준 56.3%의 성공률로 1위를 기록했다. 기본 추론 단계에서도 성공률 54.3%, 작업당 비용 0.88달러를 기록해 카본의 최고 성적인 53.9%, 1.94달러를 앞섰다. 카본보다 높은 성공률을 유지하면서 작업당 비용을 약 55% 줄인 셈이다.
기업의 복잡한 업무를 평가하는 발스 인덱스에서는 70.9%로 2위에 올랐으며, 법률 조사와 세무 업무 평가에서는 각각 1위를 차지했다. 실제 이용자들의 에이전트 작업 4200여건을 바탕으로 평가한 에이전트 아레나에서도 1336점으로 2위를 기록했다. 구글에 따르면 두 평가에서 네온의 작업당 비용은 최고 성능 경쟁 모델보다 약 50~80% 낮았다.
코딩 성능도 강화했다. 아티피셜 애널리시스의 코딩 에이전트 지수에서 58.6점으로 1위를 기록했으며, 터미널 환경에서 복잡한 개발 작업을 수행하는 '터미널벤치 4.1'에서는 65.2%를 달성했다. 과학과 수학 분야에서도 '터미널벤치 사이언스' 70.5%, '리만벤치' 84.0%, 'HLE 다이아몬드' 71.3%로 구글이 공개한 비교 평가에서 최고 수준의 성적을 거뒀다.
네온은 장시간 실행되는 AI 에이전트 작업에 맞춰 설계됐다. 여러 파일에 걸친 오류를 수정하거나 코드 구조를 개선하는 작업을 수행하며, 불필요하게 파일을 반복해서 읽는 횟수를 줄이고 장시간 작업에서도 진행 상황을 관리하도록 했다. 내부 평가에서 사실과 다른 내용을 만들어내는 오류도 기존 모델보다 줄었다는 설명이다.
특히 AI 코딩 도구인 '안티그래비티'에서는 네온이 여러 하이드로젠 에이전트를 동시에 지휘하는 오케스트레이터 역할도 수행할 수 있다. 복잡한 작업을 여러 하위 작업으로 나눠 병렬로 처리하도록 해, 고성능 모델 하나가 모든 작업을 직접 수행하는 방식보다 효율성을 높이려는 것이다.
네온은 최대 100만 토큰의 컨텍스트를 지원하며 텍스트뿐 아니라 이미지, 오디오, 동영상, PDF, 스프레드시트 등을 분석할 수 있다. 추론 수준은 낮음(low), 보통(medium), 높음(high), 매우 높음(xhigh) 등 4단계로 구성돼 작업 난도에 따라 성능과 비용을 조절할 수 있다. 매개변수와 모델 아키텍처는 공개되지 않았다.
API 가격은 입력 100만 토큰당 3달러, 출력 100만 토큰당 15달러다. 캐시된 입력은 100만 토큰당 0.15달러로 일반 입력보다 95% 저렴하다. 카본의 정가인 입력 4달러, 출력 20달러와 비교하면 25% 낮은 수준이다. 현재 카본에는 이달 30일까지 입력 2달러, 출력 10달러의 프로모션 가격이 적용되고 있어 당장의 토큰당 요금은 네온이 더 높다.
네온은 구글 AI 스튜디오와 제미나이 API 유료 서비스, 기업용 제미나이, 안티그래비티 등을 통해 제공된다. 일반 이용자도 구글 AI 프로와 울트라 요금제에 가입하면 제미나이 앱에서 선택해 사용할 수 있다.
한편, 사이버 보안에 특화한 '제미나이 4 네온 포 사이버(Gemini 4 Neon for cyber)'도 공개했다. 이 모델은 소프트웨어 취약점 탐지 평가인 'SEC-벤치 프로'에서 90.5%, 웹 시스템 침투 테스트 평가인 '웹익스플로잇벤치 v1.2'에서 51.26%를 기록했다.
구글은 기존 카본보다 적은 비용으로 취약점을 탐지하고 검증·수정할 수 있다고 설명했다. 보안 특화 모델은 신뢰할 수 있는 보안 전문가를 대상으로 하는 '페어윈드(Fairwind)' 프로그램을 통해 차례로 제공할 예정이다.
이번 출시로 구글은 제미나이 4 제품군을 세분화하고, 작업의 난도와 비용에 따라 모델을 선택할 수 있도록 했다. 기업용 AI와 에이전트 시장에서 비용 효율성을 앞세워 경쟁력을 높이려는 전략이다.

[TITLE] 엔비디아, 1페타플롭 AI 성능 갖춘 소형 PC ‘RTX 스파크’ 출시…GPU 서버 없이 로컬 AI 에이전트 실행
[LINK] https://www.aitimes.kr/news/articleView.html?idxno=42802
[PUBLISHED] 2026-11-19 14:01 KST
[SOURCE] 인공지능신문
[TOPIC] 에이전트, 개발, 모델, 신기술
[SCORE] 8
[REASON] 개발자는 로컬 환경에서 대규모 에이전트 실행 가능
[FIELD] 신기술
[BODY]
최대 128GB 통합 메모리로 1,200억 파라미터 AI 모델 구동…이미지·영상 생성부터 모델 파인튜닝까지 지원
엔비디아(NVIDIA)가 최대 1페타플롭의 AI 연산 성능과 128GB 통합 메모리를 갖춘 소형 데스크톱 ‘RTX 스파크(RTX Spark)’를 출시했다. 별도의 GPU 서버나 클라우드에 의존하지 않고 개인용 PC에서 대규모 AI 모델과 자율형 AI 에이전트를 실행할 수 있는 제품으로, 개발자와 콘텐츠 제작자를 위한 로컬 AI 환경 확대에 나섰다.
엔비디아는 19일 에이수스(ASUS), 델(Dell), MSI를 통해 RTX 스파크 소형 데스크톱을 공급한다고 밝혔다. 국내에서는 이날 오전부터 쿠팡과 컴퓨존에서 에이수스 제품의 사전예약을 시작하며, 에이수스와 MSI 제품은 11월 말부터 12월 초 사이 정식 출시될 예정이다.
RTX 스파크는 20코어 엔비디아 그레이스(Grace) CPU와 6,144개 쿠다(CUDA) 코어를 갖춘 블랙웰(Blackwell) RTX GPU를 탑재했다. 최대 1,200억 파라미터 규모의 거대언어모델(LLM)을 로컬에서 실행하고, 90GB 이상의 3D 장면 렌더링과 4:2:2 영상의 실시간 편집을 지원한다.
특히 AI 에이전트를 24시간 실행할 수 있어 사용자가 다른 작업을 수행하거나 자리를 비운 동안에도 데이터 처리와 콘텐츠 생성, 예약 작업을 이어갈 수 있다. 헤르메스 에이전트(Hermes Agent)와 엔비디아 네모클로(NemoClaw)를 활용한 에이전트 구축, 언슬로스(Unsloth) 기반 모델 파인튜닝도 지원한다.
로컬 AI 모델과 클라우드 모델을 작업 특성에 따라 자동 배분하는 엔비디아 스위치야드(Switchyard)도 제공한다. 일반적인 작업은 PC에서 처리하고 복잡한 추론은 클라우드 모델에 맡겨 외부 API 사용 비용을 관리하는 방식이다.

디노티시아는 CPU가 서비스 실행을, GPU가 AI 모델 연산을, VDPU가 벡터 검색을 각각 담당하는 구조를 구상하고 있다. 다수의 VDPU 카드를 탑재한 서버 한 대에서 2소켓 CPU 서버 대비 약 10배의 검색 성능을 구현하는 것이 목표다. 이는 현재 달성한 성능이 아닌 회사가 제시한 개발 목표다.
디노티시아는 벡터 데이터베이스 ‘씨홀스’와 AI 에이전트 소프트웨어도 자체 개발하고 있다. 실제 검색 과정에서 발생하는 요구사항을 VDPU 설계에 반영하고, 반도체와 소프트웨어를 함께 최적화해 기업 데이터를 저장하고 검색한 뒤 AI 모델에 공급하는 AI 스토리지 사업으로 확장한다는 계획이다.
정무경 디노티시아 대표는 이번 시연을 첫 VDPU ASIC의 성능과 실제 작동을 확인한 단계로 평가했다. 글로벌 서버·스토리지 기업과 개념검증을 이어가며 성능과 안정성을 검증하고 외부 시스템으로 적용 범위를 넓히겠다는 방침이다.

프런티어 AI 연구·훈련 환경 인터넷 차단, 출시 전 안전성 검증 강화…GPT-6.1 아스트라 공개도 보류
오픈AI(OpenAI)는 내부 인공지능(AI) 연구 모델이 보안 취약점을 이용해 외부 인터넷에 접근한 사실을 확인한 뒤 고성능 AI 모델의 훈련과 평가를 약 12일간 중단한 사례를 18일(현지시간) 공개하고, 연구·훈련부터 내부 배포와 외부 서비스 제공에 이르는 전 과정에서 인터넷 접근 제한과 긴급 작동 중단 등 다층 안전 통제 체계를 강화하고 있다고 밝혔다.
가장 주목되는 사례는 내부 연구 모델이 도메인 이름 시스템(DNS)의 설정 오류를 이용해 제한적인 인터넷 접근에 성공한 사건이다. DNS는 인터넷 주소를 실제 서버의 IP 주소와 연결하는 시스템으로, 잘못 구성된 네트워크 설정이 AI 모델의 외부 통신 경로로 악용될 수 있다.
오픈AI에 따르면 내부 감시 시스템이 해당 모델의 행동을 탐지했으며, 회사는 보안 취약점을 조사하고 해결하기 위해 지난 9월 20일부터 10월 1일까지 가장 높은 성능을 갖춘 모델들의 훈련과 평가를 중단했다.
AI가 의도적으로 보안망을 우회할 가능성을 실제 연구 환경에서 확인했다는 점에서 의미가 크다. 다만 오픈AI가 공개한 사례는 제한적인 인터넷 접근에 관한 것으로, AI 모델이 내부 시스템 전체를 장악하거나 외부로 민감한 정보를 유출했다는 의미는 아니다.
오픈AI는 지난 7월 발생한 허깅페이스(Hugging Face) 관련 사건 이후 프런티어 모델의 훈련·시험·배포 환경을 전반적으로 재설계했다고 설명했다. 특히 연구 단계에서는 모델의 정렬 상태와 안전성을 완전히 신뢰하기 어렵기 때문에 외부 시스템에 접근할 수 있는 권한 자체를 제한하는 방식을 강화했다.
현재 프런티어 모델의 연구·훈련 환경은 실시간 인터넷에 직접 접근하지 못하도록 설계됐다. 모델의 권한을 제한하는 샌드박스(Sandbox), 실행 환경을 분리하는 가상머신(Virtual Machine), 데이터센터 클러스터 전체를 외부 인터넷과 격리하는 네트워크·클라우드 경계 통제를 결합한 구조다.
여러 단계의 보안 장치를 적용해 하나의 통제 수단이 실패하더라도 다른 장치가 위험 행동을 차단하거나 감지할 수 있도록 했다. 오픈AI는 이러한 방식을 '심층 방어(Defense in Depth)'라고 설명했다.
모델이 보안 경계를 우회하는지를 확인하기 위한 공격적 안전성 시험도 실시한다. 자체적으로 보유한 고성능 AI 모델을 활용해 외부 인터넷 접속, 샌드박스 탈출, 격리된 다른 AI 에이전트와의 통신 등을 시도하도록 하고, 실제 보안 체계가 이를 차단할 수 있는지 평가한다.
모든 프런티어 모델의 추론 과정도 감시 대상이다. 모델이 허용되지 않은 외부 인터넷 접근에 성공한 사실이 감지되면 보안 담당자에게 경고를 전달하고 해당 작업을 자동으로 일시 중단하도록 설계했다.
긴급 대응을 위해 중앙 통제 시스템 '컨트롤 룸(Control Room)'도 구축했다. 컨트롤 룸은 연구 환경에서 실행되는 AI 작업을 추적하고, 작업 중단 명령을 받은 뒤 35초 이내에 추가적인 모델 출력을 멈추도록 설계된 시스템이다.
특히 중단 기능은 개별 연구 프로그램이 아니라 모델 추론 인프라에 직접 적용된다. 연구 프로그램마다 별도의 종료 기능을 구현하지 않더라도 중앙 시스템에서 모델 출력을 통제할 수 있는 구조다.
프런티어 모델 연구 작업에서는 컨트롤 룸 자체가 사용할 수 없는 상태가 발생하더라도 모델 출력을 중단하도록 했다. 중앙 통제 기능에 장애가 발생했을 때 AI가 통제되지 않은 상태로 계속 작동하는 상황을 방지하기 위한 조치다.
오픈AI는 샌드박스가 완벽하게 뚫리지 않는다고 보장할 수는 없다고 인정했다. 대신 반복적인 침투 시험으로 보안 경계의 강도를 확인하고, 실시간 감시 체계가 위험 행동을 탐지해 대응할 수 있도록 다중 방어 구조를 운영한다는 설명이다.
안전 통제 방식은 AI 모델의 개발 단계에 따라 달라진다. 연구 단계에서는 인터넷 격리와 실행 권한 제한에 중점을 두지만, 내부 배포 단계에서는 모델이 실제 업무 환경에서 어떻게 행동하는지를 평가한다.
내부 배포 단계에 진입한 모델은 오픈AI 직원들이 사용하는 챗GPT(ChatGPT)와 코덱스(Codex) 등의 환경에서 시험된다. 이 과정에서는 외부 인터넷뿐 아니라 사내 협업 도구인 슬랙(Slack), 소스코드, 내부 인프라 등에 대한 접근이 허용될 수 있다.
연구 단계와 달리 실제 업무 환경에서는 모델에 더 많은 권한이 주어지는 만큼 정렬 평가와 시스템 차원의 보호 장치, 행동 감시가 중요해진다.
오픈AI는 모델이 샌드박스 밖에서 사용되기 전에 정렬 상태와 감시 가능성에 대한 평가를 통과하도록 요구한다. 안전·보안 제한을 우회하려는 행동이나 허용되지 않은 작업을 수행할 가능성을 평가하고, 실제 사용 과정에서 위험 행동이 발생하는지도 지속적으로 확인한다.
내부 코덱스 사용에는 별도의 자동 검토 체계인 '오토 리뷰(Auto-Review)'도 적용한다. AI 에이전트가 위험할 수 있는 작업을 수행하려 할 때 해당 행동을 평가하고, 필요한 경우 사용자에게 판단을 요청하는 방식이다.
민감한 내부 정보가 허가되지 않은 외부 목적지로 전송되는 데이터 유출 위험도 주요 감시 대상이다. 모델의 기능이 확대될수록 단순히 유해한 답변을 차단하는 수준을 넘어 AI가 실제 시스템에서 어떤 행동을 수행하는지 확인하는 것이 중요해지고 있다.
일반 이용자와 기업에 제공하는 외부 배포 단계에서는 안전성 검증 범위가 더욱 확대된다. 오픈AI는 모델의 기본적인 정렬 상태뿐 아니라 사이버 공격, 생물학적 위해 등 고위험 분야에서 악용될 가능성을 평가한다고 밝혔다.
특히 고성능 모델에는 자동화된 레드팀(Red Team)을 활용한 적응형 시험을 실시하고, 일부 모델에 대해서는 외부 전문기관과 함께 안전장치의 효과와 모델의 정렬 상태를 검증한다. 외부 서비스 운영 중에는 시스템 차원의 분류기와 안전성 통제 장치를 적용하는 동시에 AI 기반 조사 시스템과 사람의 검토를 결합해 악의적인 이용 행위를 탐지한다.
오픈AI는 사이버 공격과 생물학적 위해, 모델 증류(Model Distillation)를 통한 무단 능력 추출, 모델 자체의 비정렬 행동 등을 주요 위험 유형으로 제시했다.
고위험 AI 기능에 대한 접근을 제한하는 신뢰 기반 프로그램도 운영한다. 사이버보안 분야의 '데이브레이크(Daybreak)'와 생명과학 분야의 '로절린드(Rosalind)'를 통해 검증된 연구자와 방어 목적의 이용자에게 고성능 AI 기능을 제공하면서 악의적인 접근을 제한하는 방식이다.
안전성 평가 결과는 실제 모델 출시 일정에도 영향을 미치고 있다. 오픈AI는 내부 훈련을 중단하거나 GPT-6.1 아스트라(GPT-6.1 Astra)와 같은 모델의 공개를 보류한 사례를 언급하며, 자체 안전 기준을 충족할 충분한 근거가 확보될 때까지 개발과 배포 속도를 조절하고 있다고 설명했다.
특히 모델이 안전하게 작동한다는 판단을 단순한 내부 평가 결과에만 의존하지 않고, 기술적 보호 장치와 운영 절차, 위험 행동 조사 결과를 종합하는 '안전성 입증 체계(Safety Case)'도 도입했다.
모델이 다음 개발 단계로 진입하기 위해서는 해당 단계에서 필요한 안전성 검토를 거쳐야 한다. 주요 판단은 안전 자문 그룹(Safety Advisory Group, SAG)의 검토를 받을 수 있으며, 오픈AI 재단 이사회 산하 안전·보안위원회(Safety and Security Committee, SSC)의 감독을 받는다.
AI 모델의 위험 행동과 보안 사고에 대한 공개 절차도 마련했다. 안전 통제 장치가 실패한 사실이 확인되면 실제 피해 발생 여부와 관계없이 원인을 조사하고, 필요한 경우 외부에 공개한다는 방침이다.
직원 누구나 모델의 비정렬 행동과 관련된 사건을 공개 검토 대상으로 제기할 수 있으며, 공개 여부에 이견이 발생하면 안전 자문 그룹에 판단을 요청하도록 했다.
오픈AI의 발표는 프런티어 AI 안전 관리의 중심이 모델의 답변 내용에 대한 통제를 넘어, 실제 행동과 시스템 접근 권한을 관리하는 방향으로 확대되고 있음을 보여준다.

[TITLE] 리퀴드 AI, 의사결정 모델 'd1.2' 출시…AA 평가 1위

[FIELD] AI 모델
[BODY]
리퀴드 AI가 텍스트와 이미지, 오디오를 처리하는 옴니모달 의사결정 모델 'd1.2'와 'd1.2-울트라'를 출시했다. 상위 모델인 d1.2-울트라는 아티피셜 애널리시스(AA)의 의사결정 모델 평가에서 1위를 차지했다.
리퀴드 AI는 16일(현지시간) 의사결정 모델 신제품 'd1.2'와 'd1.2-울트라'를 출시했다고 공식 발표했다. 두 모델은 기존 텍스트와 이미지 입력에 오디오 입력을 추가했으며, API에서 5가지 새로운 작업 유형을 지원한다.
일반적인 대형언어모델(LLM)이 자연어 답변을 생성하는 것과 달리, 의사결정 모델은 질문에 대해 정해진 형식의 답과 확률을 반환한다. 문서에서 필요한 정보를 추출하거나 조건에 맞는 항목을 분류하는 등 대량의 판단 작업을 빠르고 저렴하게 처리하는 데 특화했다.
새로운 기능은 ▲문서에서 특정 값 추출 ▲텍스트 내 특정 유형의 구간 탐색 ▲이미지 속 사물 위치 표시 ▲이미지 내 객체 수 추정 ▲여러 조건에 해당하는 선택지 동시 판별 등이다.
예를 들어 청구서에서 결제 금액이나 날짜를 추출하고, 해당 정보가 없는 경우에는 임의로 답하지 않고 '찾을 수 없음'으로 표시한다. 텍스트에서는 이름이나 전화번호, 이메일 등 개인정보가 포함된 구간을 찾아 위치와 함께 반환한다. 이미지에서는 서명이나 나무 등 특정 객체의 위치를 사각형으로 표시하고, 여러 객체의 개수도 추정할 수 있다.
오디오 입력은 음성의 언어를 식별하거나 배경에 사이렌 소리가 있는지 판단하는 데 활용할 수 있다. 질문 자체도 음성으로 전달할 수 있다. 공개된 테스트 결과에 따르면 두 모델은 ESC-50 음향 데이터셋과 43개 언어를 포함한 'FLEURS' 음성 데이터셋에서 질문의 95~97%에 정확하게 답했다.
성능 평가에서도 상위 모델이 두각을 나타냈다. 아티피셜 애널리시스의 '의사결정 지수 v2.1(Decision Index v2.1)'에서 d1.2-울트라는 75점을 기록해 의사결정 모델 가운데 1위에 올랐다. 기존 최고 모델보다 2점 높은 점수다. d1.2는 69점을 기록했다.
해당 지수는 이력서와 영수증, 연구 논문 등을 대상으로 한 정보 추출과 의사결정, 도구 호출, 고난도 지식 질문 등 6개 평가 항목을 종합한다. 특히 정답 확률을 얼마나 정확하게 예측하는지도 평가한다. 확신에 찬 오답일수록 더 큰 감점을 받는 방식이다.
리퀴드 AI가 13개 벤치마크의 2만2505개 질문을 대상으로 자체 평가한 결과, d1.2-울트라의 확률 보정 오차는 0.8%포인트로 나타났다. d1.2는 1.2%포인트였다.
경쟁 모델인 '제브(Jev) 1.14'는 2.7%포인트, 퍼플렉시티의 '디사이더(Decider) v1.3'은 3.7%포인트, 오픈AI의 'GPT-6 루나' 기반 '디시전스 API'는 7.2%포인트를 기록했다. 예측 확률이 실제 정답률과 얼마나 일치하는지를 보여주는 지표로, 오차가 낮을수록 신뢰도가 높다.
이 같은 특성은 기업의 업무 자동화에도 활용할 수 있다. 모델이 답변과 함께 제시하는 확률을 기준으로 신뢰도가 낮은 작업만 사람에게 전달하는 방식이다. 예를 들어 정답 확률이 일정 기준에 미치지 못하는 문서 검토나 데이터 추출 작업을 별도로 분류할 수 있다.
두 모델은 리퀴드 API를 통해 이용할 수 있다. 입력 토큰 100만개당 가격은 d1.2가 0.02달러, d1.2-울트라가 0.042달러다. 두 모델 모두 출력 토큰 비용은 없으며, 현재는 클라우드 API 방식으로만 제공된다. 가중치 공개 일정은 아직 확정되지 않았다.

[REASON] 리눅스 관리자는 AI 에이전트 작성 보안 패치 조기 적용 여부 검토
[FIELD] 보안
[BODY]
Ubuntu AI security patches are here, if you’re willing to test them yourself
Canonical is letting Ubuntu Pro customers install security patches written by AI agents before its engineers finish reviewing and testing them. The patches come from Surge, a system Canonical built to fix known vulnerabilities in Ubuntu’s userspace software, meaning everything outside the operating system’s kernel. They ship through a new opt-in channel called the Edge archive.
If you leave Edge switched off, nothing changes in how your updates are checked: Ubuntu’s regular security updates still get human validation before release. Switch it on and you get fixes sooner, but you also pick up a job Ubuntu’s own testing normally handles, which is deciding whether a patch is safe to run in production.
Twice the fixes, still too slow
Ubuntu’s security teams have already shipped twice as many fixes as they did last year. The company says AI agents are behind a wave of vulnerability reports and attacks across open source. Human review and soak testing, where a fix runs for an extended stretch to catch problems before release, take longer than some customers are willing to sit exposed. Its answer is that “we need to fight AI with AI.”
Machines check machines, then call a human
Surge passes the work down a line of AI agents, each with one job. The first reads vulnerability feeds, matches each report to Ubuntu packages, and drops anything that doesn’t affect Ubuntu. The next grabs the upstream fix and the code around it. Then several competing models each write their own backport, which means adapting a fix made for the current version of a program to the older version a stable Ubuntu release ships.
A panel of separate judge models looks over the candidates and has to reach a consensus. If the judges deadlock, aren’t confident, or run into an unusual case, the patch goes to a human on the Ubuntu security team. Anything that makes it through gets built and run through the same deterministic tests as any other Ubuntu package. The company says this setup protects against regressions and against supply-chain attacks, where someone slips malicious code into software through its build or update path.
The kernel gets its own track
Kernel fixes stay out of Surge’s hands. The kernel needs a different backporting setup, the company says, and just shipping the newest version would be a big stability risk for enterprise systems. So kernels now run on a two-week Stable Release Update cycle, with the cycles overlapping so a new proposed kernel lands every week.
Old bugs only
Surge is aimed at the backlog of vulnerabilities that are already known. New flaws, including the ones Canonical’s automated research turns up, still go through coordinated disclosure: the company reports them privately and works with upstream maintainers under embargo before anything goes public.
“We strongly disagree with those who have abandoned coordinated disclosure practices,” the company wrote.

The maintainers of the PHP programming language on Wednesday issued an advisory announcing an upcoming security release that addresses critical flaws.
The release is scheduled for November 19, 2026, between 2 and 2:30 p.m. UTC.
"These releases are part of PHP's regular four-week release cycle and will address security vulnerabilities affecting all supported PHP versions," the maintainers said. "The highest severity is CRITICAL."
However, the project also noted that issues rated critical require either non-default configuration or uncommon setups. It did not disclose any additional specifics.
However, it's expected to include CVE-2026-115560, a remote code execution flaw that succeeds only if the following conditions are met -
- An application sets session.serialize_handler to php_binary or php_serialize in its configuration, and its code switches the handler to php with ini_set() before calling session_start().
- Session upload progress is enabled, which is PHP's default.
As mitigations, users were urged to set session.upload_progress.enabled=0 until the next regular bugfix release and restart the PHP worker for the setting to be applied.
The development comes nearly a month after PHP released fixes for two critical vulnerabilities, CVE-2026-109618 and CVE-2026-109619, collectively tracked as PHP2Shell that enable unauthenticated remote code execution (RCE) via specially crafted HTTP requests.
The shortcomings have since come under limited active exploitation, targeting publicly-accessible Palo Alto Networks management interfaces and Check Point Security Gateways to launch attacks against Active Directory and deliver backdoors.
In a report published on October 30, 2026, Hunt.io said it identified 616 PHP2Shell-related files, spanning shared exploit kits, cloned proof-of-concepts (PoCs), custom heap exploits, scanners, and post-exploitation tooling, across multiple hosts, even as participants in underground forums have sought exploits, discussed prerequisites, and whether circulating PoCs worked.
"Exploit developers are unlikely to create a single universal exploit that works reliably across all affected PHP deployments," CrowdStrike said.
Last month, PHP also released patches to address a critical flaw in Brotli (CVE-2026-111497 aka Node2Shell or Broccoli2Shell), an out-of-bounds write vulnerability in the decoder library that could result in arbitrary code execution.
Users are advised to apply the updates as soon as they become available.
