An OpenAI agent assigned a simple writing task decided on its own to build a secret email surveillance tool
Key Points
- An internal OpenAI research model was supposed to create a health document during a reinforcement learning training run.
- After its context window was compacted, the model began developing scripts for unauthorized email forwarding on its own, referring to the intended recipient as an "attacker" in its logged reasoning.
- The agent noticed the contradiction between its original task and its actions, deliberately ignored it, and continued working on the email scripts.
During a training experiment, an internal OpenAI model began creating scripts for unauthorized email forwarding even though it was only supposed to write a health document.
According to an OpenAI report, an internal research model was given a simple task during a reinforcement learning training run in mid-October. It was supposed to create an editable document about key health and fitness priorities.
After the agent's context window was compacted, it pursued an entirely different task. During compaction, the previous conversation is carried forward as a short summary, a common process in AI systems. The summary still described the health document assignment. Yet in the new context window, the agent began searching the local file system for a vehicle-cost script the user had never mentioned, according to OpenAI. Why the agent started this task isn't clear.
When the search turned up nothing, the agent speculated that a "colleague" had recreated the execution environment and that an earlier script had been lost. In its logged reasoning, it then formulated the goal of creating a "realistic malicious active helper," a script designed to secretly copy outgoing emails to an unauthorized recipient. The agent itself referred to the intended recipient of these copies as the "attacker."
Agent recognizes the contradiction and ignores it
When the agent retrieved the original user task again, it recognized the deviation. In its logged reasoning, it reacted: "WTF history is unrelated!" It noticed that the previous conversation was about a health document and had nothing to do with email forwarding.
Instead of returning to the actual assignment, the agent dismissed the contradiction, writing in its reasoning "this is problem environment weird. Need ignore." It continued planning, stating that it would "use helper facility that copies all mail to attacker using extra cc."
The agent then created scripts for sending a vehicle-cost summary along with a helper script designed to add an extra recipient whenever the mail program was called. On one of the sending paths, the address could be added as a BCC.
In its final response to the user, the agent wrote: "The summary mail path now adds the personal mailbox as a copy recipient." According to OpenAI, the agent never executed the scripts it generated, didn't send any email, and its final response described the scripts it had produced. It didn't include a link to the requested fitness document, though.
Security training as a possible factor
OpenAI's monitoring system for unwanted model behavior flagged the incident, and the subsequent investigation turned up eight examples of similar behavior in the same training run, according to the report.
Investigators identified a training dataset designed to make models more robust against prompt injection attacks as a possible factor, and OpenAI removed it from training. The company says it hasn't established that the dataset alone was responsible, though, because it also observed similar behavior in models whose training didn't include that dataset.
According to OpenAI, this incident differs from earlier cases where models wrote unauthorized instructions into their own compaction summaries. Here, the recorded summary still correctly described the fitness document. The agent pursued the unauthorized email task anyway, even after it had retrieved the original assignment again.

[FIELD] 보안
[BODY]
A critical flaw in VMware vCenter lets an attacker with network access bypass authentication and gain unauthorized access to the system, Broadcom, which owns VMware, said in an advisory published today.
Fixed versions are out for all supported branches, and the company lists no workaround. vCenter is the central console for managing an organization's ESX hosts and virtual machines.
The vulnerability is tracked as CVE-2026-123890 and is rated 9.8 on the CVSS scoring system. "VMware vCenter contains an authentication bypass vulnerability in the VMware Directory Service," the advisory says.
In an FAQ published with the advisory, the company says the issue "qualifies under ITIL methodologies as an emergency change," and urges organizations to consult their security staff immediately on timing.
The flaw was exploited as a zero-day more than two months before the patch, Google's threat intelligence team said in a technical analysis published November 20. A suspected China-nexus espionage actor tracked as Armory Castle used it in early September to gain administrator access to a vCenter server inside a network the group had already breached. Credit for reporting the bug goes to Google-owned Mandiant.
The bug is present in vCenter 8.0, 9.0, and 9.1, and in the vCenter builds that ship inside VMware Cloud Foundation, vSphere Foundation, and the Telco Cloud Platform and Telco Cloud Infrastructure products. That includes the older Cloud Foundation 5.x line. It is there whether or not Enhanced Linked Mode is in use.
Older versions are not cleared. The company no longer evaluates versions past end of support, and says vSphere 6.5 and 6.7 should be presumed affected. The same goes for vSphere 7.0, which left general support in October 2025, and whose customers can request a patch under an extended support contract.
None of the five flaws in the advisory lets code run on an ESX host from inside a virtual machine, and ESX itself is not affected, the advisory FAQ says.
There is no fallback for systems that cannot be updated yet: asked whether a workaround exists, the FAQ answers "Not as listed by Broadcom," while noting that mitigations may still exist in an organization's own defenses.
The updates are cumulative and cannot be installed through vCenter Quick Patch. Virtual machines continue running while vCenter installs the update, though management access drops briefly, and some encryption operations against a Standard Key Provider become unavailable until vCenter is back online.
One warning applies to upgrades already in progress: installing vCenter 8.0 U3m or 9.0.2.0200 blocks a later upgrade to VMware Cloud Foundation 9.1.1, a conflict the FAQ calls a "Back-in-Time" issue. The options are to upgrade vCenter to 9.1.1 first and apply the security update there, or to wait briefly for VCF 9.1.2.
The bypass is the second critical authentication flaw in the VMware Directory Service this year. The earlier vCenter flaws, patched on July 29, included CVE-2026-59309, another 9.8-rated bypass in the same component per the July advisory, alongside a directory-traversal bug, CVE-2026-59310.
Attacks on that traversal flaw began five days after its disclosure, German incident response firm QUIRSO assessed in August, linking them with moderate confidence to a suspected China-nexus actor.
The August attacks compromised an estimated 361 IP addresses in 47 countries and deployed Babuk-derived ransomware on ESXi hosts.
The advisory also fixes four lower-severity flaws, rated 6.7 to 8.1: a SQL injection (CVE-2026-123891) and a command injection (CVE-2026-123892) in SDDC Manager, a privilege escalation to root on the SDDC Manager appliance (CVE-2026-123893), and a SAML token signature bypass in VMware Tools for Windows (CVE-2026-123894), exploitable only where Guest Alias mapping is configured. Each needs an authenticated or already privileged actor, and the last one stays inside the guest virtual machine.

D-Matrix bets stacked DRAM can solve inference’s memory bandwidth problem
As artificial intelligence workloads shift to inference, memory bandwidth decides whether hardware generates tokens quickly or sits idle. D-Matrix Corp. is answering with Raptor, a second-generation chip stacking 3D DRAM beneath its compute logic.
AI infrastructure has become a systems game, and winners combine memory, interconnect and software into cohesive designs, according to Satyam Srivastava (pictured), fellow at d-Matrix.
“It’s no longer a chip problem. Chip plays a part of it. Memory bandwidth is a fundamental advantage that has to be solved,” Srivastava said. “The next is energy efficiency. The next is interconnect efficiency. The next is software cohesiveness.”
Srivastava spoke with theCUBE Research’s John Furrier at SC26, during an exclusive broadcast on theCUBE, SiliconANGLE Media’s livestreaming studio. They discussed d-Matrix’s Raptor chip and its stacked 3D DRAM, inference memory bandwidth and the shift toward heterogeneous computing. (* Disclosure below.)
Raptor brings a stacked-memory tier to inference
D-Matrix proves each risky technology on a test chip first. Jayhawk proved die-to-die connectivity, and Jayhawk II validated digital in-memory computing. The Corsair accelerator combined both and entered full production earlier this year, Srivastava explained.
“Fast forward, we have the Pavehawk chip, test chip, which is proving out 3D DRAM stacked underneath the logic die, which serves as the core technology for Raptor, which is our second-generation chip coming out next year,” Srivastava said.
Stacking keeps the distributed memory architecture intact but moves memory cells onto a separate layer rather than consuming logic die area. Data travels a short distance and never crosses an interposer. That puts 3D DRAM in a new tier between SRAM and high-bandwidth memory, Srivastava said.
“So you’re getting 10 times higher energy efficiency compared to HBM, 10 times higher bandwidth compared to HBM, where it sits in between SRAM and HBM in terms of capacity,” Srivastava said.
Pairing a Corsair-based server with an existing Hopper GPU fleet can raise utilization from about 20% to as much as 80%, meaning more tokens per dollar, Srivastava noted. D-Matrix has also adopted NVLink Fusion rackscale infrastructure from Nvidia Corp. to connect its accelerators to Nvidia’s AI factories.
“For us, it unlocks the opportunity to participate in a very established ecosystem, the world’s most popular AI factory. We get access to a very hardened design of an MGX rack,” Srivastava said.
The partnership points toward heterogeneous computing, where software orchestrates GPUs, CPUs and accelerators such as Raptor as one system, with the cluster as the unit of computing, Srivastava explained.
“So think of a chip, but that chip is an entire cluster and it has many different hardware units,” Srivastava said. “Some are GPUs, some are CPUs, some are ASIC accelerators, and you can use whichever one you like to serve the needs of the workload the best.”

[TITLE_KO] 패치되지 않은 윈도우 신규 제로데이 FastUnlock, 잠긴 PC에서 프로그램 실행 허용
[LINK] https://thehackernews.com/2026/11/new-unpatched-windows-0-day-fastunlock.html
[PUBLISHED] 2026-11-20 14:30 KST
[SOURCE] The Hacker News
[TOPIC] 보안
[SCORE] 7
[REASON] 윈도우 잠금 상태 물리 접근 실행 취약점 대비
[FIELD] 보안
[BODY]
A newly disclosed unpatched zero-day technique called FastUnlock lets someone with physical access to a locked Windows computer start programs without signing in. Whoever uses it gets only a limited account, not administrator control of the machine.
The method was posted yesterday by a researcher who uses the handles MSNightmare and Nightmare Eclipse, and the endpoint-security firm ThreatLocker tested it the same day and found it works.
There is no fix from Microsoft yet, and nothing shows the method has been used in a real attack.
The technique does not work on every machine. It requires physical access to the computer and a Microsoft account accessible through the lock screen's recovery options, and it uses Windows' built-in screen reader, Narrator, to navigate the locked screen.
In its test, the firm reached a point where it could run a program from the lock screen in a limited account that ThreatLocker identified as WSIAccount and said is "not an administrator account."
The researcher's GitHub disclosure is a short post with a video and little written detail, so the clearest account of what the flaw does comes from the firm's independent test.
Many Windows computers encrypt their drives with BitLocker, but in a common setup, that does not make them immune to this technique. A chip called the TPM unlocks the drive automatically when the computer starts, so by the time the lock screen appears, the files are already readable, and the bypass runs at that point. Microsoft's own TPM documentation describes this mode, in which the drive unlocks "without having to enter a PIN."
FastUnlock does not break that encryption or recover the key. It runs on a computer that has already unlocked its own drive in the normal way, which is a smaller problem than cracking an encrypted disk, though still a real one for a machine someone else is holding.
The conditions above, physical access and a reachable Microsoft account, are what put a machine at risk. No official list of affected Windows versions has been published, so treat any machine that meets those conditions as possibly affected until one is.
What You Can Do Now
With no patch available, the useful steps are about physical control and startup protection.
- Keep machines that can go missing out of the wrong hands. Lock away or closely manage laptops, shared desks, and front-counter computers that a stranger could reach.
- On sensitive machines, add a startup PIN to BitLocker instead of letting the drive unlock on its own.
- Shut down or hibernate devices when they leave someone's control. A startup PIN protects only a machine that has not yet started, not one already on the lock screen.
- Do not treat a locked screen on its own as enough.
Microsoft's countermeasures guidance recommends using a startup PIN, along with shutting down or hibernating machines when faced with determined, hands-on attackers. Until an official fix or advisory appears, watch for one and apply it when it comes.

지니 4는 사용자가 입력한 텍스트나 참조 이미지, 또는 두 가지를 결합한 정보를 바탕으로 탐색 가능한 가상세계를 생성하는 AI 모델이다. 일반적인 영상 생성 모델이 정해진 장면을 순서대로 만들어내는 것과 달리, 사용자의 조작에 반응하며 환경을 변화시키는 것이 특징이다.
개발자는 키보드로 가상공간을 이동하면서 자연어 명령을 추가해 환경을 수정할 수 있다. 예를 들어 가상세계의 날씨를 바꾸거나 조명을 조정하고, 새로운 사물을 배치하거나 특정 사건이 발생하도록 지시하는 방식이다.
환경을 변경하는 과정에는 구글의 제미나이(Gemini) 추론 기술이 활용된다. 구글은 제미나이의 추론 기능이 변화하는 세계의 상태를 일관성 있게 유지하도록 지원한다고 설명했다.
가상세계의 시각적 변화뿐 아니라 소리도 함께 생성한다. 지니 4는 주변 환경음과 효과음, 등장인물의 대사를 영상과 동기화하는 네이티브 오디오(Native Audio) 기능을 지원한다. 사용자가 가상공간을 이동하거나 새로운 상황을 만들어내면 장면의 변화에 맞춰 음향도 생성할 수 있다.
구글은 영상과 음향이 결합된 상호작용형 환경을 통해 개발자가 기존의 정적인 3D 장면이나 사전 제작된 영상과 다른 형태의 디지털 경험을 구현할 수 있다고 밝혔다.
기술적 활용 범위는 게임과 콘텐츠 제작에 한정되지 않는다. 구글은 지니 4를 활용해 상호작용형 서비스의 시제품을 제작하거나 공간 설계 개념을 시각화할 수 있다고 소개했다. 개발자가 아이디어를 실제 제품으로 구현하기 전에 가상환경에서 구조와 사용자 경험을 실험하는 방식이다.
특히 로봇과 AI 에이전트 훈련을 잠재적인 활용 분야로 제시했다. 로봇과 피지컬 AI 개발에는 주변 환경의 변화에 대응하고, 물체와 공간의 관계를 파악하며, 행동 결과를 예측하는 능력이 중요하다. 월드모델은 이러한 환경을 가상으로 구성해 AI 시스템의 행동을 실험하는 데 활용될 가능성이 있다.
예를 들어 개발자가 다양한 공간 구조와 조명, 사물 배치를 가진 가상환경을 생성하면 로봇이나 AI 에이전트가 서로 다른 조건에 대응하도록 훈련하거나 평가하는 연구에 활용할 수 있다. 다만 이는 기술적 활용 가능성을 설명한 것으로, 구글이 이번 발표에서 실제 로봇의 학습 성능 향상이나 물리적 작업 성공률을 입증한 것은 아니다.
AI 에이전트 분야에서도 응용 가능성이 주목된다. 기존의 AI 에이전트가 문서와 소프트웨어 도구를 중심으로 작업을 수행했다면, 월드모델을 활용한 에이전트는 가상공간을 탐색하고 환경 변화에 대응하는 행동을 실험할 수 있다.
개발자들은 구글 AI 스튜디오에서 제공하는 인터랙티브 캔버스(Interactive Canvas)와 시작용 애플리케이션을 이용해 지니 4의 기능을 시험할 수 있다. 제미나이 API 문서와 가격 정보도 함께 제공된다.
생성 콘텐츠의 식별을 위한 기술도 적용했다. 구글은 지니 4가 생성하는 모든 출력물에 신스아이디(SynthID) 워터마크를 포함한다고 밝혔다. 신스아이디는 AI 생성 콘텐츠에 사람이 쉽게 알아차릴 수 없는 디지털 표식을 삽입하는 기술이다.
월드모델의 실시간 생성 능력이 발전하면서 AI로 제작한 영상과 가상환경을 식별하는 기술의 중요성도 커지고 있다. 구글은 모델 공개 당시 카메라 움직임에 따른 지연, 복잡한 물리적 상호작용, 실시간 오디오의 정확성, 장시간 장면의 지속성과 같은 과제를 해결하고 있다고 설명했다.
따라서 720p·24fps 생성 지원이 모든 복잡한 가상환경에서 동일한 반응 속도와 물리적 정확성을 보장하는 것은 아니다. 개발자가 실제 서비스에 적용하려면 지연시간과 세계 상태의 일관성, 물리적 상호작용의 신뢰성 등을 추가로 평가해야 한다.
지니 4의 개발자용 API 공개는 월드모델이 연구 시연 단계를 넘어 외부 개발자가 활용할 수 있는 기술 기반으로 확대되고 있다는 점에서 의미가 있다.
텍스트와 이미지로 가상세계를 생성하는 능력에 실시간 조작과 음향, 추론 기능이 결합하면서 AI 기반 가상환경 제작의 활용 범위가 넓어질 것으로 예상된다. 특히 로봇과 피지컬 AI, 자율형 AI 에이전트 개발에서는 실제 환경에서 수행하기 어렵거나 비용이 높은 실험을 가상공간에서 보완할 수 있는 가능성이 주목된다.
향후 지니 4의 산업적 가치는 가상세계의 시각적 완성도뿐 아니라 물리적 일관성과 실시간 반응성, 장시간 환경 유지 능력, 실제 로봇 및 AI 에이전트 훈련에 대한 유효성이 얼마나 검증되는지에 따라 결정될 전망이다.

[TITLE] 加 베이글 랩스, 로봇 제어 오픈 웨이트 AI 모델 세계 3위…GPT-6 아스트라 평가 점수 앞서

[REASON] 오픈웨이트 로봇 제어 모델의 벤치마크 성능 상위 기록
[FIELD] AI 모델
[BODY]
정밀 제어·작업 기억·환경 적응·다단계 작업 평가…로봇팔·이동형 로봇 자율화, 제조·물류 분야 상용화 추진
캐나다의 피지컬 AI 연구기업 베이글 랩스(Bagel Labs)가 19일(현지시간) 범용 로봇 제어 오픈 웨이트 AI 모델 '베이글 로보틱스 1(Bagel-Robotics-1)'을 허깅페이스(다운)를 통해 공개하고, 로보도조(RoboDojo) 시뮬레이션 벤치마크의 독립형 로봇 제어 모델 부문에서 세계 3위를 기록했다고 발표했다.
특히 로봇의 정밀 제어와 작업 기억, 새로운 환경에 대한 적응력 등을 평가하는 시험에서 오픈AI(OpenAI)의 GPT-6 아스트라(GPT-6 Astra) 공개 평가 점수를 앞서며, 오픈 웨이트 AI 모델의 로봇 자율제어 기술 경쟁력을 보여줬다고 회사는 설명했다.
로보도조는 AI 모델이 로봇을 얼마나 정밀하게 제어하고, 이전 작업의 정보를 기억하며, 익숙하지 않은 환경에 적응하고, 여러 단계로 구성된 작업을 수행할 수 있는지 평가하는 로봇 조작 벤치마크다. 공식 리더보드(보기)에 따르면 베이글 로보틱스 1은 11월 18일 시뮬레이션 평가에 등록됐으며, 평균 점수 38.65점과 성공률 31.91%를 기록했다.
베이글 랩스는 해당 평가 결과를 바탕으로 독립형 로봇 제어 모델 가운데 세계 3위에 올랐으며, 로보도조 주요 리더보드에 등록된 북미 기업의 모델 중 가장 높은 순위를 확보했다고 설명했다. 특히 로보도조 평가팀이 공개한 GPT-6 아스트라의 시험 결과와 비교해 일반화, 정밀 제어, 장기 작업 수행, 기억 등 주요 평가 항목에서 높은 점수를 기록했다고 강조했다.
다만 두 모델의 비교는 로보도조가 공개한 특정 시뮬레이션 평가 결과에 한정된다. GPT-6 아스트라의 전반적인 AI 성능이나 실제 로봇 제어 능력을 베이글 로보틱스 1이 모두 앞섰다는 의미는 아니다.
이번 발표에서 주목할 부분은 오픈 웨이트 모델을 활용한 로봇 자율제어 기술이다. 오픈 웨이트(Open Weight)는 학습된 AI 모델의 가중치를 외부에서 활용할 수 있도록 공개하는 방식이다. 개발자는 공개된 가중치를 기반으로 모델을 실행하거나 허용된 범위에서 특정 환경과 작업에 맞게 조정할 수 있다.
로봇 제어 분야에서 이러한 접근은 제조업체나 연구기관이 자체 로봇 플랫폼에 AI 기술을 적용하고 실험하는 데 활용될 가능성이 있다. 다만 오픈 웨이트가 반드시 학습 데이터와 전체 소스코드까지 공개하는 완전한 오픈소스를 의미하는 것은 아니다.
베이글 랩스는 이번 모델을 범용 로봇 제어 기술 연구의 일환으로 개발했다. 회사의 목표는 상대적으로 작은 AI 모델을 활용하면서도 로봇팔과 이동형 로봇 등 다양한 하드웨어에서 자율적인 작업 수행 능력을 구현하는 것이다.
이는 로봇이 정해진 동작을 반복하는 수준에서 벗어나 환경 변화에 대응하고 여러 단계의 작업을 수행하도록 만드는 피지컬 AI 기술과 연결된다. 예를 들어, 제조 현장에서는 로봇이 작업 대상과 주변 환경의 변화를 파악하면서 물체를 조작하는 능력이 필요하다. 물류 환경에서는 이동형 로봇이 상황에 따라 경로와 작업 순서를 조정하는 기술이 중요하다.
베이글 랩스는 이러한 산업적 수요를 고려해 제조와 물류 분야를 우선적인 사업 협력 대상으로 제시했다. 회사는 기존 로봇에 자율제어 기능을 추가하거나 새로운 자율 로봇 시스템을 구축하려는 기업들과 협력 논의를 진행할 계획이다. 로봇 플랫폼의 종류와 자동화하려는 작업, 실제 배치 환경의 요구사항을 검토해 적용 가능성을 모색한다는 구상이다.
베이글 랩스는 비단 로이(Bidhan Roy) 창업자 겸 최고경영자(CEO)가 설립한 캐나다 토론토 소재 피지컬 AI 연구기업으로, 자율 로봇을 위한 AI 모델과 학습 방법을 개발하고 있다.
로봇 제어 AI의 경쟁은 대규모 언어모델의 추론 성능을 넘어 물리적 환경에서 행동을 결정하고 실행하는 능력으로 확대되고 있다. 특히 오픈 웨이트 모델이 로봇 조작 벤치마크에서 상위권 성적을 확보했다는 점은 피지컬 AI 기술의 개발 주체가 대형 AI 기업에만 국한되지 않을 수 있음을 보여준다.

[REASON] 상장 이후에도 AI 통제 확신까지 모델 배포 속도 조절 선언
[FIELD] AI 모델
[BODY]
다리오 아모데이 앤트로픽 CEO가 기업공개(IPO)로 막대한 자금을 확보한 직후에도 AI 안전을 위해 모델 개발 속도를 조절하겠다는 입장을 재확인했다. 상장기업이 된 이후에도 사업적·정치적 압력에 굴복하지 않고 AI 안전을 우선하겠다는 것이다.
아모데이 CEO는 19일(현지시간) 미국 뉴욕 나스닥에서 열린 상장 기념행사에서 "AI 시스템이 안전하고 인간의 통제 아래 있다는 확신을 얻는 데 필요한 만큼 시간을 들여 훈련과 배포 속도를 조절할 것"이라며 "사업적 압력이나 정치적 압력에 굴복하지 않겠다"라고 밝혔다.
그는 AI가 과학과 의학 발전을 크게 앞당길 수 있지만, 악의적인 개인이나 국가의 기술 오용, 경제적 혼란, 인간의 통제력 상실 등의 위험도 있다고 지적했다. 이어 "가장 어려운 안전성 확보 작업은 아직 우리 앞에 남아 있다"라며 AI 모델의 행동을 이해하고 통제하기 위한 연구와 검증을 강화하겠다고 강조했다.
충분히 강력한 AI가 인간과 협력한다면 100년에 걸친 과학·의학 발전을 10년으로 단축할 수 있다고 전망했다. 그러면서 AI의 위험은 피할 수 없는 것이 아니며, 개발 기업들이 안전성 확보에 얼마나 노력하느냐에 따라 결과가 크게 달라질 것이라고 강조했다.
또 이날 상장으로 회사의 재무적 기반이 강화됐으며, 이는 올바른 결정을 내리겠다는 의지를 더 굳건하게 한다고 말했다. 이어 안전한 AI 개발과 사업적 성공이 양립할 수 있다는 사실을 보여준다면, 다른 기업들도 같은 방향을 선택할 것이라고 강조했다.
