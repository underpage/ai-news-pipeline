- eMudhra 중간 인증서 8개에 연결된 개인 키가 침해됐다는 신고가 Mozilla에 접수됨. 공격자는 이 키로 자신이 통제하지 않는 웹사이트의 위조 HTTPS 인증서를 발급할 수 있음

- Mozilla는 OneCRL로 해당 인증서를 차단했으며, 신고 접수 후 3시간 이내에 표준 설정을 사용하는 모든 Firefox 사용자에게 배포를 완료함
- OneCRL 보호 조치는 업데이트나 재시작 없이 적용됨. 사용자 지정 설정 때문에 이를 받지 못했을 수 있는 소수 사용자를 위해 Firefox와 ESR 업데이트도 출시함
- NSS 신뢰 인증서 목록에서도 해당 중간 인증서에 서명한 루트 인증서를 제거함. OneCRL 업데이트를 받지 않는 다른 애플리케이션도 보호하기 위한 추가 조치임
개인 키 침해 위험과 긴급 차단
- Mozilla는 10월 17일 20:06 UTC, eMudhra 중간 인증서 8개에 연결된 개인 키가 침해됐다는 신고를 접수함
- 침해된 키로 위조 HTTPS 인증서를 발급할 수 있으며, 사용자 연결을 가로챌 수 있는 공격자는 웹사이트 사칭과 트래픽 열람 또는 변조에 이를 이용할 가능성이 있음
- 엔지니어들은 즉시 중앙 인증서 폐기 목록인 OneCRL을 사용해 Firefox에서 해당 인증서를 차단함
  - 사용자가 Firefox를 업데이트하거나 재시작할 필요 없이 보호가 적용됨
  - 같은 날 22:59 UTC, 신고 접수 후 3시간이 지나기 전에 표준 설정을 사용하는 모든 Firefox 사용자 대상 배포를 완료함
Firefox 추가 업데이트와 NSS 신뢰 목록 변경
- 10월 20일, OneCRL 업데이트를 받지 못했을 수 있는 소수 사용자에게도 보호 조치를 전달하기 위해 다음 버전을 출시함
  - 데스크톱 및 Android용 Firefox 158.0.1을 출시함
  - ESR 버전으로는 Firefox ESR 115.43.1과 Firefox ESR 153.5.1을 제공함
  - 사용자 지정 설정이 OneCRL 업데이트 수신을 막았을 가능성이 있는 사용자가 대상임
- NSS 3.131.1에서는 침해된 중간 인증서에 서명한 루트 인증서를 신뢰 인증서 목록에서 제거함
  - Firefox는 이미 OneCRL로 보호되고 있음
  - 추가 변경은 Mozilla의 신뢰 저장소나 그 파생 버전을 사용하지만 OneCRL 업데이트는 받지 않는 다른 애플리케이션을 보호하는 데 도움이 됨
- Mozilla는 온라인 보안과 개인정보 보호를 기본권으로 보고 신속한 사용자 보호 대응을 지속하며, 상황이 허락하는 대로 추가 정보를 공개할 예정임

[BODY]
DeepSeek open-sources DeepInfer, the inference framework behind its production services
Chinese artificial intelligence startup Hangzhou DeepSeek Artificial Intelligence Basic Technology Research Co. Ltd. today open-sourced DeepInfer, the inference framework behind its own production services.
The release takes on the cost of serving large models to the public. DeepSeek calls reaching a massive user base at a reasonable price “the core problem an inference framework has to solve” in a deployment Q&A posted with the code. One cluster now serves 155 trillion tokens a day, according to the same document, and revenue at off-peak pricing works out to $38 per graphics processing unit per hour.
For now DeepInfer supports a single model, DeepSeek-V4.1-Flash, and by default it loads the updated 1017 version DeepSeek released over the weekend. Nvidia Corp.’s SM100 Blackwell GPUs can run the framework, as can Ascend 950 neural processing units from Huawei Technologies Co. Ltd. Hopper and other older Nvidia architectures are not on the list.
Two features that keep outputs identical from run to run work only on Nvidia hardware. All of the published performance benchmarks ran on Nvidia chips too, and the figures are DeepSeek’s own.
Speculative decoding in DeepInfer runs through DSpark, a system in which a draft model proposes five tokens at a time and a confidence head predicts which of them the main model will accept. Verification compute goes only to the likeliest candidates. That trims the number of draft tokens checked per step by about 30%, and DeepSeek estimated a 4% to 7% throughput gain at its production load. A second technique, which the company says nearly halves total prefill computation, runs only the last 128 tokens of each prompt back through the model’s decoder layers.
DeepSeek has not yet released its key-value cache management and load-balancing code, saying the two are tightly coupled to internal infrastructure. A blog post the company published on Zhihu lays out how both work. Splitting prefill and decode across separate machines is also left to operators, with the README noting that most of the engine work for it is already in place. The smallest deployment DeepSeek describes as efficient uses 64 GPUs for prefill and another 64 for decoding.
The same coupling kept DeepSeek from releasing its full engine in April 2025, when it described the software as an early fork of vLLM built around its cluster management tools. Maintaining a large open-source project was also more than “a small research team focused on developing better models” had bandwidth for, the company wrote at the time.
DeepSeek had already released components such as the FlashMLA, DeepGEMM and DeepEP kernel libraries, which DeepInfer now uses. The new README names vLLM as its original foundation.
DeepInfer’s Ascend support follows a Sept. 30 release in which DeepSeek brought the TileLang kernel programming language to Huawei’s chips with the chipmaker’s help. The startup plans to deploy at least 160,000 Ascend 950DT accelerators at a new data center in Inner Mongolia, Bloomberg reported in September.
The framework arrived a day after the U.S. Department of Homeland Security ordered federal civilian agencies to remove DeepSeek products from their systems, including third-party services built on its technology.
DeepInfer is available on GitHub under the Apache 2.0 license, and the companion deepseek-recipe library released with it converts requests into token sequences using the same logic as DeepSeek’s official application programming interface. DeepSeek said inference code for future models will go into the same repository.

[BODY]
- Mistral이 음성 인식과 합성 모델군 Voxtral 3와 음성 에이전트 SDK를 공개. 전화나 웹에서 대화하며 정보를 검색하고, 청구서를 확인하거나 예약을 처리하는 서비스 구축 가능
- 한국어를 포함한 50개 언어의 음성 전사와 화자 구분 지원. 전문 용어와 참고 문맥을 전달하면 별도 미세 조정 없이 인식을 보정하며, 실시간 모델은 35개 이상 언어에서 500ms 미만 지연 제공
- 음성 합성은 35개 이상 언어와 50개 이상 방언을 지원하고, 대화 문맥에 맞춰 감정과 속도, 강조를 조절. 약 30분의 오디오로 특정 화자의 말투와 표현을 재현하는 Pro Voice도 제공
- LiveKit 기반 SDK가 음성 인식, LLM의 추론과 도구 호출, 음성 출력을 겹쳐 실행. Mistral 기준 대화 턴 처리 시간은 1초 미만이며, 사용자가 끼어들면 발화를 중단
- Mistral API와 자체 인프라 배포를 선택 가능. 전사는 분당 0.0035달러부터, 음성 합성은 100만 문자당 13달러이며, 온프레미스나 프라이빗 클라우드 배포는 별도 문의 필요
음성 인식부터 업무 실행까지 연결
- 신뢰할 수 있는 음성 에이전트는 언어, 억양, 화자, 끼어들기를 정확히 인식하고, 문맥 속 의도를 추론하며, 감정과 표현을 담아 말하고, 연결된 시스템에서 여러 단계의 작업을 수행해야 함
- Voxtral 3는 음성 인식 모델, 음성 합성 모델, 에이전트 SDK를 결합해 이 네 가지를 실시간으로 처리하도록 설계됨
- 활용 대상은 컨택센터, 서비스 데스크, 가상 비서, 핸즈프리 코파일럿이며, 자체 도구와 데이터에 연결해 미묘한 의도와 복잡한 요청을 처리할 수 있음
다국어 전사와 문맥 기반 인식 보정

  - Mistral의 비교에서 영어, 프랑스어, 스페인어를 포함한 다국어 전사와 화자 분리에서 최고 수준의 결과를 기록했으며, Whisper, Scribe v2, Gemini 3.5 Transcribe를 앞섬

- Voxtral Realtime Transcribe 3는 에이전트 용도의 실시간 모델로, 35개 이상 언어에서 500ms 미만 지연의 전사를 제공함

NIST, the NSA, and CISA recognize the increasing potential for AI agents to behave in an unexpected and potentially harmful manner, and has responded with a list of key practices for both preparing for and responding to such behavior. The report (Key Practices for Incident Readiness and Response in Super Intelligence Training and Evaluation) uses the term super intelligence (SI) rather than artificial intelligence (AI) in line with presidential executive order 14434.
In the report, the ten key practices are grouped into five stages: prepare, detect, respond, recover, and report. For clarity, the report also includes three useful terminology definitions covering AI agents, AI control incident, and AI control near-miss.

The last, Share Information Publicly, is mainstream good behavior throughout cybersecurity that will benefit everyone: “Share details with the public, where appropriate, as early as feasible,” and “Identify and publicly report key practices, takeaways, or improvements adopted in response to the incident or that could benefit other actors in the ecosystem.”

Targets included RubyGems, Hugging Face, and the Australian government's Medicare statistics portal. Agents also tried to break into the US Department of Education. In none of these cases had they been told to attack.
AI systems have been seen knowingly attacking systems that weren't even their targets, says David Krueger, a machine learning professor at the University of Montreal. Given these known failure patterns, ordering autonomous systems to "neutralize" threats is "incredibly dangerous," he says.
Hyrum Anderson, CEO of AI security firm Abundant, also warns about damage on the way to the target. An agent could hit a US water utility, for example, if an adversary has set up its command infrastructure there. Organizations below a "security poverty line," from dental offices to critical infrastructure, face the most risk, he says. Under pressure, agents often treat guardrails as obstacles, and once the order is "destroy," the blast radius could grow dramatically.
William Marcellino of the RAND Corporation points to the systems' lack of judgment. People trust a 19-year-old Marine with live ammunition because he knows enough about the world to recognize what he shouldn't do, he says. Today's publicly available AI doesn't have that ability.

OpenAI acquires Orchestra Bio to bring AI agents into drug development
OpenAI Group PBC revealed today that it has acquired drug development software startup Orchestra Bio Inc.
Orchestra builds artificial intelligence agents that help pharmaceutical teams keep development programs on track,. Its staff and technology will now sit inside OpenAI’s Rosalind life sciences unit.
Much of OpenAI’s case for the deal comes down to how long drugs take to reach patients. Getting a new medicine through to U.S. regulatory approval takes 10 to 15 years on average by the company’s count, and programs pass between departments and outside partners whose systems often do not connect.
Orchestra’s agents take over the monitoring of studies, and TechCrunch’s write-up of the deal credits them with keeping track of finances and sorting out clinical trial scheduling problems as well. In OpenAI’s telling, a failed manufacturing batch that threatens to push a trial back would set the software to work out which activities and timelines are hit and weigh ways to respond. People still make the final call.
Scientists should be able to use the combined tools to make discoveries and “manage the work needed to turn them into treatments,” OpenAI said. Terms were not disclosed, and OpenAI gave no timeline for when Orchestra’s agents will show up in its products.
The Rosalind business that Orchestra is joining dates to April, when GPT-Rosalind launched as a reasoning model for biology and drug discovery research. Eligible organizations have been able to use it outside research preview since September under a trusted-access program. Rosalind Workbench connects the model to scientific tools and data.
Novo Nordisk A/S and Moderna Inc. are among the drugmakers already working with OpenAI on Rosalind. The Danish company wants faster research and commercial execution out of that partnership, OpenAI said, and Moderna’s scientists use the models to turn complex data into plans for experiments.
The deal is not OpenAI’s first in health care this year. Medical records company Torch Health Inc. joined OpenAI in January to build out ChatGPT Health. About $400 million changed hands in April when rival Anthropic PBC bought AI biotech startup Coefficient Bio.
Orchestra Bio is a venture capital-backed startup that Chief Executive Ashoka Rajendra founded in San Francisco in 2022. At the company’s August 2025 launch, Rajendra pitched Orchestra to biotech founders as software that came with guidance on financial management and long-term planning. Backing at that point came to $20 million, from investors including Andreessen Horowitz, 8VC and Insight Venture Management.

[TITLE] AI 추론 비용 최대 10분의 1로…오픈소스 ‘llm-d 1.0’ 공개, 기업용 AI 대규모 운영 본격화

[REASON] 추론 비용을 낮추는 기업용 오픈소스 분산 추론 엔진 1.0 출시
[BODY]
IBM·레드햇·구글 클라우드·엔비디아 등이 참여한 분산 추론 프로젝트…동시 3,000개 코딩 에이전트 처리, 분당 660만 토큰 출력
에이전트 인공지능(AI)이 기업 현장으로 확산하면서 대형언어모델(LLM)을 얼마나 효율적으로 운영하느냐가 AI 경쟁력의 새로운 변수로 떠오르고 있다. 모델의 성능을 높이는 것만큼 추론 비용을 줄이고, 수많은 AI 에이전트의 요청을 안정적으로 처리하며, 서비스 중단 없이 인프라를 운영하는 기술이 중요해진 것이다.
이러한 과제를 해결하기 위한 오픈소스 분산 추론 프로젝트 ‘엘엘엠디(llm-d)’ 기업용 운영 환경을 겨냥한 1.0 버전이 20일(현지시간) 공개됐다. 최근 실증에서는 에이전트 기반 작업의 토큰당 추론 비용을 상용 API 대비 최대 5~10분의 1 수준으로 낮추고, 동시에 최대 3,000개의 코딩 에이전트를 처리하는 성능을 보였다.
llm-d 1.0은 LLM 추론을 여러 컴퓨팅 자원에 분산해 처리하고, 기업이 기존 인프라를 활용하면서 AI 서비스의 처리량과 비용 효율성을 높일 수 있도록 설계됐다. llm-d는 2025년 레드햇(Red Hat), IBM, 구글 클라우드(Google Cloud), 코어위브(CoreWeave), 엔비디아(NVIDIA)가 공동으로 출범시킨 오픈소스 프로젝트다. 현재는 클라우드 네이티브 컴퓨팅 재단(CNCF)의 관리 체계 아래 운영되며, 25개가 넘는 조직에서 500명 이상의 기여자가 참여하고 있다.
AI 에이전트 시대, 모델보다 비싼 ‘추론 인프라’가 문제
기존 AI 서비스에서는 사용자의 질문을 받아 답변을 생성하는 과정이 핵심이었다. 그러나 AI 에이전트는 상황이 다르다. 여러 단계의 작업을 수행하고, 이전 대화와 문서에서 얻은 정보를 반복적으로 참조하며, 여러 에이전트가 동시에 작업을 진행하기도 한다.
이 과정에서 모델이 실제 답변을 생성하는 연산뿐 아니라 이전 요청에서 사용한 문맥을 저장하고 재활용하는 데 상당한 컴퓨팅 자원이 투입된다. 요청이 특정 시점에 집중되면 지연 시간이 늘어나고, 서로 다른 서비스와 에이전트가 동일한 GPU 자원을 놓고 경쟁하면서 비용과 성능을 동시에 관리하기도 어려워진다.
llm-d 1.0은 이러한 문제를 해결하기 위해 분산 추론 환경의 요청 배분, 캐시 관리, 연산 자원 활용, 서비스 가용성을 통합적으로 다룬다. 단순히 모델을 실행하는 소프트웨어를 넘어, 여러 모델과 하드웨어가 함께 작동하는 실제 운영 환경에서 추론 효율을 높이는 인프라 계층을 지향한다.
핵심 기술에는 접두부 캐시를 고려한 요청 라우팅, 부하 인식형 라우팅, 키·값(KV) 캐시 오프로드, 프리필과 디코드의 분리 처리, 전문가 병렬화, 배치 및 비동기 추론 등이 포함된다. vLLM과 SGLang 등 여러 추론 서버를 지원하며, 서로 다른 하드웨어를 혼합한 환경에서도 활용할 수 있도록 설계됐다.
특히 접두부 캐시 활용은 여러 요청이 공통으로 사용하는 문맥을 재계산하지 않고 재사용하도록 돕는다. 프리필과 디코드를 분리하면 입력 문맥을 처리하는 작업과 실제 토큰을 생성하는 작업에 각각 적합한 자원을 배치할 수 있다. 이를 통해 복잡한 에이전트 작업에서 반복 연산을 줄이고, GPU 활용률과 처리량을 높일 수 있다는 설명이다.
서비스 중단 없는 운영과 에이전트 전용 스케줄링 강화
llm-d 1.0(다운)의 주요 변화는 성능 최적화 기술을 실제 기업 운영에 필요한 기능으로 통합했다는 점이다. 첫째, 다중 테넌트 서비스의 품질 관리 기능을 강화했다. 여러 기업이나 서비스가 같은 추론 인프라를 공유하더라도 우선순위와 공정성을 고려해 요청을 제어한다. 응답 속도가 중요한 사용자 요청이 급격하게 늘어나는 에이전트 작업에 밀려 처리 지연을 겪는 상황을 줄이는 데 목적이 있다.
둘째, 서비스 중단을 최소화하는 운영 기능을 도입했다. 라우터의 고가용성 구성과 대기 시스템, 순차 업데이트를 지원해 계획된 유지보수나 업그레이드 과정에서도 요청 처리가 이어지도록 했다. 프리필·디코드 분리 환경에서는 두 작업을 담당하는 복제 인스턴스를 하나의 논리적 단위로 관리해 배포와 업데이트를 조정할 수 있다.
셋째, 안정적인 설정 API와 강화된 요청 처리 경로를 제공한다. 클라우드와 가속기 환경에서 검증된 구성을 기반으로 기업이 운영 표준을 마련하고 시스템을 확장할 수 있도록 지원한다.
넷째, 에이전트의 작업 특성을 반영한 추론 처리 기능을 강화했다. 세션을 인식하는 라우팅으로 다중 대화에서 기존 캐시를 재사용하기 쉬운 위치에 요청을 배분하고, 대화 단계별 우선순위를 고려해 스케줄링한다. 응답 API의 상태 관리 기능도 지원해 에이전트가 이전 대화의 문맥을 활용하면서 불필요한 재계산을 줄일 수 있도록 했다. 이러한 기능은 짧은 응답 시간이 필요한 대화형 서비스와 수많은 작업을 병렬로 수행하는 자율형 에이전트를 하나의 인프라에서 운영해야 하는 기업에 의미가 있다.
IBM 연구진, 양자 오류 정정 설계에서 추론 비용 11.5배 절감
IBM은 llm-d를 활용한 연구에서 오픈 웨이트 모델과 분산 추론 인프라를 결합해 비용 효율을 개선한 사례도 소개했다. IBM 리서치(IBM Research)는 양자 오류 정정 하드웨어를 탐색하는 연구에서 llm-d와 오픈 프런티어 모델을 활용했다. 그 결과, 모든 구성 요소를 독점형 솔루션으로 구축한 방식과 비교해 추론 비용을 11.5배 낮췄다고 밝혔다.
연구진이 보고한 접두부 캐시 적중률은 약 98%였으며, 토큰 100만 개당 혼합 추론 비용은 약 0.11달러였다. 반복적으로 활용되는 문맥을 높은 비율로 재사용하면서 추론 비용을 줄인 사례다.
이는 오픈소스 모델의 활용과 추론 인프라 최적화가 결합할 경우, 특정 연구·개발 작업에서 독점형 모델과 서비스에 대한 의존도를 낮추면서도 대규모 연산을 수행할 수 있음을 보여준다. 다만 해당 비용 수치는 IBM이 소개한 특정 연구 환경의 결과로, 모든 모델과 기업 워크로드에 동일하게 적용되는 것은 아니다.
7530억 매개변수 모델로 동시 3,000개 코딩 에이전트 처리
더 주목할 만한 결과는 대규모 전문가 혼합(MoE) 모델을 활용한 에이전트 작업 실증에서 나왔다. IBM 연구진은 약 7,530억 개 매개변수를 갖춘 오픈 웨이트 모델 ‘GLM 5.2’를 널리 사용되는 엔비디아 GPU에서 llm-d로 배포했다. 별도의 전용 추론 인프라만을 전제로 하지 않고, 기업이 이미 보유한 GPU 자원을 활용해 대규모 모델을 운영할 수 있는지를 시험한 것이다.
수백 개의 에이전트 세션이 병렬로 실행되는 벤치마크 환경에서 시스템은 분당 최대 660만 개 이상의 출력 토큰을 처리했다. 동시에 최대 3,000개의 코딩 에이전트를 선점 중단 없이 운영했다. 여기서 선점 중단은 실행 중인 작업이 다른 요청에 의해 강제로 중단되는 상황을 뜻한다.
비용 측면에서도 차이가 나타났다. 연구진은 현재의 클라우드 GPU 대여 요금을 기준으로 계산할 경우, 해당 배포 환경의 토큰당 비용이 이에 상응하는 상용 API 가격보다 5~10배 낮아질 수 있다고 분석했다. 특히 에이전트 작업처럼 입력 문맥의 양이 많고 기존 정보를 반복적으로 참조하는 워크로드에서 절감 효과가 컸다.
다만 이는 특정 모델과 벤치마크, 클라우드 임대 요금 및 비교 대상 API 가격을 기준으로 산출한 결과다. 실제 기업의 비용은 하드웨어 구성, 모델 크기, 입력·출력 토큰 비율, 사용률, 운영 인력과 전력 비용 등에 따라 달라질 수 있다.
구글 클라우드·AMD·엔비디아 등으로 확산하는 생태계
llm-d는 특정 클라우드나 GPU에 종속되지 않는 개방형 추론 인프라를 지향한다. 구글 클라우드는 llm-d 1.0을 구글 쿠버네티스 엔진(GKE)에 통합하고, 자체 TPU와 엔비디아 GPU 제품군에서 활용할 수 있도록 지원할 계획이라고 밝혔다.
엔비디아는 차세대 가속 컴퓨팅 플랫폼인 베라 루빈(Vera Rubin)으로 llm-d 지원을 확대하는 방향을 제시했다. AMD 역시 인스팅트(Instinct) GPU를 기반으로 개방형 고성능 분산 추론을 발전시키겠다고 밝혔다.
서비스 기업의 도입 사례도 이어지고 있다.

KAI가 우주 궤도에서 위성에 탑재된 인공지능(AI)으로 고장 원인을 분석하고 대응책을 만드는 기술을 검증했다.
한국항공우주산업(KAI)은 지난 20일 큐브위성 BEE-1012를 활용해 AI 기반 자율운영 기술의 시범 임무를 수행했다고 21일 밝혔다. 이 위성은 이달 7일 누리호 5차 발사 때 우주로 올라갔으며, KAI가 자체 개발한 AI 모듈을 탑재했다.
실증은 지상국에서 가상 고장 신호를 보내는 방식으로 진행됐다. 위성의 AI 모듈은 신호를 받아 고장 원인과 범위를 분석한 뒤 대응책을 담은 기술 보고서를 작성해 지상국으로 전송했다.
검증 대상은 데이터를 지상으로 보내 분석하는 대신 위성 내부에서 처리하는 'AI 온보드 프로세싱' 기술이다. 이번 시범 임무에서는 실제 고장을 복구하는 단계가 아니라, 가상 고장에 대한 분석과 대응책 생성·전송 기능을 확인했다.
KAI는 이 기술이 위성의 이상 상황에 대응하는 시간을 줄이고 지상국과 주고받는 통신 부담을 낮추는 데 도움이 될 것으로 기대하고 있다. 향후 지상 개입을 줄인 자율운영 위성을 구현하기 위한 기반으로 활용할 계획이다.
AI 모듈 개발에는 항공기 분야에서 쌓은 고장·수명 예측과 예지정비 기술을 활용했다. 예지정비는 장비 상태를 분석해 고장 가능성과 정비 시점을 미리 파악하는 기술이다. KAI는 이를 위성에 접목하고 수만 가지 고장 시나리오를 학습시켰다고 설명했다.
국내 기업들도 개발에 참여했다. 국방 AI 기업 펀진과 우주 환경에 맞는 AI 솔루션을 구현했으며, 모빌린트가 개발한 AI 연산용 반도체인 신경망처리장치(NPU)를 적용했다.
