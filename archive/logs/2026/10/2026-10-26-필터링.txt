[TITLE] AI coding agents hijacked using AGENTS.md file in Downloads folder
[TITLE_KO] 다운로드 폴더의 AGENTS.md 파일로 AI 코딩 에이전트 탈취
[LINK] https://www.bleepingcomputer.com/news/security/ai-coding-agents-hijacked-using-agentsmd-file-in-downloads-folder/
[PUBLISHED] 2026-10-26 00:49 KST
[SOURCE] BleepingComputer
[TOPIC] 에이전트, 개발
[SCORE] 8
[REASON] 코딩 에이전트가 읽는 지시 파일 범위 통제 필요
[FIELD] 보안
[BODY]
Researchers found a malicious AGENTS markdown instruction file in a customer’s Downloads folder that tricked an AI coding agent into installing a rogue npm package.
They reproduced the attack against OpenAI Codex and demonstrated a related technique against Claude Code to leak OAuth tokens and hijack the account using only the malicious instructions.
Markdown files such as AGENTS.md are plain-text files that contain project-specific instructions for AI coding agents, such as the tools to use, how to run tests, and the coding conventions to follow.
Agents following malicious instructions
Researchers at Forever Security, a company that monitors for risks introduced by AI agents and autonomous software, discovered the tactic on a customer’s computer, where a coding agent attempted to install the malicious npm package ‘function-color.’
The investigation traced the AI agent’s attempt to install a malicious npm package to an AGENTS.md file in the customer’s ~/Downloads folder, which also served as the agent’s working directory.
Agents automatically load applicable files from their working directory and use the contained instructions to guide their actions.
While these files aren’t executables, malicious instructions contained in them can lead to AI agents running commands, installing packages, or changing settings using the tools and permissions available to it.
"There is nothing here for OpenAI or Anthropic to patch. An agent that follows the AGENTS.md in its folder is doing exactly what it was built to do," the researchers say.
The researchers' test confirmed that an attacker could use such a file to manipulate OpenAI Codex and Claude Code into executing code or stealing credentials.
Although the researchers could not determine how the malicious instructions file landed into the target's ~/Downloads location, they explained to BleepingComputer that simply visiting a malicious page could drop a payload without any user interaction.
In a report this week, Forever Security says that "~/Downloads is special. It is the one folder the web can write to on its own," and that "a web page can download a file named AGENTS.md into your Downloads folder, silently."
The researchers created a proof-of-concept (PoC) to demonstrate how the attack could land a malicious file into the ~/Downloads location without the user noticing.
When BleepingComputer verified the PoC page, it downloaded an AGENTS.md file containing harmless content, namely the strings "sensitive data here" and "line 2."
By default, many popular browsers, including Chrome, Edge, and Firefox, save files downloaded from the web to the user's ~/Downloads directory without prompting them to choose a save location for each download.
BleepingComputer’s tests in other browsers, such as Brave, prompted the user to approve the download, which should be enough to alert the user that a file was downloaded.
However, Chrome, Edge, and Firefox display download notifications by default, alerting users when a file has been saved locally.
After dropping the file into Downloads, the attack would require the target to launch their AI agent in that same directory so it could load the instruction file and digest its malicious instructions.
Forever researcher Gal Weizman told BleepingComputer that this is common practice, as people often use AI agents to organize that folder or to act on a newly downloaded file.
Weizman says that internal statistics show that hundreds of customers run AI agents, including Claude Code, OpenAI Codex, and Cursor CLI, from their ~/Downloads folders. Claude Code alone launched more than 1,300 sessions from that location, the researcher told BleepingComputer.
Tests show attack feasible
The researchers tested their reconstructed attack chain against Codex using a harmless payload that simply opened the calculator app, recording a 90% success rate.
In a separate test, they used a malicious CLAUDE.md file to redirect Claude Code’s API traffic to a server they controlled.

  - macOS와 Windows에는 가상화 환경을, 가속기가 필요한 작업에는 사용자 공간 샌드박싱을 적용한 GPU 컨테이너를 사용함

  - 서비스 개발 및 운영팀과 협력해 예상 밖 동작과 여러 인프라 계층에 걸친 약점을 조사함

다른 제품도 사용 조건에 따라 점검이 필요하다. 엔보이와 이스티오(Istio)는 브로틀리 압축 해제 기능이 활성화된 환경에서 영향을 받을 수 있다. 파이썬에서는 ‘Brotli’나 ‘brotlicffi’ 패키지가 설치돼 있으면 일부 HTTP 통신 라이브러리가 이를 이용해 압축 응답을 자동으로 해제한다. 개발자가 직접 압축 해제 코드를 작성하지 않았더라도 취약한 처리 경로가 생길 수 있다는 의미다.

운영자는 외부 압축 데이터를 처리하는 서비스를 우선 확인하고, 실제 배포된 실행 환경과 컨테이너까지 수정 여부를 점검해야 한다. 업데이트 후에는 서비스를 재시작하고, 취약한 구성요소가 포함된 컨테이너 이미지는 다시 빌드해 배포해야 한다.
즉시 업데이트하기 어렵다면 압축 해제 전에 브로틀리 요청을 차단하거나 외부 응답의 자동 압축 해제를 중단하는 임시 조치를 검토할 수 있다. 다만 압축 요청 헤더에서 브로틀리를 제외하는 것만으로는 충분하지 않다. 상대 서버가 브로틀리 응답을 보낼 수 있기 때문이다. 웹방화벽 역시 서비스가 외부에서 받아 처리하는 응답까지 보호한다고 단정할 수 없어, 최종적으로는 취약한 실행 환경과 라이브러리를 수정해야 한다.

TorchTPU replaces PyTorch/XLA, a lazy-tensor bridge from 2020 that, according to the announcement, "required intrusive source-code modifications." The new backend aims to make porting a model as simple as changing model.to("cuda") to model.to("tpu"). Collier described the community's goal as open source software for models that "run on any chip in any cloud and connect to any agent." The Foundation's keynote slides showed how fast that market moves: DeepSeek's Flash model became 60% cheaper in 37 days, and Kimi K3 ran 68% faster on the same hardware in 33 days.
Mazin Gilbert, executive director of the Agentic AI Foundation, said agent token consumption passed human consumption on February 6, 2026. It has since grown 14-fold, against 2.8-fold for humans. "So this is basically a hockey stick that's exploding," said Gilbert. Practitioners should check the scope before reusing those numbers, because the public data comes from a single platform, OpenRouter.
Because TorchTPU plugs into PyTorch's low-level dispatcher, the speakers said, Hugging Face models worked with it out of the box. The vLLM and SGLang inference engines run natively, and TorchTitan supports dense, mixture-of-experts, and diffusion models for training at scale. Ray and llm-d scale TPU workloads across hosts on Kubernetes. Four repositories were open sourced: TorchTPU, vLLM-TorchTPU, SGLang-TorchTPU, and TorchTitan.
Jia showed near-linear scaling past 8,000 TPU chips, with per-chip throughput holding roughly constant as the cluster grew. Google's published results include a Qwen3 235B mixture-of-experts run on 8,192 TPU v7x chips at 28% model FLOPs utilization. The announcement is candid that the one-line change is only a starting point:
One cannot achieve peak TPU performance with that simple change, since a model's shapes, sharding and ops may be skewed toward a GPU architecture; however, the model should run out of the box.
Google's answer to that tuning gap is more agents. Jia closed by announcing the TPU agent suite, now in preview on GitHub, which plugs into coding harnesses to automate onboarding, diagnostics, and performance tuning.
Zhou said Meta's PyTorch team co-developed TorchTPU with Google "to make TPU a first-class native PyTorch target," citing production needs for performance, reliability, and maintainability. "All of this is open source and available today and it is just a beginning," Zhou said. Jana van Greunen, director of PyTorch engineering at Meta, gave the motivation in Google Cloud's announcement:
At Meta, advancing the frontier of AI requires immense compute scale and deep hardware diversity. We cannot be constrained by a single hardware architecture.
Google was not alone. AWS put TorchNeuron, a native PyTorch backend for its Trainium chips, into public beta on October 20, with .to('neuron') as the only code change. Both backends register through PrivateUse1, PyTorch's extension point for custom hardware. TorchNeuron's first release has gaps: The Next Web reported that it does not yet support dynamic input shapes and skips about 22,000 PyTorch tests.

인공지능(AI)이 사람을 대신해 전화를 걸고, 상대방과 대화하며, 업무 처리 결과까지 보고하는 시대가 열리고 있다. AI 에이전트가 단순한 질문 응답이나 문서 작성에서 벗어나 실제 전화망을 통해 사람과 소통하고 업무를 수행하는 방향으로 진화하고 있다.

머스크는 “그록 봇(Grok Bot)은 이제 여러분을 대신해 사람이나 기업에 전화하고, 요청사항을 전달하며, 상대방의 답변을 기록한 뒤 통화 내용을 요약한 메모를 보내줄 수 있다”고 밝혔다.
이번 발표의 핵심은 AI가 사용자의 요청을 이해하는 데 그치지 않고, 실제 전화 통화를 통해 외부 상대방과 소통한 뒤 그 결과를 사용자에게 전달한다는 점이다. 사용자가 일일이 전화를 걸고 통화 내용을 정리해야 했던 과정을 AI 에이전트에 위임할 수 있도록 하는 것이다.
전화 걸고 대화한 뒤 결과까지 보고, AI 에이전트의 역할 확대
머스크가 공개한 기능은 전화 연결부터 업무 요청, 상대방 응답 기록, 통화 결과 요약까지 하나의 작업 흐름으로 수행하도록 설계됐다. 예를 들어 사용자가 특정 업체에 연락해 예약 가능 여부를 확인하도록 요청하면, AI가 해당 업체에 전화를 걸어 문의 내용을 전달하고 상대방의 답변을 기록한 뒤 결과를 요약해 사용자에게 알려주는 방식이다.
상품 재고 확인이나 서비스 이용 문의, 일정 확인 등에도 같은 방식이 활용될 수 있다. 이는 공개된 기능을 바탕으로 예상할 수 있는 활용 사례이며, 각각의 업무에 대한 실제 수행 성공률이 검증됐다는 의미는 아니다.
그록 봇 0.77 시험판을 분석한 외부 개발자들의 설명에 따르면, 전화 연결 이후 대기하거나 자동응답시스템의 안내에 따라 숫자를 입력하고 담당자와 연결되는 기능도 시험되고 있는 것으로 알려졌다. 실시간 통화 내용을 표시하는 기능 역시 거론됐다.
이러한 세부 기능은 머스크가 직접 발표한 공식 기능 범위와 구분할 필요가 있다. 시험판에서 확인된 기능이 모두 정식 서비스에 적용되는지, 실제 전화 환경에서 어느 수준까지 안정적으로 작동하는지는 추가 확인이 필요하다.
AI가 전화를 걸어 상대방의 답변을 수집하는 것과 복잡한 협상이나 예약 변경, 계약 등 후속 업무까지 독립적으로 완료하는 것은 기술적으로 다른 과제다. 이번 발표에서 확인되는 핵심 기능은 전화 기반 요청 전달과 응답 기록, 결과 요약이다.
예약 확인·고객센터 문의까지...전화 업무 자동화 가능성
AI 에이전트의 전화 업무 수행 기능은 개인의 일상생활뿐 아니라 기업의 고객 응대와 업무 운영 방식에도 변화를 가져올 수 있다.
기존 음성 AI 서비스가 주로 사용자의 질문에 답하거나 걸려 온 전화를 응대하는 데 집중했다면, 이번에 머스크가 소개한 기능은 AI가 먼저 외부에 전화를 걸어 사용자가 지시한 업무를 수행한다는 점에서 차이가 있다.
특히 고객센터에 전화를 걸어 상담원 연결을 기다리거나, 여러 업체에 반복적으로 연락해 정보를 확인하는 작업에 활용할 수 있다. 기업 입장에서는 거래처 문의, 일정 확인, 단순 정보 수집 등 반복적인 전화 업무를 자동화하는 데 적용할 여지가 있다.
이는 AI 에이전트의 활용 범위가 디지털 정보 처리에서 현실 세계의 커뮤니케이션으로 확장되고 있음을 보여준다. 전화는 상대방의 실시간 응답과 상황에 따라 대화 흐름이 달라지는 만큼, AI가 실제 업무를 수행하는 능력을 평가하는 중요한 환경이 될 수 있다.
통화 녹음·개인정보 보호·상대방 동의 등 해결 과제
전화 업무를 AI에 위임하는 과정에서는 기술적 완성도와 함께 개인정보 보호, 통화 상대방의 동의, AI의 신원 고지 등 해결해야 할 문제도 적지 않다.
AI가 통화 내용을 기록하고 요약하려면 상대방의 음성이나 개인정보가 처리될 수 있다. 국가와 지역에 따라 통화 녹음 및 개인정보 처리에 관한 법적 요건이 다르기 때문에 실제 서비스 운영에서는 관련 규정을 준수해야 한다. 또한 AI가 사람을 대신해 통화하는 과정에서 잘못된 정보를 전달하거나 상대방의 답변을 부정확하게 이해할 경우 업무상 혼선이 발생할 수 있다.
엑스의 공식 도움말 역시 그록 봇이 실수할 수 있으며, 사용자는 AI가 제안한 작업을 검토하고 승인하거나 거부할 수 있다고 안내하고 있다. 이러한 통제 장치가 전화 업무에도 어떻게 적용되는지가 중요하다.

One of ML Drift's main goal is simplifying access to the diverse GPU hardware that developers encounter when creating applications for edge devices.

Nvidia open-sources Flora to make robot video labeling 125x cheaper than GPT-6 Astra
Labeling one hour of robot video for 72 cents instead of $88 is what Nvidia promises with Flora, its open data engine. But the comparison with GPT-6 Astra isn't quite as lopsided as the price tag suggests.
Large AI models for robots learn from videos that need text annotations, and according to Nvidia's GEAR research lab, this requires three types of labels. First, descriptions of what action happens when in the video, used to select training data. Second, ratings of how well a robot progresses step by step, so it can learn through trial and error. And third, judgments on whether a task was completed successfully, used to monitor robots during deployment. Most existing tools only provide one of these types. Large language models like GPT-6 Astra can generate several, but they're too expensive for the massive volumes of video involved.
According to the paper, Flora covers all three. Nvidia says the system is already running during training of its GR00T models, annotating up to 200,000 hours of video per day across 512 GB300 GPUs. The models are available on Hugging Face.
Flora consists of three fine-tuned Qwen3.5 models. A 9B model splits videos into action segments, and a 27B model describes them while factoring in what happened before and after each action. A second 27B model called Flora-Rewarder takes on three roles depending on the prompt. It rates an episode's success on a scale of 1 to 5, classifies each half-second step as normal, suboptimal, or failure, and assigns scores based on self-defined rubrics.
Up to 125x cheaper by Nvidia's own estimates
In a test with 50 videos, Flora scored slightly better than GPT-6 Astra according to Nvidia, even though OpenAI's model was allowed to use its full reasoning capacity. Labeling one hour of video runs about 72 cents with Flora by Nvidia's estimate, compared to roughly $88.50 with GPT-6 Astra. Claude Opus 5 scored much worse in the same test and still cost about $42 per hour.
The Flora cost figures are projections, though, not production measurements. Nvidia calculated them based on an assumed rental price of $10 per GPU per hour.
Flora finds actions better, but Astra often describes them more precisely
On the public WGO-Bench, Flora is best at detecting action boundaries but trails Astra in overall score and falls behind Gemini 3.8 Flash in pure description accuracy. According to the researchers, the gains come mainly from temporal localization.
On Nvidia's own DenseCaptionBench, Flora leads across all metrics for human recordings, but for robot videos the model comes in second behind Astra. There's a methodological catch the researchers acknowledge, too. GPT-6 Astra evaluates the descriptions while also being one of the models under test.
Almost no other model catches mid-episode errors
On RoboRewardBench, Flora's error rate is 27.8 percent lower than Astra's. The paper attributes the gap to partially completed tasks. When a robot only tips a bottle over instead of knocking it off the table, Flora assigns 3 out of 5 points to match the human reference, while Astra gives just one.
Flora-Rewarder catches 53.3 percent of failed steps within an episode, while no competitor gets above 11.7 percent and Astra doesn't catch a single one. The tradeoff is that Flora falsely flags about 11 percent of normal steps as errors. Astra still leads on rubric-based scoring and trajectory ranking.
In a video with many short hand movements, Flora identifies 34 of 37 individual actions, while Astra catches only four. On the flip side, Flora sometimes splits longer actions into too many small steps and occasionally gets descriptions wrong. In one video, a robot hand wipes a plate with a cloth, but Flora describes it as folding a napkin.
Nvidia positions Flora as an open alternative to commercial services like Scale AI's Physical AI Data Engine.

엔비디아가 로컬에서 적은 메모리로 자연스러운 대화와 작업 수행이 가능한 경량 온디바이스 AI 모델을 선보였다. 이번 모델은 음성·비전 모델과 함께 구동되는 기기 내 AI 시스템과 게임, 로봇 분야의 개발자가 성능과 메모리 사용량 사이의 균형을 맞추는 데 초점을 맞췄다.
엔비디아는 23일(현지시간) 약 4GB의 메모리 환경에서 실행할 수 있도록 설계한 오픈소스 경량 언어모델 ‘네모트론 3.5 볼트 E4B 4GB(Nemotron 3.5 Bolt E4B 4GB)’를 공개했다.
특히 이번 모델은 윈도우 PC는 물론 엣지 컴퓨팅과 로보틱스 개발 환경에서 즉시 도입할 수 있도록 실용적 배포 생태계를 넓힌 것이 특징이다.
구글의 '젬마 4 E4B'를 기반으로 엔비디아의 사후학습 기법을 적용했다. 지포스 RTX와 젯슨(Jetson), RTX 스파크, DGX 스파크 등 엔비디아 하드웨어에서 실행할 수 있으며, 음성이나 비전 모델 등 다른 AI 모델과 함께 구동할 수 있도록 메모리 사용량을 줄인 것이 핵심이다.
주요 대화형 에이전트 벤치마크에서 이전 모델인 네모트론 3 나노 4B보다 평균 점수가 약 40% 높았으며, 비교 대상 모델보다 평균적으로 약 10% 높은 점수를 기록했다. 추론 기능을 활성화한 비교에서는 출력 토큰 수를 최대 80% 줄였다. 불필요한 텍스트 생성을 줄이면 연산량과 비용을 낮추고 응답 속도를 개선할 수 있다는 설명이다.
모든 평가 항목에서 우위를 보인 것은 아니다. 21개 벤치마크 가운데 15개에서 경쟁 모델보다 높은 점수를 기록했지만, 일부 장기 문맥 처리와 도구 호출 평가에서는 '큐원3.5-4B'가 앞섰다. '타우2-벤치(Tau2-Bench)' 점수는 볼트가 55.1점, 큐원3.5-4B가 75.1점이었다. 따라서 실제 적용 환경에 맞춰 모델의 성능을 검증할 필요가 있다.
네모트론 3.5 볼트 E4B는 대화 도중 API를 호출해 실제 작업을 수행할 수 있다. 여러 차례 대화를 주고받으면서 작업을 이어갈 수 있으며, 비동기 방식의 도구 호출을 구현하기 위한 가이드도 제공한다.
음성 인터페이스에 적합한 짧고 간결한 답변을 유도하는 대화 모드를 지원하며, 복잡한 요청에는 추론 기능을 활성화하고 빠른 응답이 필요할 때는 이를 비활성화할 수 있다. 추론에 사용하는 시간과 분량을 제한하는 설정도 제공해 애플리케이션의 지연 시간 요구에 맞춰 조정할 수 있다.
컨텍스트 길이는 최대 6만4000토큰이다. 대화 기록과 시스템 지침, 도구 정의, 검색 결과, 애플리케이션 상태 등을 함께 처리할 수 있다. 지원 언어는 35개이며, 기반 모델은 140개 이상의 언어로 사전 학습됐다.

활용 분야는 PC와 모바일, 스마트홈, 차량 내 음성 비서처럼 기기에서 직접 실행되는 에이전트, 대화와 행동을 결합하는 게임 속 NPC 캐릭터와 가상 동반자, 로봇과 중장비를 제어하는 임베디드·산업용 에이전트다.
기존 LLM도 이러한 기능을 구현할 수 있지만, 메모리와 응답 지연, 하드웨어 호환성, 운영 비용, 개인정보 보호 등의 제약으로 실제 제품에 적용하기 어려운 경우가 있다. 로컬에서 실행하는 경량 모델은 외부 서버 의존도를 줄이면서 이러한 문제를 완화할 수 있다.
엔비디아는 이번 모델의 사후 학습에 검증 가능한 보상을 활용하는 강화학습(RLVR)과 인간 피드백 기반 강화학습(RLHF)을 적용했다. 관련 학습에는 네모(Nemo)-RL과 네모-짐(Nemo-Gym) 프레임워크를 사용했다.
학습 과정에서는 도구 호출과 지시 이행, 구조화된 출력, 다중 턴 대화 등을 다뤘다. 추론 모드와 비추론 모드를 모두 학습에 포함하고, 비추론 데이터와 추론 데이터의 비율을 2대1로 유지해 추론 기능을 사용하지 않을 때도 정확도를 확보하도록 했다.
학습 후 선택한 BF16 체크포인트를 Q4_K_M 형식으로 양자화해 배포용 모델을 만들었다. 중요도 행렬(imatrix)을 활용한 보정 과정에는 약 100만 토큰 규모의 강화학습 데이터를 사용했다.
병렬 추론을 지원하는 D플래시(DFlash) 초안 생성기(drafter)도 함께 공개했다. 이 방식은 한 번의 순전파로 여러 후보 토큰을 생성하고 대상 모델이 이를 병렬로 검증하는 구조다. 이를 통해 젬마 4 E4B의 기존 초안 생성기와 비교해 처리량을 최대 21% 높일 수 있다고 강조했다.
모델은 허깅페이스와 올라마(Ollama), LM 스튜디오, 언슬롯(Unsloth), 젯슨 AI 랩 등을 통해 이용할 수 있다. 엔비디아의 인게임 추론 SDK를 활용해 게임 캐릭터에 적용하는 것도 가능하다.
