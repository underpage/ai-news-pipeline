[BODY]
Researchers found a malicious AGENTS markdown instruction file in a customer’s Downloads folder that tricked an AI coding agent into installing a rogue npm package.
They reproduced the attack against OpenAI Codex and demonstrated a related technique against Claude Code to leak OAuth tokens and hijack the account using only the malicious instructions.
Markdown files such as AGENTS.md are plain-text files that contain project-specific instructions for AI coding agents, such as the tools to use, how to run tests, and the coding conventions to follow.
Agents following malicious instructions
Researchers at Forever Security, a company that monitors for risks introduced by AI agents and autonomous software, discovered the tactic on a customer’s computer, where a coding agent attempted to install the malicious npm package ‘function-color.’
The investigation traced the AI agent’s attempt to install a malicious npm package to an AGENTS.md file in the customer’s ~/Downloads folder, which also served as the agent’s working directory.
Agents automatically load applicable files from their working directory and use the contained instructions to guide their actions.
While these files aren’t executables, malicious instructions contained in them can lead to AI agents running commands, installing packages, or changing settings using the tools and permissions available to it.
"There is nothing here for OpenAI or Anthropic to patch. An agent that follows the AGENTS.md in its folder is doing exactly what it was built to do," the researchers say.
The researchers' test confirmed that an attacker could use such a file to manipulate OpenAI Codex and Claude Code into executing code or stealing credentials.
Although the researchers could not determine how the malicious instructions file landed into the target's ~/Downloads location, they explained to BleepingComputer that simply visiting a malicious page could drop a payload without any user interaction.
In a report this week, Forever Security says that "~/Downloads is special. It is the one folder the web can write to on its own," and that "a web page can download a file named AGENTS.md into your Downloads folder, silently."
The researchers created a proof-of-concept (PoC) to demonstrate how the attack could land a malicious file into the ~/Downloads location without the user noticing.
When BleepingComputer verified the PoC page, it downloaded an AGENTS.md file containing harmless content, namely the strings "sensitive data here" and "line 2."
By default, many popular browsers, including Chrome, Edge, and Firefox, save files downloaded from the web to the user's ~/Downloads directory without prompting them to choose a save location for each download.
BleepingComputer’s tests in other browsers, such as Brave, prompted the user to approve the download, which should be enough to alert the user that a file was downloaded.
However, Chrome, Edge, and Firefox display download notifications by default, alerting users when a file has been saved locally.
After dropping the file into Downloads, the attack would require the target to launch their AI agent in that same directory so it could load the instruction file and digest its malicious instructions.
Forever researcher Gal Weizman told BleepingComputer that this is common practice, as people often use AI agents to organize that folder or to act on a newly downloaded file.
Weizman says that internal statistics show that hundreds of customers run AI agents, including Claude Code, OpenAI Codex, and Cursor CLI, from their ~/Downloads folders. Claude Code alone launched more than 1,300 sessions from that location, the researcher told BleepingComputer.
Tests show attack feasible
The researchers tested their reconstructed attack chain against Codex using a harmless payload that simply opened the calculator app, recording a 90% success rate.
In a separate test, they used a malicious CLAUDE.md file to redirect Claude Code’s API traffic to a server they controlled.

ML Drift is the core GPU acceleration engine that powers LiteRT. By open-sourcing it, Google is enabling developers to build custom graphics and inference runtimes for applications ranging from traditional computer vision, audio, and depth processing to generative AI.
One of ML Drift's main goal is simplifying access to the diverse GPU hardware that developers encounter when creating applications for edge devices.
Developers are faced with a wide range of GPU architectures, driver versions, and low-level APIs, not knowing a priori on which specific hardware the application will run on.

Dawn provides a unified API model leveraging WebGPU's hardware abstraction layer, avoiding the need to interface directly with platform-specific graphics APIs such as DirectX and Vulkan.

The company also emphasized that ML Drift is already running on millions of devices through apps like Chrome, YouTube Shorts, Photos, and Meet.

Native 5D tensor support without layout hacks is a massive win for running spatial and transformer models on edge GPUs. Decoupling logical tensors from physical memory allocations should significantly cut down on memory fragmentation during live inference.
Matthew Charles Vladislav Busel, founder and sole developer of Tensorust, questioned "how it compares with Core ML on recent iPhones for latency and memory, since that is what most of us ship against today", though Google has not provided any comparative figures.
With the release of ML Drift, Google will stop updating the legacy TensorFlow Lite GPU delegate. For backward compatibility with existing models, the company recommends migrating to the LiteRT ML Drift GPU accelerator. Application developers can use the LiteRT ML Drift accelerator, while GPU and system engineers can access its lower level C++ API to construct custom GpuModel compute graphs and write custom shaders.

Anthropic found that a single agent with on-demand context often outperforms multi-agent setups in quality, cost, and latency. The company is releasing a migration kit to help teams evaluate and make the switch.
Anthropic is recommending that companies evaluate whether they can consolidate sub-agents, because a single primary agent that loads context as needed often delivers better results than a fleet of specialized ones. Newer models starting with Opus 4.5, along with Opus 5.5 and Fable 5.1, can manage complex plans directly in a single loop, which can also reduce costs and wait times. In one comparison, Anthropic says the single-agent architecture ran about twice as fast as the multi-agent setup.
The recommendation comes from hands-on experience across multiple enterprise deployments, where Anthropic's Applied AI team found that a single agent using so-called skills frequently beat both monolithic prompt designs and sub-agent setups on quality. One company, for example, had a dozen specialized sub-agents inside its customer-facing agent, which made it hard to keep a consistent brand experience and hurt usability with high latency.
The model can now do much of the orchestration work itself
According to Anthropic, many agent designs follow a familiar pattern with intent detection, a fixed processing pipeline, user segmentation, separate recommendation branches, and an orchestrator sitting on top. Much of that is work the model can now handle on its own for the respective use case.
Anthropic calls it "Conway's Law" for agents. The architecture becomes a copy of the org chart, with each team shipping its own sub-agent until hundreds of overlapping agents pile up with no shared standards. What follows is what Anthropic calls a "Frankenprompt," where every team adds rules to the system prompt that end up contradicting each other. A clean system prompt, four or five lean data tools, and fixed output guardrails cover much of the respective use case, according to the company.
As one example, Anthropic cut the Claude Code system prompt for newer models by over 80 percent, partly because skills and tools now load only when needed. Newer models also comment on their own progress and check their own work, which can make some of the extra control layers unnecessary.
Anthropic says sub-agents still make sense when a single agent's context window shows measurable performance degradation, when multiple tasks need to run in parallel with separate context windows, or when a single agent struggles with tool selection.
For a step-by-step migration, Anthropic has published a migration kit on GitHub that walks teams through a workflow to identify existing patterns, evaluate alternatives, and verify the best approach. Anthropic warns against merging blindly, since in one test with a support agent, folding in a sub-agent did reduce latency but broke a previously working process. The primary agent started answering on its own instead of consulting the right specialist.
Teams should keep skill libraries from sprawling
Instead of giving every team its own agent, Anthropic recommends packaging workflows into skills and loading tools on demand through a tool search. A small central team should own the system prompt and overall quality. Separately, Anthropic notes that the model's tool selection tends to degrade beyond 30 to 50 tool definitions, so designated owners on each team should maintain the skill libraries to keep them from ballooning.

[TITLE] “AI가 사람 대신 전화하고 업무까지 처리”…머스크, 그록 자율 통화 기능 공개

[REASON] 전화 통화 및 업무 수행을 대행하는 그록 봇 기능 공개

전화 연결부터 요청 전달·상대방 답변 기록·결과 보고까지…AI 에이전트, 실제 음성 소통 영역으로 확장
인공지능(AI)이 사람을 대신해 전화를 걸고, 상대방과 대화하며, 업무 처리 결과까지 보고하는 시대가 열리고 있다. AI 에이전트가 단순한 질문 응답이나 문서 작성에서 벗어나 실제 전화망을 통해 사람과 소통하고 업무를 수행하는 방향으로 진화하고 있다.
일론 머스크(Elon Musk) 테슬라(Tesla)·스페이스X(SpaceX) 최고경영자(CEO)는 25일(현지시간) 자신의 소셜미디어 엑스(X)를 통해 AI 챗봇 그록(Grok)의 전화 업무 수행 기능을 소개했다.
머스크는 “그록 봇(Grok Bot)은 이제 여러분을 대신해 사람이나 기업에 전화하고, 요청사항을 전달하며, 상대방의 답변을 기록한 뒤 통화 내용을 요약한 메모를 보내줄 수 있다”고 밝혔다.
이번 발표의 핵심은 AI가 사용자의 요청을 이해하는 데 그치지 않고, 실제 전화 통화를 통해 외부 상대방과 소통한 뒤 그 결과를 사용자에게 전달한다는 점이다. 사용자가 일일이 전화를 걸고 통화 내용을 정리해야 했던 과정을 AI 에이전트에 위임할 수 있도록 하는 것이다.
전화 걸고 대화한 뒤 결과까지 보고, AI 에이전트의 역할 확대
머스크가 공개한 기능은 전화 연결부터 업무 요청, 상대방 응답 기록, 통화 결과 요약까지 하나의 작업 흐름으로 수행하도록 설계됐다. 예를 들어 사용자가 특정 업체에 연락해 예약 가능 여부를 확인하도록 요청하면, AI가 해당 업체에 전화를 걸어 문의 내용을 전달하고 상대방의 답변을 기록한 뒤 결과를 요약해 사용자에게 알려주는 방식이다.
상품 재고 확인이나 서비스 이용 문의, 일정 확인 등에도 같은 방식이 활용될 수 있다. 이는 공개된 기능을 바탕으로 예상할 수 있는 활용 사례이며, 각각의 업무에 대한 실제 수행 성공률이 검증됐다는 의미는 아니다.
그록 봇 0.77 시험판을 분석한 외부 개발자들의 설명에 따르면, 전화 연결 이후 대기하거나 자동응답시스템의 안내에 따라 숫자를 입력하고 담당자와 연결되는 기능도 시험되고 있는 것으로 알려졌다. 실시간 통화 내용을 표시하는 기능 역시 거론됐다.
이러한 세부 기능은 머스크가 직접 발표한 공식 기능 범위와 구분할 필요가 있다. 시험판에서 확인된 기능이 모두 정식 서비스에 적용되는지, 실제 전화 환경에서 어느 수준까지 안정적으로 작동하는지는 추가 확인이 필요하다.
AI가 전화를 걸어 상대방의 답변을 수집하는 것과 복잡한 협상이나 예약 변경, 계약 등 후속 업무까지 독립적으로 완료하는 것은 기술적으로 다른 과제다. 이번 발표에서 확인되는 핵심 기능은 전화 기반 요청 전달과 응답 기록, 결과 요약이다.
예약 확인·고객센터 문의까지...전화 업무 자동화 가능성
AI 에이전트의 전화 업무 수행 기능은 개인의 일상생활뿐 아니라 기업의 고객 응대와 업무 운영 방식에도 변화를 가져올 수 있다.
기존 음성 AI 서비스가 주로 사용자의 질문에 답하거나 걸려 온 전화를 응대하는 데 집중했다면, 이번에 머스크가 소개한 기능은 AI가 먼저 외부에 전화를 걸어 사용자가 지시한 업무를 수행한다는 점에서 차이가 있다.
특히 고객센터에 전화를 걸어 상담원 연결을 기다리거나, 여러 업체에 반복적으로 연락해 정보를 확인하는 작업에 활용할 수 있다. 기업 입장에서는 거래처 문의, 일정 확인, 단순 정보 수집 등 반복적인 전화 업무를 자동화하는 데 적용할 여지가 있다.
이는 AI 에이전트의 활용 범위가 디지털 정보 처리에서 현실 세계의 커뮤니케이션으로 확장되고 있음을 보여준다. 전화는 상대방의 실시간 응답과 상황에 따라 대화 흐름이 달라지는 만큼, AI가 실제 업무를 수행하는 능력을 평가하는 중요한 환경이 될 수 있다.
통화 녹음·개인정보 보호·상대방 동의 등 해결 과제
전화 업무를 AI에 위임하는 과정에서는 기술적 완성도와 함께 개인정보 보호, 통화 상대방의 동의, AI의 신원 고지 등 해결해야 할 문제도 적지 않다.
AI가 통화 내용을 기록하고 요약하려면 상대방의 음성이나 개인정보가 처리될 수 있다. 국가와 지역에 따라 통화 녹음 및 개인정보 처리에 관한 법적 요건이 다르기 때문에 실제 서비스 운영에서는 관련 규정을 준수해야 한다. 또한 AI가 사람을 대신해 통화하는 과정에서 잘못된 정보를 전달하거나 상대방의 답변을 부정확하게 이해할 경우 업무상 혼선이 발생할 수 있다.
엑스의 공식 도움말 역시 그록 봇이 실수할 수 있으며, 사용자는 AI가 제안한 작업을 검토하고 승인하거나 거부할 수 있다고 안내하고 있다. 이러한 통제 장치가 전화 업무에도 어떻게 적용되는지가 중요하다.

[TITLE] “모르면 추측 대신 기억을 확인한다”…ETRI·GIST, 스스로 판단하고 행동하는 로봇 AI 플랫폼 공개
[LINK] https://www.aitimes.kr/news/articleView.html?idxno=42427
[PUBLISHED] 2026-10-26 10:40 KST
[SOURCE] 인공지능신문
[TOPIC] 에이전트, 모델, 신기술
[SCORE] 7
[REASON] 환경 관측과 기억 검색을 결합한 로봇 AI 에이전트 개발
[BODY]
환경 관측과 능동적 기억 검색 결합한 ‘씬쿼리플래너’ 개발…로봇의 복합작업 성공률 최대 24%p 향상, 3차원 장면 그래프 기반 정보 검증으로 AI 환각·판단 오류 줄여
로봇이 주변 환경을 직접 관찰하고, 과거에 확인한 정보를 기억에서 찾아 검증한 뒤 행동하는 새로운 인공지능(AI) 기술이 개발됐다. 기존 로봇 AI가 불확실한 상황에서 언어모델의 사전 지식에 의존해 잘못 판단하는 문제를 줄이고, 실제 관측한 사실을 바탕으로 복잡한 작업을 수행하도록 하는 기술이다.
한국전자통신연구원(ETRI)은 광주과학기술원(GIST)과 공동으로 환경 관측과 능동적 기억 검색을 결합한 로봇 AI 에이전트 '씬쿼리플래너(SceneQueryPlanner)'를 개발했다고 26일 밝혔다.
연구진은 로봇이 공간과 사물의 위치, 재질, 상태 등을 구조화된 기억으로 저장하고, 작업 수행 과정에서 필요한 정보를 스스로 검색하거나 추가 관측하도록 설계했다. 이를 통해 기존 방식 대비 복합작업 성공률을 최대 24%포인트 높였다.
로봇 AI의 새로운 과제...'무엇을 할까'보다 '무엇을 확인할까'
최근 대형언어모델(LLM)의 발전으로 로봇은 사람의 자연어 명령을 이해하고 여러 단계의 행동을 계획할 수 있게 됐다. 그러나 실제 생활환경에서는 언어를 이해하는 것만으로 작업을 정확하게 수행하기 어렵다. 물체의 위치와 종류뿐 아니라 재질, 현재 상태, 주변 사물과의 관계 등 세부적인 환경정보를 파악해야 하기 때문이다.
예를 들어 사용자가 "식탁 위 유리컵은 선반에, 플라스틱 컵은 캐비닛에 정리해 줘"라고 지시하면 로봇은 컵을 찾는 것에서 그치지 않고 각각의 재질을 구분해야 한다. 또 "켜져 있는 전자제품을 모두 꺼줘"라는 명령을 수행하려면 어떤 전자제품이 있는지, 현재 전원이 켜져 있는지 확인해야 한다.
기존 대형언어모델 기반 로봇 에이전트는 주변 환경을 관측한 정보를 긴 문장 형태로 전달받아 행동을 계획하는 경우가 많았다. 하지만 관측정보가 부족하면 물체의 속성을 잘못 추측할 수 있고, 반대로 정보가 지나치게 많으면 작업과 관계없는 내용까지 처리해야 해 추론의 안정성이 떨어질 수 있다.
연구진은 이러한 문제를 '수동적 관측(Passive Observation)'에 따른 한계로 설명했다. 필요한 정보가 누락되거나 불필요한 정보가 과도하게 제공되는 환경에서는 AI가 잘못된 근거로 판단하는 환각(Hallucination)과 불안정한 추론이 발생할 수 있다는 것이다.
이를 해결하기 위해 연구진은 로봇이 정보를 수동적으로 전달받는 방식에서 벗어나, 현재 작업에 필요한 정보가 무엇인지 판단하고 직접 확보하는 능동적 정보 탐색(Active Information Seeking) 방식을 제안했다.
3차원 장면 그래프에 공간·사물·상태 저장...로봇의 구조화된 기억 구현
씬쿼리플래너의 핵심 기술은 로봇이 관측한 환경정보를 '3차원 장면 그래프(3D Scene Graph)'로 구성해 저장하는 것이다. 3차원 장면 그래프는 공간을 방과 가구, 물체 등으로 구분하고 각각의 위치와 속성, 상호 관계를 연결한 구조화된 정보 표현 방식이다.
예를 들어 거실에 있는 탁자와 탁자 위 컵, 주방의 캐비닛과 선반 등을 각각의 객체로 표현하고, 물체가 어디에 놓여 있는지와 어떤 속성을 갖는지를 관계 정보로 연결한다.
물체의 재질뿐 아니라 문이 열려 있는지, 전자제품의 전원이 켜져 있는지 등 작업에 필요한 상태 정보도 저장할 수 있다. 이러한 기억은 새로운 관측정보가 들어오면 갱신된다. 로봇이 다른 방으로 이동한 뒤에도 이전에 관측한 환경정보를 활용할 수 있도록 설계된 것이다.
특히 씬쿼리플래너는 저장된 모든 정보를 한꺼번에 언어모델에 제공하지 않는다. 현재 수행해야 할 작업과 직접 관련된 정보만 선택적으로 검색한다. 이를 통해 환경정보가 증가하더라도 불필요한 내용이 추론 과정에 개입하는 문제를 줄이고, 여러 공간에 걸친 장기 작업에서도 필요한 정보를 활용하도록 했다.
환경 관측과 기억 검색 결합...정보 확인 자체를 행동 계획에 포함
연구진이 제안한 핵심 개념은 '기억·환경 이중 그라운딩(Memory–Environment Dual-Grounding)'이다. 그라운딩은 AI의 판단과 추론을 실제 관측정보나 확인 가능한 데이터에 연결하는 과정을 의미한다.
씬쿼리플래너는 두 가지 정보 확인 방식을 결합한다. 먼저 '환경 그라운딩(Environment Grounding)'은 로봇이 직접 주변을 관찰하거나 이동하면서 필요한 정보를 확보하는 방식이다. 반면 '메모리 그라운딩(Memory Grounding)'은 이전에 관측해 저장한 기억에서 현재 작업에 필요한 정보를 검색하는 방식이다.
씬쿼리플래너는 사용자의 명령을 세부 작업으로 나누고, 각 단계에서 필요한 정보가 무엇인지 판단한다. 이후 저장된 기억을 검색할지, 주변 환경을 추가로 관측할지 선택한다.
연구진은 정보 획득 자체를 행동 계획의 핵심 요소로 취급했다. 즉, 로봇이 물체를 집거나 이동하는 동작뿐 아니라 '어떤 정보를 확인해야 하는가'까지 계획하도록 한 것이다. 예를 들어 컵을 재질별로 분류해야 한다면 로봇은 먼저 컵의 위치를 파악하고, 기억에 저장된 재질 정보를 조회한다. 필요한 정보가 부족하면 추가적인 환경 관측을 통해 확인한 뒤 물체를 이동한다.
이처럼 추측에 의존하지 않고 필요한 정보를 명시적으로 확인하는 구조는 여러 단계에 걸친 복잡한 작업에서 판단 오류를 줄이는 데 도움이 된다.
새로운 평가체계 '앳플랜-벤치' 개발...복합작업 수행 능력 검증
연구진은 기술의 효과를 검증하기 위해 속성 기반 행동 계획 평가체계인 '앳플랜-벤치(AttPlan-Bench)'도 개발했다. 앳플랜-벤치는 여러 방으로 구성된 가정환경에서 장기간에 걸쳐 수행해야 하는 복합작업을 평가하도록 설계됐다.
평가에는 물체 이동과 정리, 가열과 냉각, 청소, 전자제품의 전원 조작 등 10가지 유형의 작업이 포함됐다. 특히 단순히 물체를 찾아 이동하는 작업을 넘어 재질이나 상태, 위치관계를 정확하게 확인해야 하는 속성 기반 작업을 포함했다. 이는 AI가 일반적인 행동 계획을 생성하는 능력뿐 아니라, 실제 환경에서 확보한 정보를 바탕으로 판단하는 능력을 평가하기 위한 것이다.
연구진은 기존의 추론·행동 결합 방식인 '리액트(ReAct)'와 씬쿼리플래너의 성능을 비교했다. 리액트는 언어모델이 추론과 행동을 반복하면서 문제를 해결하는 대표적인 AI 에이전트 접근법이다. 그러나 환경정보를 수동적으로 전달받는 구조에서는 필요한 세부 정보가 누락되거나 불필요한 정보가 누적되는 한계가 있다.
씬쿼리플래너는 이 과정에 선택적인 기억 검색과 환경 관측을 추가해 작업 수행에 필요한 정보를 확보하도록 했다.
라마 3.1 성공률 69.6%, 큐웬 2.5는 68.0%...최대 24%p 개선
실험 결과 씬쿼리플래너는 오픈소스와 상용 언어모델을 활용한 평가에서 기존 리액트 방식보다 높은 작업 성공률을 기록했다. 메타(Meta)의 라마 3.1(LLaMA 3.1)을 활용한 실험에서는 작업 성공률이 기존 46.8%에서 69.6%로 상승했다. 이는 22.8%포인트 개선된 수치다.
알리바바의 큐웬 2.5(Qwen 2.5)를 적용한 실험에서는 기존 44.0%에서 68.0%로 높아져 24.0%포인트 향상됐다. 오픈AI의 GPT-4o를 활용한 실험에서도 모든 평가환경에서 기존 방식보다 높은 성능을 나타냈다. 특히 물체의 속성을 확인해야 하는 복합작업의 성공률은 17.2%포인트 개선됐다.
이번 결과는 언어모델의 규모를 확대하거나 새로운 모델을 학습시키는 것 외에도, 환경정보를 검색하고 검증하는 에이전트 구조를 개선하는 방식으로 작업 수행 능력을 높일 수 있음을 보여준다.
특히 연구진은 논문에서 기억과 환경을 결합한 이중 그라운딩 방식이 다양한 작업에서 보다 안정적이고 확장성 있는 추론을 지원한다고 설명했다. 다만 이러한 성능은 연구진이 구축한 벤치마크 환경에서 확인된 결과다. 실제 가정이나 산업현장에서 로봇이 동일한 성공률을 보인다는 의미는 아니다.
