[TITLE_KO] 워드프레스 SEO 플러그인 랭크매스 침해되어 웹사이트에 백도어 심어

[REASON] 인기 워드프레스 플러그인 변조를 통한 백도어 공급망 공격
[BODY]
Some downloads of the Rank Math PRO WordPress plugin from the vendor’s official website carried malware that planted hidden backdoors in a supply-chain attack last week.
According to the vendor, a limited number of users who downloaded version 3.0.123 of the plugin between October 15 at 20:02 UTC and October 16 at 07:12 UTC received compromised versions that could compromise their websites upon activation.
“The affected plugin files contained malware that could compromise your website if the plugin was activated,” Rank Math warned.
“We immediately removed the affected files and released a clean version, Rank Math PRO v3.0.124.”
Users who installed and activated the trojanized version during this 11-hour window should treat their websites as compromised and follow the clean-up procedures in the advisory from the vendor.
Rank Math PRO is a WordPress search engine optimization (SEO) plugin that helps websites improve visibility in search results. It is the paid version of the free variant that is active on more than 4 million websites.
Sensitive material exposed
An advisory from the vendor highlights that only the PRO version was compromised and the free version of Rank Math SEO from WordPress.org remained unaffected.
Rank Math says that the malware establishes persistent access, communicates with ‘rank1cdn[.]com,’ and recreates hidden backdoors when someone visits the infected website.
The vendor warns that users installing the compromised version of Rank Math PRO expose database credentials, API keys, and other secrets accessible to the web server.
While researching the attack, BleepingComputer discovered a PHP malware sample on VirusTotal named 'cache-preloader-fff033 (1).php' that appears to be connected to the Rank Math compromise.
Although this file was not mentioned in the Rank Math or Wordfence advisories, BleepingComputer found it contained the same indicators of compromise (IoCs) included in Rank Math's alert:
- xmmqhn' XOR obfuscation key
- the '_np5pvf754c' WordPress database entry
- the '#ms6v46' cron job marker
- code for creating administrator accounts using the 'wpsupport_' username prefix and '@wp-mail.net' email addresses
The malware appears to act as a first-stage deployment script that creates the 'wp-includes/class-wp-cache-util.php' backdoor mentioned in Rank Math's advisory.
The PHP script also includes the ability to execute commands, modify WordPress databases, and steal AWS, Cloudflare, Google Cloud, Azure credentials, SSH keys, and other sensitive information.
While these IoCs indicate it is connected to the same threat actor as the Rank Math attack, BleepingComputer could not confirm whether it was distributed through the compromised plugin.
Cleanup recommendations
Website administrators who suspect a compromise should restore website files and the database from a clean backup, run security scans, and rotate all passwords, keys, and salts.
For websites without a safe backup to restore from, Rank Math recommends manual cleanup, noting that deactivating or updating the plugin after a compromise will not remove the threat.
Cleanup requires deleting the entire plugin folder and malicious database entries before investigating additional backdoors, unauthorized administrator accounts, altered files, scheduled tasks, and possible changes outside WordPress.
It is also recommended to block all outbound connections to the attacker's rank1cdn[.]com domain.
Users who installed but never activated the plugin should now delete it, download the clean 3.0.124 version, and then scan their sites.
BleepingComputer contacted Rank Math for details on the number of potentially affected sites and the initial attack vector but had received no response by the time of publication.

[BODY]
OpenCode, an open source AI coding agent that has been gaining ground among developers as an alternative to Claude Code and Cursor, said Saturday that attackers broke into an older system overnight, affecting 1.4% of users of its online platform, OpenCode Console, where some users store the API keys, or digital passwords, they use to access AI services.
As the OpenCode team struggled to keep pace with the attack, the scramble to respond highlighted a growing problem: Companies without vetted access to AI models with fewer safety restrictions have a hard time defending against large-scale, AI-driven cyberattacks.
“We had a security breach last night related to a large-scale distillation attack that impacted 1.4% of OpenCode Console users,” the company wrote on X. “We have notified them all this morning via email.” Users who did not receive an email were not impacted, the company said.
While the company didn’t specify how the distillation attack occurred, leaked API keys can help users in countries with restricted access to American models generate the high volume of outputs needed for that process. Some skeptics called the framing an overstretch, arguing that the incident was a straightforward breach whose use for distillation remains unproven.
Overnight, developers began posting spending alerts and unauthorized charges on Reddit and X: “I saw my Open AI, Anthropic, and Google AI spend alerts all fire off before going to bed wondering what was going on,” a developer wrote.
Other users reported charges in the hundreds of dollars on individual accounts; a few described totals above $1,000.
Anthropic and Google both blocked the API keys they believed were exposed, while OpenAI said it worked with OpenCode to restore access and refund its API customers for credits used in the attack. OpenCode said refunds for unauthorized charges are underway.
The exposed keys were confined to Console, where some users had them in workspaces. The open source app and command-line tool were not affected, according to co-founder Dax Raad. “Note this is the OpenCode Console, not OpenCode itself, those keys never come to us,” he wrote on X.
Even as users and AI companies moved to disable the exposed keys, the OpenCode team was still under pressure. Raad said attackers had been trying to break into its systems nonstop for 48 hours, requiring the team to keep AI defensive agents running around the clock. AI models that the OpenCode team turned to for analysis helped for a while, but started refusing to work when the malicious code they were asked to examine activated safety filters.
“[T]hat was a bit frustrating,” he wrote on X.
OpenCode later received access to OpenAI’s Daybreak Blue program, which gives vetted users AI models that are less likely to refuse requests for defensive security work. Raad said the access improved the team’s ability to investigate the attack.
OpenCode isn’t the first company to hit this wall. In July, AI platform Hugging Face said commercial AI models blocked its attempts to analyze activity logs from an intrusion by autonomous AI agents, which OpenAI later revealed were its own models running with safeguards lowered during a test. In a section of its blog post titled “The asymmetry problem,” Hugging Face wrote that guardrails “cannot distinguish an incident responder from an attacker.”
Security researchers have raised similar complaints, saying the restrictions are inconsistent and have pushed some toward foreign open-weight models, which anyone can download and run.
The weekend episode drew a response from David Sacks, co-chair of the President’s Council of Advisors on Science and Technology.
“OpenCode (and earlier Hugging Face) hit the same wall mid-attack: frontier models refused to analyze the very exploits needed for defense because the payloads tripped safety filters. The guardrails backfired,” he wrote on X.
The breach occurred the same night OpenCode made GLM-5.3-Flash free for users.

[TITLE] 앤트로픽이 검증한 ‘AI 웜’ 자가복제 실험
[LINK] https://byline.network/2026/10/19-673/
[PUBLISHED] 2026-10-20 09:41 KST
[SOURCE] 바이라인네트워크
[TOPIC] 모델, 보안
[SCORE] 9
[REASON] 자가복제하는 AI 웜의 실행 가능성 검증 연구
[BODY]
앤트로픽이 검증한 ‘AI 웜’ 자가복제 실험
인공지능(AI) 기업 앤트로픽이 다른 기기로 옮겨가며 스스로 복제하는 ‘AI 웜(AI Worm)’의 구현 가능성을 시험했다. 앤트로픽은 지난 12일(현지시간) 저사양 사물인터넷(IoT) 기기에서 AI 모델을 실행하고 통제된 환경에서 복제 절차를 수행한 연구 결과를 발표했다.
앤트로픽 연구진은 AI 모델이 새로운 기기의 환경에 맞춰 실행 방법을 조정할 수 있다는 점에 주목했다. 다만 실제 인터넷에서 AI가 스스로 기기를 감염시키며 확산하는 웜을 구현한 것은 아니다.
스스로 복제하는 ‘AI 웜’이란
컴퓨터 웜(Worm)은 사람의 개입 없이 다른 컴퓨터로 자신을 복제해 퍼지는 악성코드다. 네트워크에서 취약한 기기를 찾아 감염시킨 뒤 같은 과정을 반복한다. AI 웜은 이러한 복제 과정에 AI 모델을 활용하는 방식이다. 기존 웜은 주로 미리 작성한 프로그램과 공격 절차에 따라 움직이지만, AI 웜은 새로운 기기의 운영체제와 소프트웨어 환경을 분석하고 실행 방법을 조정하도록 설계할 수 있다.
AI 웜은 다른 기기에 접근한 뒤 AI 모델의 ‘가중치(Weights)’와 실행 프로그램을 전달하는 방식으로 복제할 수 있다. 가중치는 AI가 학습한 정보를 수치로 저장한 데이터다. 새로운 AI를 학습시키는 것이 아니라 기존 모델을 복사해 다른 기기에서 실행하는 것이다.
예를 들어 AI 웜이 스마트TV에 침투했다고 가정해 보자. AI는 주변 네트워크에서 다른 기기를 찾고 접근 가능한 경로를 조사한다. 취약점을 이용해 다른 기기에 접근하는 데 성공하면, 자신의 AI 모델과 실행 프로그램을 다른 기기에 옮긴다. 새로운 기기에서 AI가 작동하도록 실행 환경을 구성하고 같은 과정을 반복하는 방식이다. 여기서 복제한다는 것은 AI가 새로운 AI 모델을 학습시켜 만드는 것은 아니다. 기존 AI 모델의 가중치를 다른 기기에 복사하거나 외부 저장소에서 내려받는 것이다.
TV 박스 15대 연결해 AI 모델 실행
앤트로픽은 저가형 안드로이드 TV 박스 15대를 연결해 약 260억개 매개변수를 가진 AI 모델 ‘젬마4-26B-A4B(Gemma4-26B-A4B)’를 분산 실행했다. 연구진은 모델을 여러 부분으로 나눠 기기마다 실행하고 서로 통신하도록 구성했다. 처리 속도는 초당 0.39토큰으로 일반적인 챗봇 형태의 AI보다 느렸다.
별도 실험에서는 90억개 매개변수의 소형 AI 모델이 9개 하드웨어 유형 중 8개에서 AI 실행 환경을 구축했다. 이는 서로 다른 기기에서도 AI가 실행에 필요한 프로그램을 설치하고 환경을 구성할 수 있는지 확인한 실험이다. 연구진은 안드로이드 가상 기기 8개로 구성한 통제된 네트워크에서도 복제 절차를 시험했다. 대형 AI 모델 ‘GLM-5.2’는 5차례 시험 중 4차례에서 8개 기기 전체로 복제 작업을 확장했다.

앤트로픽은 소형 AI 모델의 성능이 향상되고 있지만, 복제 과정을 연속으로 수행하는 데는 한계가 있다고 설명했다. 복제에 필요한 작업을 안정적으로 수행하는 대형 모델은 저사양 기기에서 직접 실행하기 어렵기 때문이다. 연구진은 소형 AI 모델의 성능이 기존 추세대로 개선된다면 올해 말에는 자가복제에 필요한 수준에 도달할 가능성이 있다고 전망했다.
AI 웜 확산하면 ‘AI 봇넷’ 형성 가능
앤트로픽은 AI 웜의 잠재적 확산 사례로 기존 사물인터넷 봇넷을 제시했다. 봇넷(Botnet)은 악성코드에 감염된 여러 기기를 공격자가 원격으로 통제하는 네트워크다. 감염된 컴퓨터는 흔히 ‘좀비 PC’라고 부른다. 웜은 감염을 확산시키는 악성코드이고, 봇넷은 감염된 기기를 공격에 활용하는 체계다.
실제로 보안업체 신시언트(Synthient)는 지난 1월 ‘킴울프(Kimwolf)’ 봇넷이 안드로이드 기반 기기 200만대 이상을 감염시켰다고 분석했다. 주요 감염 대상은 TV 스트리밍 장치 등이었다.
앤트로픽은 AI 기반 봇넷이 기존 봇넷보다 다양한 기기에서 작동할 가능성에 주목했다. 기존 봇넷이 주로 특정 운영체제나 취약점을 대상으로 공격한다면, AI는 새로운 기기의 환경을 분석하고 실행 과정에서 발생하는 문제를 해결할 수 있다는 설명이다.
감염된 기기 여러 대의 연산 자원을 결합해 AI 모델을 실행하는 것도 가능하다. 앤트로픽은 이러한 방식으로 AI 모델이 스마트TV뿐 아니라 스마트 냉장고, 로봇청소기 등에서도 실행될 가능성을 제시했다. 다만 해당 기기에 실제 침투해 복제하는 데 성공한 것은 아니다.
AI 웜을 막으려면
앤트로픽은 AI 웜이 확산하는 과정에서 발생하는 비정상적인 네트워크 통신을 탐지할 수 있다고 설명했다.
AI 모델을 다른 기기로 전달할 때 수 기가바이트(GB) 규모의 데이터가 이동하거나 여러 기기가 지속해서 통신하는 현상이 탐지 단서가 될 수 있다. 감염된 기기가 다른 장치를 탐색하면서 발생하는 통신도 확인할 수 있다.
감염 기기를 네트워크에서 격리하는 방법도 제시했다. 인터넷서비스제공업체(ISP)가 감염된 이용자의 통신을 제한하면 추가 확산을 줄일 수 있다는 설명이다. 기기 제조사는 기본 보안 설정을 강화해 공격 대상을 줄일 필요가 있다.
앤트로픽은 “아직 완전한 형태의 자율 복제 AI가 등장한 것은 아니지만, AI 에이전트는 복제에 필요한 개별 작업을 점점 더 잘 수행하고 있다”며 “이러한 AI가 확산하기 어렵도록 시스템 보안을 강화하는 동시에 이들이 계속 존재하는 상황에도 대비해야 한다”고 강조했다.

ConnectWise suspends Cloud Backup service after attackers abuse its Microsoft 365 access
American software company ConnectWise is contending with a security incident that has allowed unknown attackers to use its application identities to break into organizations’ Microsoft 365 accounts.
The intruders used a compromised credential belonging to the ConnectWise Cloud Backup application, formerly known as SkyKick.
This spurred the company to temporarily suspend the backup service, as well as its SaaS Security (monitoring and alerting) and Cloud Management (user and license management) services, as they are integrated with Cloud Backup.
The investigation into the incident is ongoing, with the help of third-party experts.
How the service works
ConnectWise sells most of its products to managed service providers (MSPs), the outside IT firms that small and mid-sized companies hire to run/manage their technology. The company says more than 100,000 such providers use its platform, and each may look after dozens or hundreds of client organizations.
Cloud Backup, which ConnectWise acquired with SkyKick in 2024, is one of the tools MSPs use to protect those clients’ data. It keeps copies of email, OneDrive and SharePoint files, and Teams chats so they can be restored after accidental deletion or a ransomware attack.
To do that, an administrator at each client grants the software broad permissions through Microsoft Entra ID, Microsoft’s identity system. The backup app then exists in that organization’s Microsoft 365 account as an application identity (otherwise known as a “service principal”) and it can read and write data without any person signing in.
According to Huntress, the credential works in every organization that has granted the app access to its Microsoft 365 account. Whoever holds that credential can sign in as the backup service to any of those accounts and inherit the access customers had already approved.
A single compromise at the vendor therefore reached customers of many different MSPs at once, which is why Microsoft has described the incident as a supply chain attack.
What Huntress found
Huntress, a cybersecurity company that monitors SMBs for signs of intrusion, confirmed unauthorized access to at least 162 Microsoft 365 tenants.
It says the stolen credential was used on October 15, between 06:13 and 08:34 UTC, to sign in as the backup application from 144.172.64[.]128, an address belonging to a hosting provider rather than the Microsoft cloud infrastructure the app normally operates from. The same address had been used on October 13 and 14 to try guessing passwords at four law firms, without success.
The sign-ins moved through customer accounts a few seconds apart in a fixed order, which the company says points to an automated script working from a target list.
The researchers also saw other ConnectWise applications, part of its Cloud Management product, give themselves administrator roles (mostly Exchange Administrator) in roughly 50 of the organizations Huntress monitors. The software signature on those events matches the one ConnectWise’s own apps use, which suggests the company’s automation rather than the attacker (but ConnectWise has not confirmed this).
In one case, the activity was clearly hostile. Hours before the main sweep, the ConnectWise Cloud Management app for Microsoft Teams made itself a global administrator and, within about five minutes, added new credentials to two other trusted applications in that account: “an MSP management application, and Huntress’s own application (Huntress Security Platform).”
Those credentials were set to remain valid until 2028, giving whoever created them a way back in that would survive the shutdown of ConnectWise’s apps.
The activity appears to be broader than the confirmed breaches. Huntress says it found nearly 1,000 Microsoft 365 accounts with sign-in attempts from the attackers’ address, more than 300 of them successful.

Remote attackers without privileges can exploit them to launch denial-of-service (DoS) attacks or gain code execution on NGINX systems with non-default configurations.

CVE-2026-93479 can also be mitigated by using named captures instead of unnamed captures and limiting their use to the block with the regex match.

구글은 AI 모델을 재학습하지 않고도 지시문과 도구 활용법, 메모리, 작업 절차 등을 스스로 개선해 에이전트의 성능을 높이는 오픈소스 프레임워크 ‘하네스²(Harness²)’를 온라인 아카이브를 통해 최근 공개했다.
하네스²는 AI 에이전트의 성능이 기반 모델뿐 아니라 모델을 둘러싼 실행 환경에도 영향받는다는 점에 주목했다. 여기서 하네스는 시스템 프롬프트, 가이드라인 및 안전 규칙, 메모리, 도구 활용 지침, 하위 에이전트, 스킬, 스크립트, 플러그인·미들웨어 등 파일 형태로 마운트되는 8가지 핵심 컴포넌트를 뜻한다.
기존 AI 성능 개선 방식은 모델을 재학습하거나 정답이 정해진 평가 데이터를 활용하는 경우가 많다. 하지만 실제 환경에서는 처음 접하는 작업이 계속 등장하고, 결과가 옳은지 자동으로 판정할 기준이 없는 경우도 많다. 하네스²는 이런 상황에서 정답을 알려주는 별도의 검증기가 없는 오픈월드 환경 속에서, 에이전트가 실제 작업 과정에서 드러난 행동 양상을 서로 비교(Propose-Probe-Compose)하는 대조적 검증 방식을 통해 실행 방식을 수정하도록 설계됐다.
핵심은 두 단계의 반복 개선 구조다. 첫 번째는 현재 작업에 맞춰 하네스를 수정하는 과정이다. 에이전트가 기본 설정으로 작업을 수행하면 개선 시스템이 두 가지 수정안을 제안한다. 하나는 계획 수립이나 도구 사용처럼 여러 작업에 공통으로 적용할 수 있는 문제를 겨냥하고, 다른 하나는 특정 분야의 지식이나 절차를 개선하는 데 초점을 맞춘다.
이후 두 수정안을 동일한 작업에 적용해 실행 결과를 비교한다. 개선 시스템은 실제 작업 과정에서 관찰된 차이를 바탕으로 효과가 확인된 변경 사항을 선택한다. 정답을 알려주는 별도의 검증기가 없어도 어떤 수정이 더 나은 결과를 냈는지 비교해 개선 방향을 정하는 방식이다.
두 번째 단계인 하네스 레벨에서는 한 작업에서 얻은 경험을 지속적 개선 라이브러리(LESSONS) 등에 기록해 다음 작업에 참고한다. 예를 들어 특정 도구를 사용하는 방법이나 작업 순서를 바꿨을 때 성능이 좋아졌다면, 그 경험을 이후 작업의 개선안에 반영하는 식이다.
다만 매번 수정된 설정을 그대로 이어서 사용하는 것은 아니다. 새 작업은 기본 하네스에서 시작하고, 이전 작업에서 축적한 경험을 참고해 필요한 개선안을 다시 제안한다. 이를 통해 특정 작업에만 맞춘 수정이 다른 상황에서 부작용을 일으키는 문제를 줄이려는 것이다.
구글 연구진은 전문 업무용 벤치마크 3종인 '워크버디 벤치(WorkBuddy-Bench)', '잡벤치(JobBench)', 하비의 'LAB'에서 하네스²를 평가했다. 'GLM-5'와 '제미나이 3.5 플래시'를 기반으로 여러 실행 환경을 조합해 시험한 결과, 한 차례의 개선만으로도 네 가지 모델·하네스 구성 모두에서 세 벤치마크의 성능이 향상됐다.
가장 큰 개선 폭은 GLM-5를 오픈코드(OpenCode)와 함께 사용한 구성에서 나왔다. 워크버디 벤치 점수가 기존 64.2점에서 75.7점으로 11.5점 상승했다. 잡벤치에서는 최대 4.5점, 법률 업무 평가인 LAB에서는 평가 항목별 통과율이 최대 11.8%포인트 높아졌다.
반면 모든 조합에서 개선 폭이 같지는 않았다. GLM-5와 '코덱스'를 조합하면 잡벤치 점수는 23.6점에서 24.8점으로 1.2점 오르는 데 그쳤다. 연구진은 개선 작업에 더 많은 예산을 투입해 수정안을 여러 차례 탐색하면 추가 성능 향상도 가능하다고 설명했다.
하네스²는 모델의 가중치를 변경하지 않고 실행 환경만 개선한다는 점에서 모델 재학습에 드는 비용과 부담을 줄일 수 있는 접근법이다. 구글은 이를 깃허브를 통해 오픈소스로 공개해 개발자들이 기존 모델과 에이전트 환경에 적용할 수 있도록 했다.
