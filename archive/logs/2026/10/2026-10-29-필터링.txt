[TITLE_KO] 앤트로픽의 미공개 AI 모델, 크롬·사파리·윈도우·리눅스의 결함을 연결해 실제 작동하는 익스플로잇 생성

[TOPIC] 모델, 보안
[SCORE] 9
[REASON] 앤트로픽 미공개 모델이 주요 OS 및 브라우저 익스플로잇 연쇄 개발
[BODY]
An unreleased Anthropic AI model found security flaws in Chrome, Safari, Android, Windows, and Linux and chained them into working proof-of-concept exploits, the company said in its latest report.
The exploits were built in the lab after the model was prompted, not seen in any real attack, and Anthropic reported every flaw to the vendor first, so all of them are already patched. One proof of concept opened the Calculator app on a stock Mac running Chrome within seconds of a page loading, with no further clicks.
Anthropic's Frontier Red Team described five chains in a research post. The strongest claim is not any single bug, but that one model found several separate flaws and combined them into a working exploit, something the company says has until now been the work of a few specialist teams. That capability claim rests on Anthropic's own account.
The patches and the fact that Apple and Google credit Anthropic and its Claude model for specific fixes can be verified with the vendors.
What a reader cannot check is how much of each chain the model built on its own. Anthropic says the work needed only "initial prompting" and "little human involvement," but it does not break down what a person did at each step, and it does not name the model beyond calling it an unreleased, internal research model.
For the one flaw with its own public record, the Windows bug, the record names no finder at all. Here are the five chains, what each would do, the condition each needs, and where the fix landed.
In the Chrome chain, the model used four separate flaws in turn. A malicious page first corrupted memory in V8, Chrome's JavaScript engine.
A second flaw escaped V8's memory sandbox and took control of the part of Chrome that renders the page. A race condition in a feature called CacheStorage then let that code read memory it should not reach and learn the layout of the more privileged browser process.
A final use-after-free bug in FedCM, Chrome's sign-in feature, let the exploit run code outside the sandbox entirely. Anthropic says it reported 62 flaws to Google that were assigned CVEs and fixed as of Chrome 156, all rated critical or high, including 13 sandbox escapes.
Google's own release notes credit "Xinyang Ge of Anthropic, assisted by Claude" for specific Chrome fixes, though not for all 62.
The Safari chain is different because it never runs code at all. It chains flaws to obtain full read and write access to the browser's memory, then changes a single value to turn off the same-origin policy, the rule that prevents one website from reading another's data.
With that rule off, a malicious page can read a user's history and cookies and send signed-in requests to other sites. Apple fixed the use-after-free at the center of the chain in iOS and iPadOS 26.5.2 and credits "Milad Nasr and Nicholas Carlini with Claude, Anthropic" for it.
The Windows chain is the one with an independent paper trail, and it is also the narrowest. It is a denial-of-service attack: a few network packets crash the machine, and repeating them keeps it down, but it does not run code or steal data. Anthropic describes the flaw as an out-of-bounds read in the Windows kernel's QUIC handling.
The public record for the bug it points to, CVE-2026-33096, instead names HTTP.sys, Windows' built-in web request handler, and rates it 7.5 out of 10. No open source ties those two descriptions together as the same component. The CVE record credits no finder, so Anthropic's authorship of this one rests on its own post.
As of late October, the U.S. government's vulnerability enrichment marked the flaw as not exploited, and it was not in the CISA catalog of known exploited bugs.
The Linux chain is the most serious in terms of impact: it runs commands as root over the network without a login. It needs the target server to be running a multipath TCP listener.

Nvidia releases all-in-one adaptable Nemotron 3.5 audio transcription and translation model
Nvidia Corp. today released a leaderboard-winning open artificial intelligence model for multilingual audio transcription and translation, along with an open data pipeline for fine-tuning Nemotron 3.5 Transcribe.
Traditional transcription AI models follow a workflow that detects speech, transcribes it, identifies and labels different speakers, then answers questions about the transcription. Transcribe does all of this in a single model pass and is capable of digesting and answering questions about 100 hours of audio, in 40 languages and can label up to eight speakers.
It’s an open-weight, 30-billion parameter mixture-of-experts model with 4 billion active parameters. That means it can fit on reasonably small hardware, though more powerful hardware lets it transcribe faster.
For its size, Transcribe punches way above its weight and it can run anywhere from the edge to the data center depending on compression. The model runs on a single Nvidia graphics processing unit, from a Jetson AGX Thor, an edge computer robot brain, or DGX Spark, a desktop AI supercomputer, all the way to a Blackwell data-center GPU. Nvidia said a Blackwell Server Edition GPU with NVFP4 precision and one-quarter model compression processes 100 hours of audio in under three minutes.
According to the company, Transcribe hits a high accuracy benchmark for getting words right, with 30.8% error rates out of the box, which can be reduced to 20.8% with careful prompting. Fine-tuned for specialized work, for example, on the Eka Care Indian medical speech benchmark, the model hit 11.8% word error rate, a substantial reduction.
Users can guide transcription analysis or ask questions with prompts. The same checkpoint can turn a recording into different outputs with separate prompts.
For example, a user could instruct the model with, “Transcribe the recording and label each speaker,” or “Translate this audio into English,” or “What decisions were made in this meeting?” or some combination. Users can also provide the model with important jargon or dialogue to help it better understand the conversation before transcribing, improving accuracy.
To build the model, Nvidia extended Granary v1 into Granary v2, the company’s massive open-source public multilingual speech AI dataset. Built with Nvidia NeMo Curator, v2 expands significantly on the previous generation of Granary. The public manifest covers 463,062 hours across 48 languages and 16 source corpora, up from 25 languages in Granary v1. These figures describe the dataset release, not Transcribe’s full training mixture or its sampling weights.
Granary v2 generates three transcripts for each recording in clean verbatim styles that can be requested from Transcribe with a prompt. One provides everything, including “ums” and “ahs.” Another reduces full wording to figures, such as spelling out numbers as symbols. A third eliminates filler words.
All that lets developers adapt transcription from different languages using the pipeline data into readable formats and fine-tune model outputs.
Transcribe is available as a Hugging Face demo, where developers can download a checkpoint and adapt it for domain expertise with fine-tuning.

이번 기술의 핵심은 AI 에이전트가 수행하려는 모든 작업에 대해 사용자에게 승인을 요청하는 대신, 별도의 AI 모델이 작업의 성격과 위험도를 판단해 일상적인 업무는 자동 승인하고 중요한 작업만 사람에게 확인받도록 하는 것이다.
기업에서 AI 에이전트의 활용이 확대되면 이메일 발송, 고객 정보 업데이트, 업무 요청 티켓 생성 등 다양한 작업이 자동으로 실행된다. 기존처럼 모든 작업에 사용자 승인을 요구하면 업무 처리 속도가 떨어질 뿐 아니라 반복적인 승인 요청에 익숙해진 사용자가 내용을 충분히 확인하지 않고 승인하는 문제가 발생할 수 있다.
AWS는 이러한 현상을 ‘승인 피로(Approval Fatigue)’로 보고, 불필요한 승인 절차를 줄이면서 실제로 중요한 작업에 사람의 주의를 집중하도록 스마트 승인을 설계했다.
스마트 승인에는 AI 에이전트와 별도로 작동하는 검토 모델인 ‘분류기(Classifier)’가 사용된다. 이 모델은 AI 에이전트가 실행하려는 작업을 사용자의 원래 요청과 비교해 자동 승인 여부를 판단한다.
예를 들어 사용자가 AI 에이전트에게 업무 자료를 정리하고 관련 기록을 업데이트하도록 요청한 경우, 검토 모델은 각 작업이 사용자의 지시 범위에 포함되는지 평가한다. 자동 승인이 가능한 일상적 작업은 별도의 확인 절차 없이 진행되지만, 영향이 큰 작업은 사용자에게 전달해 검토받는다.
특히 AWS는 조직 외부로 콘텐츠를 전송하거나 시스템 접근 권한을 변경하는 작업, 콘텐츠 삭제, 결제 실행, 사용자가 요청한 범위를 벗어나는 행동 등을 사람의 검토가 필요한 주요 사례로 제시했다.
이는 AI 에이전트가 단순히 업무를 수행하는 데 그치지 않고, 실행하려는 행동이 사용자 의도와 조직의 관리 기준에 부합하는지 별도의 AI 검토 과정을 거치도록 했다는 점에서 의미가 있다.
스마트 승인은 기존 보안 정책을 변경하거나 AI 에이전트에 새로운 권한을 부여하는 기술은 아니다. AWS에 따르면 조직이나 사용자가 이미 거부하도록 설정한 작업은 스마트 승인 기능을 통해서도 실행할 수 없다. 새로운 접근 권한을 자동으로 부여하는 것도 불가능하다.
스마트 승인이 적용되는 대상은 사용자가 매번 승인을 요청하도록 설정한 작업으로 제한된다. 이 가운데 검토 모델이 자동 승인해도 된다고 판단한 작업만 별도의 사용자 확인 없이 실행된다.
자동 승인의 범위 역시 검토를 통과한 개별 작업으로 한정된다. 하나의 작업이 승인됐다는 이유로 이후 유사한 작업이나 다른 시스템에 대한 접근까지 포괄적으로 허용되는 것은 아니다.
검토 과정에서 오류가 발생하거나 정해진 시간 안에 판단을 완료하지 못한 경우에도 시스템이 임의로 작업을 승인하지 않는다. 해당 작업은 사용자에게 전달돼 직접 확인을 받도록 설계됐다. 이러한 구조는 AI가 승인 절차의 일부를 자동화하더라도 최종적인 권한 체계와 통제 기준은 사람이 설정한 정책에 따르도록 하는 방식이다.
기업 관리자를 위한 통제 기능도 제공된다. 스마트 승인은 기본적으로 모든 사용자에게 활성화되지만, 관리자는 사용자별 맞춤 권한 설정을 통해 해당 기능을 사용할 수 있는 대상을 관리할 수 있다. 개별 사용자는 채팅 옵션에서 스마트 승인을 비활성화할 수 있으며, 일반 대화뿐 아니라 예약 실행되는 AI 에이전트 작업에도 이 설정을 적용할 수 있다.
감사 추적 기능도 포함됐다. AWS는 클라우드 감사 서비스 ‘AWS 클라우드트레일(AWS CloudTrail)’을 통해 스마트 승인이 수행한 개별 작업 검토 기록과 사용자의 기능 설정 변경 내역을 저장한다고 설명했다.
이를 통해 기업은 어떤 작업이 자동으로 승인됐는지, 언제 사용자 검토로 전달됐는지, 승인 설정이 어떻게 변경됐는지 확인할 수 있는 감사 기록을 확보하게 된다. 스마트 승인은 아마존 퀵의 에이전틱 AI 기능이 지원되는 모든 AWS 리전에서 제공된다.

[TITLE] After Passkeys, FIDO Turns to Digital Identity and AI Transaction Authentication
[TITLE_KO] 패스키 이후, FIDO는 디지털 신원 및 AI 거래 인증으로 전환
[LINK] https://it.chosun.com/news/articleView.html?idxno=2023092173017

[TOPIC] 에이전트

[REASON] FIDO 얼라이언스의 차세대 표준으로 AI 에이전트 결제 및 거래 인증 추진
[BODY]
The FIDO (Fast IDentity Online) Alliance, an international organization that develops online authentication standards, has identified digital identity verification and authorization for artificial intelligence (AI) agent transactions as its next major priorities following the widespread adoption of passkeys.
As AI agents increasingly conduct transactions on behalf of people, common standards are needed to verify the scope of authority granted by users and determine who should be held responsible when problems arise.
The FIDO Alliance outlined these priorities during the closing keynotes of Authenticate U.S. 2026, its annual authentication technology conference, held in Carlsbad, California, on October 21 (local time).
The three-day event, held from October 19 to 21 under the theme “New Frontiers,” explored the growing adoption of passkeys and developments in digital identity, payments and AI agent authentication.
The final day's program featured presentations by Mastercard and the FIDO Alliance, followed by a panel discussion involving representatives from Visa, PayPal and other payment industry organizations.
“Passkeys have shown what this industry can achieve when we align on a common vision, standards, certification and a consistent user experience,” said Andrew Shikiar, CEO of the FIDO Alliance. “Now we need to do the same for digital credentials.”
Mastercard Highlights Passkey Success, New Authentication Needs for AI Purchases
Jonathan Grossar, Senior Vice President at Mastercard, said passkeys are improving both security and convenience in online payments.
According to Mastercard, authentication completion rates among consumers who have already enrolled payment passkeys exceed 95%.
By allowing customers to approve payments using fingerprint or facial authentication, much like unlocking a smartphone, passkeys reduce the inconvenience of entering passwords or switching to banking apps.
Mastercard also presented Digital Payment Credentials (DPC) as a next step in payment authentication.
Under the proposed approach, payment credentials issued by banks or other institutions would be stored in smartphone wallets. Consumers could review transaction details, including the amount and merchant, before approving payments through biometric authentication.
Mastercard was testing related prototypes, while some features remained under development as part of ongoing standardization efforts.
Authentication requirements become more complex when AI agents purchase products on behalf of consumers.
Grossar described a scenario in which a consumer instructs an AI agent to purchase a T-shirt from a particular brand for less than $100.
If the agent later finds a suitable product and completes the purchase, the payment system must be able to verify that the transaction was authorized, even though the consumer is not present at checkout.
To address this challenge, Grossar introduced Verifiable Intent, a technology designed to connect a user's identity, purchase instructions and the actions subsequently taken by an AI agent.
“We now need to prove not only that a transaction was authorized, but also that what the agent did was consistent with what the user intended,” Grossar said.
Mastercard is working with the FIDO Alliance on related standardization efforts.
EMVCo, a technical standards organization involving major international payment networks including Visa and Mastercard, is also developing common specifications for AI-driven payments.
FIDO Alliance: “Trust Is Not a Feature, It Is an Outcome”
Nishant Kaushik, Chief Technology Officer (CTO) of the FIDO Alliance, warned that technically secure authentication does not necessarily guarantee a trustworthy service.
“Trust is not a feature. It is an outcome,” Kaushik said.
He explained that even when passkeys or digital wallets function correctly, users may still experience unfavorable outcomes.

MS는 "목표는 개별 모델의 실행 비용을 낮추는 것보다 더 크다"며 "보안 담당자가 신뢰하는 성능을 유지하면서 전체 취약점 탐지 시스템의 효율성을 높이는 것"이라고 설명했다.
MDASH는 100개 이상의 전문 보안 에이전트와 다양한 AI 모델을 조합하는 멀티모델 구조를 채택했다. 예를 들어 MAI-사이버-1-플래시는 전체 보안 작업의 약 90%를 처리하고, 난도가 높은 나머지 10%의 작업에는 GPT-5.4를 활용하는 방식이다.
MAI 사이버는 최근 30일 동안 사용자 채택률이 두 배로 증가해 수백 곳의 고객사가 수행한 수천 건 이상의 스캔에서 전체 MDASH 스캔의 약 50%를 차지하고 있다. 이번 신모델은 기존 작업 환경을 유지하면서 비용 효율을 높이려는 고객을 겨냥했다.
MAI 사이버 1.1 플래시는 이용 자격을 확인받은 고객에게 MDASH를 통해 제공된다. MS는 책임 있는 사용을 지원하기 위해 명확한 이용 정책과 지속적인 모니터링 등 안전장치도 적용했다고 밝혔다.

[TITLE] Introducing the Microsoft Copilot harness in Foundry Agent Service
[TITLE_KO] 파운드리 에이전트 서비스, 마이크로소프트 코파일럿 하네스 도입
[LINK] https://devblogs.microsoft.com/foundry/microsoft-copilot-harness-in-foundry/
[PUBLISHED] 2026-10-29 01:45 KST
[SOURCE] Microsoft Foundry
[TOPIC] 에이전트, 모델
[SCORE] 8
[REASON] MS의 통합 에이전트 제어 프레임워크 코파일럿 하네스 출시
[BODY]
A model can reason about a task. Completing that task takes more: the right context, tools, execution environment, and controls, and an agent loop that brings them together.
Microsoft’s unified harness strategy brings a shared execution foundation across our agent experiences while preserving customer choice. In Microsoft Foundry, that means you can choose a supported model and decide how much of the agent stack to build yourself, without having to assemble every layer around it.
Today, we’re introducing the Microsoft Copilot harness in Foundry Agent Service in public preview. It gives developers a fully managed way to build agents that reason, use tools, and complete complex, long-running tasks. It’s our opinionated approach to helping agents complete complex work. We’re also announcing general availability of long-running resilience for hosted agents. Together, these capabilities help developers build more reliable agents for complex, long-running workflows.
Build on a managed agent harness
Many teams building agents end up implementing the same execution machinery: coordinating model and tool calls, maintaining working context, managing files, and deciding how to continue when a task requires more than one step. That work matters, but it isn’t usually what differentiates your application.
The Copilot harness gives you a managed execution system for agents you define declaratively in Foundry Agent Service. Microsoft runs the agent loop and sandbox; you bring the knowledge, procedures, and tools that make the agent yours.
The public preview brings together four building blocks:
- Reusable skills. Package instructions, scripts, and supporting resources into procedures an agent can apply across tasks.
- Connected tools. Connect supported Foundry and Model Context Protocol (MCP) tools, with explicitly configured authentication and approvals.
- Execution and delegation. Let agents work with files and code, and delegate bounded tasks to built-in subagents while the main agent coordinates the result.
- Source-controlled agent definitions. Create and test in Foundry, or manage agent definitions and supporting resources alongside your application code.
The harness manages working context as tasks develop and coordinates model and tool steps toward a requested outcome, within configured limits and policy boundaries. You choose a supported Foundry model without having to rewrite the orchestration around it.
That lets your team focus on improving the agent’s expertise and evaluating its results.
“With the Microsoft Copilot harness in Foundry Agent Service, we had a solution running in less than a week, allowing us to focus on design and capabilities instead of the infrastructure underneath it. That speed will help us bring our vision of AI that runs within and alongside our products to market faster.”
— Chris Evans, Chief Technology Officer, Confluence Technologies
“The Microsoft Copilot harness in Foundry Agent Service gives Fashable a powerful foundation for turning complex sourcing processes into governed, measurable agent workflows. We see the opportunity to generate complete tech packs from our knowledge and templates, while extending our A2A sourcing network beyond digitally connected suppliers through email and voice. Most importantly, we can equip brand and manufacturer agents with deeper knowledge and new capabilities to work across sourcing and negotiation without automating away accountability: agents can discover, engage and calculate, while commercially binding decisions remain under human control.”
— Orlando Ribas Fernandes, CEO, Fashable
Create a Copilot harness agent with a reusable skill
Consider an agent that researches a topic, analyzes supporting data, and produces an evidence-backed brief. The same pattern can support market research, operational analysis, or an internal planning workflow: instructions define the outcome, skills define the method, and tools provide access to evidence.
