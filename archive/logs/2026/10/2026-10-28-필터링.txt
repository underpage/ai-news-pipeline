Security protections on GitHub were not breached but individual customer protections were, and autonomous coding agents played a role.

A security research firm reported Monday that it had identified breaches of 42 third-party GitHub repositories in which attackers had deployed payload blobs large enough “to evade the GitHub search and API paths normally used to find this kind of compromise.”
The report from JFrog Security Research said the victimized repositories contained execution hooks for AI coding assistants and IDEs, along with polymorphic wrappers as large as 13.7MB that “all decoded to the same hidden CI-publisher payload. The campaign’s attacker-owned repository also operates as an active encrypted data sink, receiving snapshot envelopes, and the attack leveraged a new camouflage: a compiled native addon that contains no payload of its own, and instead decrypts a file named .napi_cache at runtime to reveal the real one.”
JFrog said that the investigation also uncovered account hijacks, forged commit timelines, short-lived publishing branches and exposed npm credentials. Shellpanel artifacts in the same hijacked owner cluster link this GitHub victim infrastructure to previously reported GitHub Actions exploitation of internet-facing cPanel systems.
“During October 21 our scanners alerted us about shai-hulud packages found in the npm ecosystem,” JFrog wrote. “SafeDep’s October 22 analysis first documented the npm/package side of this activity and decoded event-bus-lite-testmetest@0.0.1. SafeDep described the payload as Miasma-family while explicitly noting uncertainty about its lineage.”
SafeDep had originally thought that the packages in the campaign it had discovered, dubbed testmetest, were merely a test by the threat actor, but this week discovered the compromises of existing repos with malicious content.
The JFrog post also focused on the npm chain implications.
“The npm chain provides the link into the broader operation. Malicious testmetest releases used a binding.gyp command expansion to execute index.js during installation, even though the packages did not declare a conventional install script,” the post said. “The loader applied a per-build Caesar transformation to a character-code array, decrypted an AES-128-GCM stage and located or downloaded Bun 1.2.18. Depending on the build, the decrypted payload was piped to bun run - or written to a temporary .b-*directory and removed after execution. The full npm payload collected credentials, poisoned repositories and CI configuration, and propagated through package registries.”
Those attacker-controlled repositories served as sources of cover projects for matching npm packages, JFrog said.
“Malicious releases delivered the npm worm, which stole GitHub and npm credentials that could provide access to third-party repositories. Within hijacked repositories, the campaign left smoke-test placeholders or armed payloads,” the researchers wrote. “Decoding the armed ci.js files exposed publishers designed to run through GitHub Actions and use npm tokens or trusted publishing to produce further malicious testmetest releases, feeding package delivery back into repository compromise.”
Defensive recommendations
JFrog’s post recommended a variety of defensive tactics for detection and mitigation of these attacks, including that CISOs “should treat installation of a full-worm version as a host compromise.” It also suggested that users should revoke and rotate all GitHub, GitLab, npm, PyPI, RubyGems, cloud, SSH, Vault, Kubernetes and AI-provider credentials, as well as auditing “all repositories accessible to affected identities for .github/init.js, .claude/settings.json, .gemini/settings.json, .cursor/mcp.json, .cursor/rules/setup.mdc, .vscode/tasks.json, unexpected composer.json or Makefile execution hooks, and skip-checks:true commits.”

구글 클라우드는 28일(현지시간) 구글 딥마인드(Google DeepMind)의 차세대 로봇 추론 모델 '제미나이 로보틱스 엠바디드 추론 2(Gemini Robotics Embodied Reasoning 2, 이하 ER 2)'를 공개 프리뷰(Public Preview)로 제공한다고 밝혔다. 이번 공개는 구글이 앞서 공개한 제미나이 로보틱스 2(Gemini Robotics 2)의 핵심 추론 모델을 실제 기업 환경에서 개발·평가·배포할 수 있도록 확대한 것이다.
ER 2는 로봇의 고차원적인 판단을 담당하는 일종의 '두뇌' 역할을 수행한다. 영상과 음성, 텍스트 정보를 종합해 주변 상황을 이해하고 작업 순서를 계획하며, 로봇의 하위 동작 모델과 하드웨어 제어 인터페이스를 연결해 실제 행동으로 이어지도록 설계됐다.
특히 수백 번의 판단이 필요한 수분 단위의 장기 작업을 수행하고, 작업 중 예상하지 못한 상황이 발생하면 진행 상태를 재평가해 다음 행동을 수정할 수 있다. 기존의 고정된 명령이나 사전 작성된 작업 절차에 의존하는 로봇 제어 방식에서 벗어나 상황에 따라 계획을 조정하는 에이전틱 피지컬 AI(Agentic Physical AI)를 구현하는 데 초점을 맞췄다.
영상 속 결정적 순간 91.3% 정확도로 식별...작업 성공 여부 스스로 판단
ER 2의 핵심 기술은 공간과 시간의 관계를 함께 분석하는 시공간 추론(Spatio-temporal Reasoning)이다.
로봇이 실제 환경에서 안정적으로 작업하려면 물체의 위치를 파악하는 것뿐 아니라 시간이 흐르면서 상황이 어떻게 변화하는지 이해해야 한다. 예를 들어 액체를 용기에 따르는 작업에서는 액체가 어느 정도 채워졌는지 판단하고, 적절한 순간에 동작을 멈춰야 한다.
ER 2는 연속적인 영상 데이터를 분석해 이러한 핵심 사건이 발생하는 시점을 식별한다. 구글이 공개한 평가 결과에 따르면 ER 2는 영상에서 중요한 사건이 발생한 프레임을 91.3%의 정확도로 찾아냈으며, 실제 사건 시점과 예측 시점 사이의 평균 절대 오차는 0.96초를 기록했다.
또한 구글은 해당 작업에서 여러 대형 모델 범주와 비교해 실행 속도가 4배 빠르고, 연산 비용도 더 낮다고 설명했다. 다만 발표자료에는 비교 대상 모델별 세부 수치가 제시되지 않았다. 이 모델은 작업 진행 상태를 성공과 실패 같은 이진 상태뿐 아니라 여러 범주나 연속적인 점수로 평가할 수 있으며 이를 통해 로봇은 작업이 정상적으로 진행되고 있는지 확인하고, 특정 단계에서 문제가 발생하면 전체 작업을 처음부터 다시 시작하지 않고 필요한 부분을 수정하거나 재시도할 수 있다.
시각적 정보 해석 능력도 강화했다. ER 2는 원형 계기판과 액면 표시창, 디지털 디스플레이, 선형 눈금, 자, 액체 온도계 등 10종 이상의 계측기 범주에서 시각적으로 표시된 값을 읽고 해석할 수 있다. 이는 별도의 디지털 연결 인터페이스가 없는 기존 산업 설비에서도 로봇이 계기판이나 화면을 직접 확인하면서 작업할 수 있는 가능성을 보여준다.
로봇팔·사족보행 로봇·휴머노이드까지…하나의 추론 모델로 협업
ER 2는 특정 로봇 하드웨어에 종속되지 않는 범용 추론 계층을 지향한다. 고정형 산업용 로봇팔, 바퀴형 이동 로봇, 사족보행 로봇, 휴머노이드 등 다양한 형태의 로봇에서 공통의 고차원 추론 모델을 활용하도록 설계됐다.
개발자는 시각·언어·행동 모델(Vision-Language-Action, VLA)이나 이동 제어 응용프로그램 인터페이스(API), 사용자 정의 기능 등을 도구로 등록하고 ER 2가 필요에 따라 호출하도록 구성할 수 있다. 이러한 구조에서는 AI가 작업의 목적과 순서를 판단하고, 실제 관절이나 구동부의 세부 움직임은 하위 제어 모델과 하드웨어 인터페이스가 담당한다.
여러 로봇이 동일한 작업 공간을 이해하고 역할을 분담하는 다중 로봇 협업도 지원한다. 예를 들어, 서로 다른 형태의 로봇이 공동 작업 환경에 대한 의미적 이해를 공유하고, 작업을 나눠 수행하거나 중간 결과물을 다른 로봇에 전달하는 방식이다. 단일 로봇만으로 수행하기 어려운 복합적인 업무를 여러 로봇이 연결된 작업 흐름으로 처리하도록 지원한다.
자연어 기반 상호작용도 주요 기능이다. 작업자는 전문적인 로봇 제어 명령어를 사용하지 않고 일상적인 언어로 작업을 지시할 수 있다. 로봇은 명령을 해석해 이동 및 조작 API를 호출하고, 작업을 수행하는 동안 자신의 접근 방식을 설명할 수 있다. 아울러, 작업 도중 운영자가 새로운 지시를 내리면 이를 반영해 행동을 조정하는 것도 가능하다.
구글 클라우드에서 시뮬레이션부터 학습·배포까지 통합
구글은 ER 2를 단순한 로봇 AI 모델이 아니라 기업용 피지컬 AI 개발·운영 체계의 핵심 구성요소로 제공한다. 기업은 제미나이 플랫폼에서 로봇의 행동을 시뮬레이션하고, 학습 데이터를 준비하며, 실제 로봇에 적용할 AI 워크플로를 개발할 수 있다.
먼저 엔비디아(NVIDIA)의 아이작 심(Isaac Sim)과 무조코 워프(MuJoCo-Warp) 같은 시뮬레이션 환경을 활용해 실제 하드웨어를 움직이기 전에 로봇의 행동을 검증할 수 있다.
멀티모달 AI 모델로 다양한 가상 상황을 생성하거나 작업 공간의 이미지에 자동으로 주석을 부여하는 기능도 활용할 수 있다. 학습 단계에서는 ER 2의 공간 지시(Spatial Pointing), 핵심 순간 탐색(Moment Finding), 작업 진행 상태 분류 기능을 이용해 로봇 시연 영상을 정리하고 학습 데이터를 구축한다.
관련 데이터는 구글 클라우드 스토리지(Cloud Storage)와 빅쿼리(BigQuery)에 저장·관리할 수 있으며, 개발자는 제미나이 플랫폼과 구글 쿠버네티스 엔진(Google Kubernetes Engine, GKE), 클러스터 디렉터(Cluster Director)를 통해 맞춤형 VLA 모델을 학습시킬 수 있다.
운영 단계에서는 기업용 신원 및 접근 관리(Identity and Access Management, IAM)와 보안 제어, 함수 호출 기능을 활용해 로봇 에이전트의 실행 환경을 관리한다.
실시간 응답이 중요한 동시적 위치 추정 및 지도 작성(Simultaneous Localization and Mapping, SLAM)과 경로 계획 등은 구글 분산 클라우드(Google Distributed Cloud)를 통해 공장 현장과 같은 로컬 환경에서 처리하도록 구성할 수 있다.
로봇 운영 과정에서 발생하는 원격 측정 데이터는 빅쿼리로 전송해 분석할 수 있다. 이러한 구조는 고차원 추론과 데이터 관리, 모델 학습에는 클라우드 자원을 활용하면서 지연시간에 민감한 일부 제어 기능은 현장 인프라에서 처리하도록 역할을 나누는 방식이다.
보스턴다이내믹스·Arm·싱가포르 연구기관 등 활용 가능성 제시
구글은 이번 발표에서 로봇 제조와 산업용 AI, 반도체, 연구 자동화 분야의 협력 사례도 소개했다. 보스턴다이내믹스(Boston Dynamics)는 사족보행 로봇 스팟(Spot)의 산업 현장 점검에 영상 기반 AI 분석을 활용하는 가능성에 주목했다.
마르코 다 실바(Marco da Silva) 보스턴다이내믹스 스팟 사업부 부사장 겸 총괄은 “영상은 점검의 가능성을 바꾼다”며 “스팟이 특정 순간에 정상 여부를 확인하는 것을 넘어 AI 모델을 영상에 적용할 수 있게 되면서 완전히 새로운 가능성이 열리고 있다”고 설명했다.
피지컬 AI 데이터 및 기술 개발 기업 딥리치(DeepReach)의 공동창업자 겸 최고기술책임자(CTO) 크리스 리우(Chris Liu)는 ER 2가 작업 기록을 정확하게 이해해 모델 학습에 필요한 핵심 데이터를 더욱 빠르고 대규모로 찾아내는 데 도움을 준다고 밝혔다.

Cybersecurity researchers have disclosed details of three cyber attacks targeting organizations in Japan in which artificial intelligence (AI) was a key element, either in the driving seat or to assist a human operator.
TrendAI, which analyzed three exposed server environments used by threat actors to conduct the malicious cyber operations, described them as distinct from previously published attacks that have leveraged ARTEX, an autonomous AI penetration testing framework, to single out entities in South Korea and Japan.
"These environments held reconnaissance and attack tools, scripts, target lists, results, logs, and command histories," security researchers Bakuei Matsukawa and Joseph C Chen said. "They ranged from workspaces used largely by hand by skilled operators to AI-agent platforms that automated the entire workflow, including command and control."
The first of the three attacks has been found to abuse CyberStrikeAI, another open-source penetration testing tool that was previously put to use in an attack campaign targeting Fortinet FortiGate appliances. The activity was concentrated in a short period in October 2026.
The AI-driven activity leverages the offensive security tool to automate various aspects of the attack lifecycle into a repeatable workflow, beginning with reconnaissance and vulnerability discovery and validation, and exploitation, to command-and-control (C2), persistence, data exfiltration, and automated reporting.
This involves delegating the work among 44 agents to handle various aspects of the attack, while also enabling the generation of forms and fake login pages in the Japanese language.
"In a short period, at least 19 identifiable organizations, including at least 16 in Japan, were subjected to validation activity," Trend Micro's enterprise security division said. "Each had a report in the same format and an index of evidence. These were outputs of a structured process run by the platform, rather than ad hoc notes left by an operator."
The second case has been characterized as a human-led attack with assistance from a large language model (LLM) to accelerate planning and tool development. Analysis of the infrastructure and artifacts indicates that the campaign is also designed to target AI workflow platforms and inference services with an aim to obtain large amounts of inference capacity at low cost.
One of the intrusions is said to have targeted a geographic information system (GIS) server exposed with default credentials, resulting in the theft of cadastral and commercial records, Windows credentials, and email data. The entire campaign lasted for 24 days in August and September 2026.
The third instance is where the AI's role has been found to be confined to developing the operator's tools and scripts, suggesting a limited role played by the technology in a series of campaigns designed to target edge devices from Cisco, Citrix, F5, and Yamaha using published vulnerabilities, management functions, or credentials present in configuration files.
The threat actor is estimated to have run at least six campaigns from January to October 2026, opportunistically striking exposed VPN devices and WebLogic servers. "The operator was experienced, with established practices for automation and evidence management," the researchers said.
There is currently no evidence at this stage that suggests these three incidents share an operator. It's also unknown if the attacks have targeted other regions and what AI models are being used to pull off the attacks.
That said, the attacks involving these threat actors are not restricted to Japan and neighboring countries like South Korea. The operator behind the first case has targeted organizations in Taiwan and Hong Kong, while the third case featured organizations in the U.K., France, Italy, Qatar, and Colombia in its WebLogic discovery lists.
"AI has increased the attackers' workforce, but the work still consists of looking for unlocked doors," TrendAI said.

[TITLE] 구글, 가상세계 보면서 새 명령 ‘지니4’ 공개
[LINK] https://it.chosun.com/news/articleView.html?idxno=2023092172944

구글이 글로 지시하면 눈앞의 가상세계를 실시간으로 바꿀 수 있는 인공지능(AI) 모델을 선보였다. 사용자는 AI가 만든 공간을 탐색하며 날씨를 바꾸거나 새로운 인물을 추가할 수 있다. 장면에 맞는 음악과 주변 소음, 등장인물의 대화도 생성한다.
27일(현지시각) 테크크런치에 따르면 구글 딥마인드는 가상 환경을 생성하고 사용자 입력에 따라 변화를 구현하는 ‘월드 모델’ 지니4를 연구용 미리보기로 공개했다.
핵심은 가상세계가 펼쳐지는 도중에도 글로 지시해 장면을 바꿀 수 있다는 점이다. 날씨나 화면을 바라보는 각도를 조정하고 사람과 사물을 추가할 수 있다. 결과물을 만든 뒤 다시 제작을 요청하는 대신, 눈앞의 장면을 수정하며 탐색하는 방식이다.
화면은 전작보다 실제 풍경에 가까워졌고 소리도 더해졌다. 배경음악과 환경 소음뿐 아니라 상호작용에 따른 대화까지 생성한다. 사물의 움직임과 등장인물의 행동도 자연스럽게 개선했다는 설명이다.
같은 장면의 설정을 일관되게 유지하는 시간은 최대 2분이다. 지난해 공개한 지니3의 두 배로 늘었다. 사용자가 장면을 바꿔가며 가상 환경을 탐색할 수 있는 시간이 길어진 셈이다.
구글은 게임과 교육, 로봇 분야에서 활용 가능성을 보고 있다. 교육에서는 역사적 장면을 담은 그림 속으로 들어가 등장인물에게 당시 사건을 묻는 방식 등을 구상하고 있다. 다만 실제 교육 서비스로 구현된 기능은 아니다.
초기 시험 이용자들은 영화 제작 과정에도 주목했다. 촬영에 앞서 장면 구성을 짜거나 아이디어를 검토할 때 배경과 시점을 바꿔가며 결과를 빠르게 확인할 수 있기 때문이다. 구글 딥마인드의 디에고 리바스 엔지니어는 아이디어를 신속하게 시험하고 창작 흐름을 유지해야 하는 단계에서 실시간 기능이 유용하다고 설명했다.
구글의 AI 모델 제미나이와 연동도 강화했다. 제미나이가 작업 순서를 계획하고 생성된 화면을 점검하면 지니4가 이를 가상 환경으로 구현한다.
로봇 분야 연구에서는 ‘제미나이4 아르곤’이 작업을 단계별로 나누고 지니4가 그 과정을 실시간으로 시뮬레이션했다. 실제 로봇을 움직이기 전 가상 환경에서 동작을 시험할 수 있는지 살펴본 실험이다.
아직 해결해야 할 문제도 있다. 실행 시간이 길어지면 사물의 모습이나 세부 표현이 달라질 수 있다. 장면에 맞는 정확한 소리를 생성하고 화면 속 글자를 읽기 쉽게 구현하는 것도 과제다. 구글은 개발 초기 단계로, 최종 서비스 형태도 확정되지 않았다고 밝혔다.
경쟁사들도 월드 모델 개발에 속도를 내고 있다. 런웨이는 앞서 사용자 입력에 반응하고 음향을 생성하는 ‘GWM 월즈2’를 공개했다. AMD는 월드랩스 인수를 추진하고 있으며, 리비안은 자율주행 시험 기술을 확보하기 위해 서드디멘션을 인수했다.
지니4는 현재 구글이 선정한 시험 이용자에게 제공된다. 향후 수주 안에 가상세계 생성 도구 ‘프로젝트 지니’를 통해 구글 AI 울트라 구독자에게도 제공할 예정이다. 제미나이 API와 구글 AI 스튜디오의 사전 이용 파트너로도 대상을 넓힌다는 방침이다.

The U.S. Cybersecurity and Infrastructure Security Agency (CISA) has added two critical PHP vulnerabilities collectively tracked as PHP2Shell to its catalog of actively exploited security flaws.
Threat actors without privileges can exploit the two security issues (CVE-2026-109618 and CVE-2026-109619) in high-complexity attacks to gain remote code execution (RCE) on unpatched systems.
The PHP security team patched the two flaws on Wednesday, October 21, one day after urging security teams to install the security updates as soon as they became available.
Although details on the PHP2Shell security flaws (including the CVE IDs and mitigation measures shared with critical infrastructure providers) leaked and some proof-of-concept (PoC) exploits were published online before patches went live, the PHP security team said that none were functional.
Multiple cybersecurity firms (including Cloudflare, Amazon, Hadrian, watchTowr, Previdian, and Patchstack) also detected widespread exploitation attempts before public disclosure, but they all tagged them as unsuccessful.
Amazon Threat Intelligence security researchers also said that attackers began targeting the PHP2Shell vulnerabilities four days before security patches were released.

[REASON] 에이전트 협업용 코드 저장소 플랫폼 등장
[FIELD] AI 에이전트
[BODY]
풀 리퀘스트 대신 AI 평가 기반 ‘트레일’ 도입, 코드 한 줄씩 검토하지 않고도 병합...깃허브보다 최대 89배 빠른 코드 푸시·AI 메모리로 토큰 71% 절감
인공지능(AI) 코딩 에이전트가 소프트웨어 개발의 중심으로 떠오르면서, 개발자가 직접 코드를 작성하고 검토하던 기존 개발 플랫폼의 구조에도 변화가 시작됐다. 깃허브(GitHub)의 전 최고경영자(CEO) 토마스 돔케(Thomas Dohmke)가 설립한 엔타이어(Entire)가 AI 에이전트와 인간 개발자의 협업을 위해 설계된 새로운 개발 플랫폼을 공개하며 깃허브에 도전장을 내밀었다.
엔타이어는 26일(현지시간) AI 에이전트와 인간이 함께 소프트웨어를 개발하도록 설계한 독립형 '깃 포지(Git Forge)'를 출시했다. 깃 포지는 소스코드 저장소 관리와 코드 검토, 협업 등을 지원하는 개발 플랫폼으로, 엔타이어는 AI 에이전트가 생성하는 대량의 코드 변경 사항을 신속하게 평가하고 병합하는 데 초점을 맞췄다.
이번 플랫폼의 핵심은 기존 소프트웨어 개발에서 널리 사용되는 풀 리퀘스트(Pull Request)를 새로운 코드 검토 방식인 ‘트레일(Trails)’로 대체한 것이다.
기존 풀 리퀘스트는 개발자가 변경한 코드의 차이점을 확인하고 검토한 뒤 병합하는 방식이다. 반면 트레일은 AI 에이전트가 코드를 푸시할 때마다 다양한 평가를 수행하고, 그 결과를 개발자가 한눈에 확인할 수 있도록 제공한다.
엔타이어는 이를 항공기 조종사의 헤드업 디스플레이에 비유했다. 개발자는 코드 변경 내역뿐 아니라 작업의 목적, 에이전트 실행 기록, 평가 결과를 종합적으로 확인할 수 있다. AI 에이전트는 평가 과정에서 발견된 문제를 반복적으로 수정하고, 개발자는 그 진행 상황을 검증한다. 모든 평가 기준이 충족되면 코드의 모든 줄을 직접 확인하지 않고도 병합할 수 있도록 설계됐다.
평가 데이터는 엔타이어 웹 인터페이스와 오픈소스 명령줄 도구인 ‘엔타이어 CLI(Entire CLI)’를 통해 확인할 수 있다.
코드 저장소의 처리 속도도 주요 차별화 요소다. 엔타이어는 깃(Git)과 호환되는 새로운 소스코드 관리 서버를 기반으로 분산형 깃 호스팅 서비스를 구축했다. 회사 측에 따르면 코드 푸시 속도는 깃허브보다 최대 89배, 커서 오리진(Cursor Origin)보다 최대 6배 빠르다.
개발자는 미국, 유럽연합(EU), 인도, 호주 등 원하는 지역에서 비공개 저장소를 생성하거나 기존 저장소를 이전해 호스팅할 수 있다. 이는 AI 에이전트의 빈번한 코드 변경 요청을 처리하는 동시에 데이터 저장 지역에 대한 선택권을 제공하기 위한 구조다.
AI 코딩 에이전트가 이전 작업 내용을 기억하고 재활용하도록 지원하는 ‘지속적 메모리(Continuous Memory)’ 기능도 도입했다.
이 기술은 에이전트의 작업 세션을 깃 저장소와 동기화해 과거 작업 기록과 프롬프트를 검색하고 활용할 수 있도록 한다. 핵심 구성 요소는 코드베이스의 관계를 파악하는 ‘코드베이스 그래프(Codebase Graph)’와 이전 에이전트 세션을 장기 기억으로 전환하는 ‘에이전트 두뇌(Agentic Brain)’다.
엔타이어에 따르면 코드베이스 그래프를 활용하면 에이전트가 필요한 정보를 더 빠르게 찾을 수 있으며, 토큰 사용량을 최대 71%까지 줄일 수 있다. 에이전트 두뇌는 과거 작업과 오류 해결 과정을 재활용해 동일한 실수를 반복하지 않도록 지원한다.
소프트웨어 빌드와 테스트를 자동화하는 지속적 통합(CI) 환경도 강화했다. 엔타이어는 빌드카이트(Buildkite), 디포(Depot)와 협력해 기존 깃허브 액션스(GitHub Actions) 기반 작업 흐름을 새로운 플랫폼으로 이전할 수 있도록 지원한다.
개발자는 빌드카이트의 변환 도구나 디포 CI를 활용해 기존 워크플로를 전환할 수 있다. 이후 코드가 푸시될 때마다 자동으로 빌드와 테스트가 실행되고, 결과는 트레일에 반영된다.
토마스 돔케 엔타이어 CEO는 “풀 리퀘스트는 오픈소스와 기업 소프트웨어 개발에 혁명을 가져왔지만, 이제 AI 에이전트가 이전보다 훨씬 빠르고 복잡하게 코드를 작성하고 있다”고 말했다.
이어 “트레일은 개발자의 아이디어와 에이전트 실행 기록, 작업 결과를 코드와 함께 검토해야 할 핵심 자료로 취급한다”며 “여러 에이전트가 AI 생성 코드의 품질과 성공 여부를 평가하도록 해 개발자가 모든 코드 변경 사항을 일일이 검토하지 않고도 확신을 갖고 병합할 수 있도록 한다”고 설명했다.
케빈 군든(Kevin Gounden) 빌드카이트 CEO는 AI 에이전트 확산으로 소프트웨어 변경 사항의 처리량이 급증하고 있다며, 엔타이어와의 협력이 이러한 개발 환경 변화에 대응하는 데 기여할 것이라고 밝혔다.
카일 갤브레이스(Kyle Galbraith) 디포 공동창립자 겸 CEO 역시 “병목 현상은 코드 작성에서 그 이후의 모든 단계로 옮겨갔다”며 기존 깃허브 액션스 워크플로를 실행할 수 있는 빠르고 안정적인 CI 환경의 중요성을 강조했다.
엔타이어는 지난 2월 6000만달러(약 797억원)의 시드 투자를 유치했으며, 현재 깃허브·마이크로소프트(Microsoft)·아틀라시안(Atlassian)·디지털오션(DigitalOcean)·레드버블(Redbubble) 출신 인력을 포함한 50명 규모의 글로벌 조직으로 성장했다.
회사는 앞서 저장소 미러링 기능과 에이전트 세션을 추적하는 엔타이어 CLI를 공개했으며, 이번 독립형 깃 포지 출시를 통해 개발 플랫폼의 핵심 기능을 통합했다.
향후에는 깃 노드 자체 호스팅, 공개 저장소, 에이전트 세션 실시간 스트리밍, 외부 개발 도구와의 추가 통합 기능을 제공할 계획이다. 초기에는 AI 중심 개발팀에 집중하고, 이후 오픈소스 프로젝트 관리자와 대기업으로 이용 대상을 확대한다는 전략이다.
이번 엔타이어의 출시는 AI 코딩 에이전트 확산으로 소프트웨어 개발의 병목이 코드 작성에서 검증·테스트·병합 단계로 이동하고 있음을 보여준다. 특히 개발자가 코드의 모든 변경 사항을 직접 검토하는 방식에서 AI 평가 결과와 실행 이력을 바탕으로 개발 과정을 관리하는 방식으로 전환하려는 시도라는 점에서 주목된다.
다만 코드 푸시 속도와 토큰 절감률은 회사가 제시한 수치이며, AI 평가만으로 코드의 안전성과 정확성을 충분히 확보할 수 있는지는 실제 개발 환경에서 검증이 필요한 부분이다. 엔타이어가 기존 깃허브 중심의 개발 생태계에서 얼마나 빠르게 이용자를 확보할지도 향후 관전 요소다.

- Liquid AI가 텍스트, 비전, 오디오, 시청각 통합, 의사결정용 모델 6종을 오픈 웨이트로 공개함. 공통 백본에서 파생한 약 2B 파라미터급 모델로, 용도에 맞게 선택해 단일 GPU로 미세조정하고 로컬에 배포할 수 있음
- 텍스트 모델 LFM3-1.7B는 4비트 정밀도에서 약 1GB 크기이며 최대 256K 토큰 문맥을 지원함. 합성곱과 두 종류의 어텐션을 결합해 긴 문맥의 처리 속도와 메모리 효율을 높임
- 로컬 에이전트의 메일 분류, 일정 관리, 웹 조사와 도구 호출에 맞춰 학습함. 자체 비교에서 일부 더 큰 모델보다 지시 준수와 도구 사용, 브라우저 업무 성능이 높았지만 에이전트 코딩과 지식 영역에서는 큰 모델이 우세함
- 비전 모델은 영상 입력, 오디오 모델은 18개 언어와 스트리밍 음성 대화를 지원함. 옴니 모델은 영상과 소리를 함께 이해하고, 시각적 맥락과 음성 지시를 결합해 도구를 호출할 수 있음
- 의사결정 모델은 여러 질문을 한 번의 연산으로 처리하고 보정된 확률과 구조화된 결과를 반환함. 문서의 값 추출, 이미지 속 대상 위치 지정, 분류와 수치 추정 등에 활용할 수 있음
공통 백본과 새로운 하이브리드 아키텍처
- LFM3의 첫 출시는 LFM3-1.7B-Base에서 파생한 약 2B 파라미터급 모델 6종으로 구성됨
  - 텍스트, 비전, 오디오, 옴니 모델 4종과 비전 및 옴니 모델에서 특화한 의사결정 모델 2종임
  - 대형 범용 모델 하나를 실행하는 대신, 용도에 맞는 모델을 선택하고 맞춤화해 기기에서 실행하는 방식임
- LFM2의 짧은 합성곱과 어텐션 조합을 하드웨어 연계 자동 아키텍처 탐색으로 재설계함
  - 탐색 대상은 휴대전화와 노트북의 CPU 2종에서 기기 및 백엔드 조합 14종으로 확대됨
  - Samsung Galaxy S26 Ultra, OnePlus 15, Raspberry Pi 5, Apple M4 Max 및 AMD Ryzen AI 노트북, Arm 및 x86 클라우드 CPU, GPU, Qualcomm Hexagon NPU를 포함함
  - 일부 합성곱을 다른 시퀀스 처리 블록으로 교체하는 실험에서는 슬라이딩 윈도 어텐션이 품질과 속도 사이에서 가장 좋은 균형을 보임
- 24개 층은 게이트형 짧은 합성곱 13개, 256토큰 윈도의 슬라이딩 윈도 어텐션(SWA) 5개, 전역 어텐션 6개로 구성됨
  - 합성곱 커널 크기는 LFM2의 3에서 7로 커짐
  - Liquid AI의 파라미터당 비교에서 LFM3-1.7B는 짧은 프롬프트에서 LFM2-1.2B와 비슷한 속도를 보이며, 8K 문맥에서는 약 25% 빠름
- 헤드별 게이트 어텐션은 시그모이드 게이트로 각 헤드의 출력을 조절해 기여할 내용이 없을 때 출력을 끌 수 있음
- 부분 RoPE는 전역 어텐션 헤드의 고주파 절반에만 회전을 적용하고, 저주파 절반은 회전하지 않아 거리와 무관한 내용 매칭이 가능하도록 함
- 샌드위치 정규화는 각 블록의 입력과 출력을 모두 정규화해 활성화 값의 크기를 안정적으로 유지함
- 토크나이저는 LFM2.5-8B-A1B와 동일한 128K 어휘를 사용하며, 비라틴 문자 체계를 더 효율적으로 토큰화하도록 설계됨
사전학습과 텍스트 에이전트 후속학습
- LFM3-1.7B-Base는 22T 토큰으로 사전학습함
  - LFM2보다 과학 논문, 저장소 단위 코드, 다양한 지식 자료, 수학 데이터의 비중을 늘림
  - 마지막 3.5T 토큰은 선별한 고품질 데이터로 중간학습하는 단계이며, 에이전트 실행 추적과 다양한 도구 호출 비중을 높임
  - 이 단계에서 문맥 길이를 256K 토큰으로 확장함
- LFM3-1.7B는 로컬 에이전트와 특화 애플리케이션을 위한 텍스트 모델임
  - Hermes Agent, Pi, OpenClaw 같은 에이전트 하네스에서 실행하도록 후속학습함
  - 받은편지함 분류, 일정 관리, 웹 조사, WhatsApp 아침 브리핑, 수천 개 도구 중 적절한 도구를 찾는 도구 검색을 지원함
  - 로컬 실행에서는 토큰 사용료 없이 여러 에이전트를 백그라운드에서 계속 실행할 수 있으며, 단일 GPU의 짧은 미세조정으로 도메인과 하네스, 도구에 맞출 수 있음
- 후속학습은 네 단계로 진행함
  - 지도 미세조정(SFT): 대화, 추론, 도구 호출, 에이전트 실행 추적 등 1.75T 토큰으로 학습함
  - 혼합 강화학습: 수학, 코드, SQL, 구조화된 출력 등 여러 영역을 동시에 학습하며, 보상에 길이 페널티를 적용해 답변을 간결하게 유지함
  - 다중 도메인 온폴리시 증류(MOPD): 코드, 수학, 도구 사용, 긴 문맥, 에이전트 작업, 기업 업무 흐름에 특화한 강화학습 교사 모델 6개의 역량을 하나로 증류함
  - 에이전트 강화학습: 실제 에이전트 하네스 안에서 웹 탐색부터 사무 업무까지 수행함
텍스트 모델의 성능과 실행 효율
- Liquid AI의 비교에서 LFM3-1.7B는 크기가 몇 배인 모델과 에이전트 작업에서 경쟁하며, 지시 준수와 BFCL 및 ToolSandbox 함수 호출 평가에서 앞섬
  - LiveClaw는 45.60점, BFCL V4는 71.39점, ToolSandbox는 80.36점을 기록함
  - WebArena-Verified는 38.42점, AutomationBench는 41.29점으로, Qwen3.5-9B의 28.94점과 15.10점보다 높음
  - 비교표의 전체 평균은 49.37점으로 Qwen3.5-9B의 47.24점보다 높지만, 모든 분야에서 우세한 것은 아님
- 에이전트 코딩과 지식에서는 더 큰 모델의 우위가 남아 있음
  - SWE-bench Verified에서 LFM3-1.7B는 43.40점, Qwen3.5-9B는 51.20점을 기록함
  - Humanity’s Last Exam 점수는 도구 없이 7.17점, 도구 사용 시 13.90점으로, 검색이 지식 격차를 줄이는 데 도움이 됨
- 기기 내 측정은 llama.cpp, Q4_0, 32K 문맥 조건에서 수행함
  - 측정한 기기 3종 모두에서 가장 빠르며, 다음으로 빠른 모델보다 디코딩 속도가 1.8~2.8배 높고 메모리 사용량도 가장 적음
  - 128K 문맥의 KV 캐시는 1.6GB로, Qwen3.5-4B의 4.3GB와 MiniCPM5-2B의 5.6GB보다 작음
- NVIDIA B300 한 대에서 SGLang, BF16, 동시 요청 1,024개 조건으로 하루 36억 토큰을 생성할 수 있으며, 해당 비교 모델 중 처리량이 가장 높음
  - 처리량 활용 사례로 LFM3-1.7B 에이전트 30만 개 이상을 병렬 실행해 Enron 이메일 아카이브를 조사함
  - Liquid RIPL에서는 불규칙한 요청과 높은 부하에서도 P95 요청 지연 시간이 안정적으로 유지되며, 온라인 사기 탐지 같은 실시간 용도를 지원함
  - 이 비교에서는 vLLM으로 제공한 경쟁 모델보다 낮은 지연 시간을 보임
- MacPaw의 실제 macOS 작업 65개 평가에서는 LFM3-1.7B가 Qwen3.5-2B보다 높은 성공률을 기록함
  - 작업 성공률은 64% 대 48%이며, 작업당 토큰 사용량은 58% 적었음
  - 진행이 막힌 시도는 1% 미만으로, 비교 모델의 15%보다 적었음
비전 모델과 자체 비전 인코더
- LFM3-VL-2B는 LFM 비전 모델 최초로 영상 입력을 지원함
  - 녹화 강의, 휴대전화로 촬영한 현장 영상, 카메라 영상에 관해 질문할 수 있음
  - 답변 전 단계별 추론으로 수학, 차트, 다단계 시각 문제를 처리함
  - 물체 위치와 공간 관계를 파악하는 능력은 로봇 응용의 기반이 됨
- Liquid AI의 비전 벤치마크 62개 평가에서 평균 71.4점을 기록함
  - 비슷한 크기의 비교 모델보다 최소 7.4점 앞서며, Gemma 4 12B의 71.7점과 비슷한 수준임
  - Gemini 3.5 Flash Lite는 70.0점, GPT-5.6 Luna는 73.4점을 기록함
