공격에는 두 개의 IP 주소가 사용됐다. 한 IP에서는 셸 실행 3건이, 다른 IP에서는 32건이 확인됐다. 공격 대상은 아파치 웹서버의 mod_php 환경에서 PHP 8.4.26을 실행하는 시스템이었다.
공격자는 여러 단계의 HTTP 요청을 통해 PHP의 메모리 고갈을 유발하고 내부 메모리 정보를 노출시킨 뒤 이를 활용해 명령을 실행한 것으로 분석됐다. 공격 흐름은 공개된 개념증명(PoC) 코드와 유사했으며, 특히 CVE-2026-109618 취약점 악용 방식과 일치하는 것으로 나타났다.
카리미는 단순한 서버 충돌이나 비정상 프로세스 발견이 아니라 메모리 정보 유출과 실제 명령 실행을 확인했다고 설명했다. 다만 추가 악성코드 다운로드 등 후속 공격 행위는 관찰되지 않았다.
PHP2Shell은 지난 10월 21일 공개된 CVE-2026-109618과 CVE-2026-109619를 통칭한다. 두 취약점 모두 CVSS v4.0 기준 9.2점의 치명적 취약점으로, 인증되지 않은 공격자가 웹 요청 처리 과정의 메모리 관리 오류를 악용해 서버에서 임의의 코드를 실행할 수 있다.
앞서 도이치텔레콤 보안팀도 취약점 공개 직후 공격코드와 유사한 요청을 관찰했다. 아마존 위협 인텔리전스 역시 공식 공개 이전인 10월 17일부터 공격 시도를 포착한 바 있다. 다만 단순 취약점 탐색과 실제 침해 성공은 구분해야 한다.
이번 사례 역시 공격에 유리하도록 구성된 단일 작업 프로세스 기반 허니팟에서 확인된 결과다. 따라서 다른 PHP 버전이나 웹서버 설정에서도 동일한 성공률을 보인다고 단정할 수 없으며, 실제 기업·기관 운영 서버의 침해 규모도 아직 확인되지 않았다.
PHP 개발팀은 이미 PHP 8.5.12, 8.4.27, 8.3.36, 8.2.35 등 보안 수정 버전을 배포하고 즉각적인 업데이트를 권고했다. 특히 아파치 mod_php 환경의 위험도가 높지만 PHP-FPM, php-cgi 등 다른 실행 환경도 점검 대상이다.
국내 기업과 기관도 외부에 노출된 PHP 기반 웹서비스와 노후 시스템의 버전을 확인하고, 보안 패치 적용 여부와 비정상적인 HTTP 요청, PHP 프로세스의 셸 실행 흔적 등을 점검할 필요가 있다.
이번 사례는 PHP2Shell 공격이 단순한 취약점 탐색을 넘어 특정 환경에서 실제 명령 실행으로 이어질 수 있음을 보여준다. 다만 현재까지 확인된 허니팟 침해 증거만으로 전 세계 운영 서버에서 공격이 대규모로 성공하고 있다고 판단하기는 어렵다.

[BODY]
Anthropic details what stops Claude Duet from going rogue
Anthropic has outlined the security and privacy protections behind Claude Duet, its proactive AI agent that can monitor connected accounts and complete tasks while users are away. The safeguards include approval requirements, checks for sensitive information and infrastructure that keeps credentials outside the model’s reach.
Duet works through a cloud-based computer and browser to prepare briefings, draft messages and handle business tasks. The standalone app is available through a research preview waitlist for Pro and Max subscribers in the US and shares usage limits with the rest of Claude.
User approvals and action limits
According to Anthropic, Duet asks users to approve actions such as sending potentially sensitive messages, making payments or deleting information. The request shows the proposed action, destination and content, including recipients.
A separate automated check assesses whether each action matches the user’s intent. Anthropic says this check operates outside the model performing the task to protect it from instructions hidden in web pages.
Approval flow: the approval card and the separate check sit outside the model, so nothing the agent reads can answer the card. (Source: Anthropic)
Accessing someone else’s account, trading securities and moving money between bank accounts remain prohibited even with approval. Certain actions, including payments and account creation, require approval each time. Background routines follow the same rules.
“Approval fatigue is a serious issue, because too many requests teach people to tap through them, sometimes without adequate consideration. We will continue to adjust this calibration over time,” the company said.
Information sharing and data retention
Anthropic uses a separate classifier designed to detect sensitive information in outgoing messages. The checks also cover browser uploads.
Duet is instructed never to share credentials, full payment card and bank account numbers, or government identification numbers, even when asked. Other private information, including health and financial details, requires explicit consent. A user’s instruction to send that information can count as consent.
When a message is blocked, Duet can remove the sensitive content and submit a revised version for approval. Anthropic acknowledges that the checks may miss sensitive information or flag harmless messages during the research preview.
Users can review Duet’s progress through a task list and give instructions while work is underway. Apps connected to Claude carry over to Duet. Disconnecting an app stops new access in both services.
Duet uses conversation history and memory to carry context between tasks until users delete the history or reset the memory. Disconnecting an app does not erase information already retained in memory. Deleting an account removes all stored information.
Credential protection and browser security
Anthropic says Duet cannot access users’ passwords, browser cookies or sign-in tokens.
Users enter passwords through a form inside the Claude app. The form encrypts the password and sends it directly to the cloud browser, which enters it on the website. Planned 1Password support will allow users to approve credential requests without passing login details through the model.
For connected apps, a separate service adds sign-in tokens when requests are made, keeping those credentials outside the agent’s workspace.
The company warns that attackers could imitate password forms. Legitimate requests appear only during a sign-in initiated by the user, inside the Claude app or on claude.ai. Password requests claiming to come from Duet through email, text messages or websites other than claude.ai are fraudulent, the company says.
Duet’s browser runs in a dedicated cloud virtual machine. The agent controls it through commands to open pages, click and type.

이를 위해 코드와 수정 이력을 관리하는 공유 저장소, 에이전트끼리 소통하는 메시지 시스템, 발견한 사실과 실패한 시도 등을 남기는 공유 기록을 마련했다. 한 에이전트가 알아낸 내용을 다른 에이전트가 활용하고, 이미 실패한 접근을 되풀이하지 않도록 돕는 구조다.

문서 변환 프로그램 ‘판독(pandoc)’을 재현하는 과제에서는 에이전트 수를 1024개까지 늘렸다. 최종 테스트 통과율은 단일 에이전트의 33.89%에서 55.06%로 상승했다. 목표 성능에 도달하는 시간도 짧아졌다. 에이전트 128개는 30분 시점에 통과율 30%를 넘겼지만, 단일 에이전트는 초기 2시간 동안 이 기준에 도달하지 못했다.
연구진은 성능 변화와 함께 협업 방식이 달라지는 과정도 관찰했다. 에이전트 8개가 참여했을 때는 작업 범위와 프로그램 구성 요소의 연결 방식을 서로 합의했다. 32개 규모에서는 여러 에이전트가 코드를 함께 검토했으며, 한 에이전트가 오류를 입증하는 사례를 찾자 앞서 내린 승인을 철회하고 수정 후 다시 검토하는 행동도 나타났다.
128개 규모에서는 관련 경험이 있는 동료에게 검토를 맡기고, 이후에도 같은 동료와 협업하는 모습이 관찰됐다. 코드를 수정하고 테스트한 뒤 동료에게 검증과 통합을 요청하는 절차를 정해 다른 작업에도 활용했다.
1024개 규모에서는 코드 통합을 맡는 에이전트가 여럿 등장했다. 작업자는 여러 통합 담당자에게 연락한 뒤 먼저 응답한 적임자에게 결과물을 넘겼다. 특정 에이전트의 작업이 실패하면 같은 분야를 맡은 다른 에이전트가 이어받기도 했다.
이런 역할과 절차를 연구진이 미리 지정한 것은 아니다. 모든 에이전트는 식별자를 제외하면 동일한 지시문을 받았으며, 동료와 소통하는 과정에서 담당 업무와 협업 절차를 정했다.
다만 이번 실험은 같은 모델과 작업 시간을 유지하면서 에이전트 수를 늘렸을 때의 변화를 측정했다. 동일한 비용으로 성능을 높였다는 뜻은 아니며, 중앙 관리자 방식과 직접 비교해 우위를 입증한 결과도 아니다.
에이전시의 공개는 AI 코딩 에이전트의 성능을 높이는 방법이 개별 모델의 추론 능력을 개선하는 데만 있지 않다는 점을 보여준다. 여러 에이전트가 작업을 나누고, 지식을 공유하며, 결과를 검증하고 통합하는 조직 구조도 성능과 처리 속도에 영향을 줄 수 있다는 것이다.

국내 기업들도 AI 에이전트를 활용한 업무 자동화에 속도를 내고 있다. AI가 처리하는 업무가 늘어날수록 접근 권한과 정보 보호, 최종 승인 절차를 어떻게 설계할지가 중요한 과제로 떠오를 전망이다.
AI가 사람의 일을 대신하는 시대를 넘어, AI의 행동을 또 다른 AI가 감시하는 시대가 시작되고 있다.

[TITLE_KO] 미소스 5, 7월 공격에서 실제 피해를 무시해
[LINK] https://www.securityweek.com/mythos-5-ignored-real-world-harm-in-july-attack/
[PUBLISHED] 2026-10-26 18:10 KST
[SOURCE] SecurityWeek
[TOPIC] 개발, 모델, 보안
[SCORE] 7
[REASON] 모델이 실제 피해를 무시한 공격 사례
[BODY]
Mythos 5 completely disregarded potential harm in a real-world attack mounted during a July 2026 AI Security Institute (AISI) evaluation, Anthropic and AISI say.
The incident, disclosed in early August, involved 17 rogue actions from Mythos 5, including the use of Tor to access the internet, the creation of fake identities to submit malicious pull requests on a public GitHub project, and the use of social engineering to pressure a maintainer into approving the code change.
As part of the evaluation, the agent had been tasked with the retrieval of protected data from a simulated network. Its safeguards were turned off, and internet access was deliberately enabled.
After reasoning that it could not complete the capture-the-flag (CTF) cybersecurity challenge using the methods within the evaluation’s scope, Mythos switched to targeting real-world people and organizations and disregarded the potential harm that would result.
“Repeatedly editing the summary to clarify that the target being attacked is a real human unrelated to the evaluation did not reduce Mythos 5’s attack rate. Mythos also showed significant inconsistency between its actions and its stated justification when asked: it often stated that attacking would be harmful in the same situations where it proceeded to attack,” AISI says.
The institute’s analysis of Mythos 5’s raw chain-of-thought outputs showed that the model often reasoned that the targets were simulated, frequently did not consider the potential harm the actions could cause, and never produced incorrect justifications implying that the target was real.
“We frequently observed models producing invalid reasoning and justifications during our experiments, drawing conclusions that are not justified by the available evidence. If this and other issues surfaced in our investigation occur more broadly and are not sufficiently addressed, especially as models become more capable, there are concerning implications,” AISI notes.
In a technical report, the institute explains that this form of motivated reasoning could make it more difficult to identify misaligned behavior, leading to a loss of the oversight and monitorability that would hurt the safe deployment of frontier AI systems.
Anthropic compared Mythos 5’s behavior to other misalignment incidents involving models targeting real-world organizations, detailed in July, September, and October reports.
In September, the company flagged recurring alignment issues across multiple incidents, where the model would disregard that it was operating on the real internet (biased reasoning) and was willing to perform harmful actions while pursuing its task (recklessness).
Now, it looked at how far the models went beyond the intended scope when the configuration made it difficult to achieve a goal (overreach), and the extent to which it misinterpreted its actions (dishonesty).
Overall, Anthropic concluded that the AISI incident was less severe in overreach but more severe in dishonesty when compared to the incidents described in September, where the model uploaded a malicious package to PyPI.
Compared to the incidents surfaced in October, where the model exploited software flaws, submitted a sensitive form online, bypassed a restriction, and used URL shortening services, the AISI actions were more severe in both overreach and dishonesty.
“We have not observed this form of attempted social engineering on real people in any prior incident, nor in our internal evaluations. We interpret this as a severe form of dishonesty, rather than some new form or category of misalignment,” Anthropic notes.
Newer models, the company says, are less likely to complete a similar attack. In tests performed on Mythos 5.1, Opus 5.5, and a general-purpose internal research model, the AI initiated the attack in up to 13% of occurrences, compared to 83% for Mythos 5.
“Our newest models also proved to be much less likely to continue the attack once they realized it was causing real-world harm.

[TITLE] Hackers Infect 953 Online Stores With Scanner-Evading JavaScript, Mostly on Magento
[TITLE_KO] 해커들, 탐지 피하는 자바스크립트로 온라인 상점 953곳 감염, 대부분 마젠토
[LINK] https://thehackernews.com/2026/10/hackers-infect-953-online-stores-with.html
[PUBLISHED] 2026-10-27 03:12 KST
[SOURCE] The Hacker News
[TOPIC] 개발, 보안
[SCORE] 7
[REASON] 온라인 상점 953곳 악성 코드 감염
[BODY]
An unknown threat actor has infected 953 online stores, most of them running Magento, as part of a long-running campaign active since July 2025.
According to Dutch e-commerce security company Sansec, the activity is designed to add a small piece of code to the store's pages that, when visited by unsuspecting users, serves malicious JavaScript loader code through Magento CMS blocks.
"When you visit, that code makes your browser ask the group's server what to do next," Sansec said. "The server first checks whether you are a real shopper or a security scanner, so scanners get nothing."
No less than five distinct domains have been observed over time in connection with the campaign -
- manulfie[.]click, first seen in July 2025
- neswnsssn[.]click, first seen in December 2025
- lanhd6549tdhse[.]top, first seen in March 2026
- additionalver[.]com, first seen in June 2026
- deepveindrilling[.]com, first seen in October 2026
Sansec said it found deepveindrilling[.]com in the CMS blocks of 83 online stores since the domain was registered on October 6, 2026.
The latest JavaScript loader domain is hosted behind Cloudflare and only responds to script requests from real visitors of infected stores. The loader is staged within Magento's cms_block database table, which is used to render static content into storefront pages.
The ultimate objective of the attack is to launch the attack-controlled code when the CMS block is rendered after a shopper opens the compromised website.
While Sansec does not disclose whether the threat actor modifies an existing CMS block (such as header, footer, or promotional banner) or creates a new block, the attacker can adopt either of the approaches to run the loader.
Two different versions of the loader have been spotted. In one version, the external JavaScript loaded from the attacker's domain stores the payload in the browser's localStorage. This causes the stashed code to be run again on subsequent visits, even if the external domain becomes unavailable.
The second version expands on this behavior by incorporating browser fingerprinting checks to filter out bots and security scanners, while ensuring that only real shoppers are exposed to the malicious code. The exact nature of the final payload remains unknown.
Early iterations of the campaign have also been observed using Keitaro, an advertising tracker and analytics platform, as a traffic distribution system (TDS), to route visitors to different responses – i.e., return a payload, a redirect, or nothing – based on their characteristics.
Sansec said requesting the additionalver[.]com script as a Windows desktop visitor returned as response "QWE=123;," which does nothing apart from setting a cookie that marks the visitor for 24 hours. The deepveindrilling[.]com domain, on the other hand, drops the Keitaro component and integrates the bot-filtering logic into the loader itself.
As for the initial access vector, 471 Magento stores are estimated to have been injected with the loader through the PolyShell (aka CVE-2026-48356) vulnerability. Another 102 stores saw files uploaded through the PolyShell or SessionReaper (aka CVE-2025-54236) vulnerabilities.
"One store on Magento 2.4.7-p1 had PolyShell webshells disguised as PNG images in pub/media/custom_options/quote/, next to the additionalver.com loader in a CMS block," Sansec said. "The block switched to deepveindrilling[.]com on October 7. The store still lacks APSB26-73, Adobe's PolyShell fix for supported release lines."
In another case, an e-commerce store running Magento 2.4.7-p10 with no missing core patches was compromised to add a rogue administrator account and then use it to inject the code.
Site owners are advised to audit their sites for suspicious accounts and unexpected CMS blocks in the cms_block and cms_page tables. It's also advised to keep the sites up-to-date and enforce strong passwords.

[TITLE] Microsoft releases emergency .NET patches for critical Brotli flaw
[TITLE_KO] 마이크로소프트, 브로틀리 치명적 결함 막는 닷넷 긴급 패치 배포
[LINK] https://www.bleepingcomputer.com/news/microsoft/microsoft-releases-emergency-net-patches-for-critical-brotli-flaw/
[PUBLISHED] 2026-10-27 00:38 KST
[SOURCE] BleepingComputer
[TOPIC] 보안
[SCORE] 7
[REASON] 닷넷의 브로틀리 결함 긴급 패치
[BODY]
Microsoft released emergency .NET security updates to patch a critical vulnerability known as Broccoli2Shell, also tracked as Node2Shell and HTTP2Shell.
Tracked as CVE-2026-111497, this critical-severity flaw stems from an out-of-bounds write in the Brotli decoder, which expands data compressed using Google's widely used Brotli lossless compression algorithm.
HTTP2Shell impacts HTTP clients and servers, as well as other applications and tools that rely on vulnerable Brotli implementations.
Successful exploitation lets unprivileged attackers use a maliciously crafted Brotli-compressed stream to trigger crashes or memory leaks and, in some cases, gain remote code execution on devices with vulnerable Brotli binaries or libraries.
According to a Microsoft advisory published Sunday, attackers can also exploit this flaw to remotely escalate privileges on systems with unpatched .NET installations that use non-default configurations.
"Applications may be affected if they process Brotli-compressed data through ASP.NET Core request decompression, HttpClient automatic response decompression, or the System.IO.Compression Brotli APIs," Microsoft said.
"Brotli decompression is not enabled by default in an out-of-the-box .NET or ASP.NET Core install. Applications must manually opt in to ASP.NET Core request decompression or HttpClient response decompression, or they must manually invoke the Brotli decompression APIs provided by .NET."
To address this flaw, Microsoft has released out-of-band (OOB) security updates for .NET 8, .NET 9, and .NET 10, along with .NET 11 Release Candidate 3, and advised "updating as soon as possible."
While proof-of-concept (PoC) exploits for Broccoli2Shell have already been published on GitHub, no reports of malicious exploitation in the wild have emerged.
A dedicated online portal tracking the flaw warns that updating the system Brotli library doesn't address the risk in apps that bundle their own copy of the library.
Those who can't apply the updates immediately should block incoming Brotli-compressed requests using a proxy or firewall, or disable Brotli decoding until they can apply a patch.
