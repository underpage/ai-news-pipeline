## 3. Docker Fixes Critical Two-Year-Old Hub Flaw That Let One User Push Images as Another

- **번역 제목**: 도커, 한 사용자가 다른 사용자로 이미지를 푸시할 수 있었던 2년 된 도커 허브의 치명적 결함 수정
- **날짜**: 2026-10-14 03:03 KST
- **주제**: 보안
- **중요도**: 9/10 - 도커 허브의 타인 이미지 푸시 가능 취약점 패치
- **태그**: 부정
- **출처**: The Hacker News
- **링크**: [원문 기사](https://thehackernews.com/2026/10/docker-fixes-critical-two-year-old-hub.html)

**요약**

- Docker fixed a critical flaw in Docker Hub (CVE-2026-105445) that allowed a user to push, pull, or delete images as another user via the personal account conversion feature.
- The vulnerability, named GhostPat, persisted for over two years and stemmed from personal access tokens being transferred to a newly designated owner while secrets remained unchanged.
- Docker stated it resolved the flaw directly on Docker Hub without requiring user updates, and found no evidence of malicious exploitation after reviewing roughly 304,000 pushes.

**번역**

- 도커는 개인 계정 전환 기능을 통해 한 사용자가 다른 사용자의 권한으로 이미지를 푸시, 풀, 삭제할 수 있도록 허용했던 도커 허브의 치명적 결함(CVE-2026-105445)을 수정했다.
- GhostPat으로 명명된 이 취약점은 2년 넘게 방치되었으며, 토큰의 시크릿이 변경되지 않은 채 개인 액세스 토큰이 새로 지정된 소유자에게 이전되면서 발생했다.
- 도커는 사용자 업데이트가 필요 없는 도커 허브 자체 패치를 적용했으며, 약 30만 4천 건의 푸시 이력을 검토한 결과 악의적으로 익스플로잇된 정황은 발견되지 않았다고 밝혔다.

## 5. npm Trusted Publishing flaw exposed 1,500+ npm packages to takeover

- **번역 제목**: npm의 신뢰 게시 기능 결함으로 1,500개 이상의 패키지가 탈취 위험에 노출
- **날짜**: 2026-10-13 18:00 KST
- **주제**: 보안
- **중요도**: 9/10 - npm 신뢰 게시 기능 취약점으로 패키지 탈취 위협
- **태그**: 부정
- **출처**: Help Net Security
- **링크**: [원문 기사](https://www.helpnetsecurity.com/2026/10/13/slugfest-npm-trusted-publishing-flaw/)

**요약**

- A flaw in npm's Trusted Publishing feature allowed attackers to take over and publish malicious updates for more than 1,500 npm packages by claiming abandoned GitHub repository slugs.
- Because npm did not check permanent numeric IDs in identity tokens, any newly registered matching slug could obtain short-lived publish credentials and push validly signed versions.
- Security researchers highlighted that AI coding agents increase the blast radius of such vulnerabilities by automatically installing dozens to hundreds of unreviewed packages per month.

**번역**

- npm의 신뢰 게시(Trusted Publishing) 기능에 결함이 발생해, 공격자가 버려진 깃허브 저장소 슬러그를 선점함으로써 1,500개 이상의 패키지를 탈취하고 악성 업데이트를 배포할 수 있는 상태가 되었다.
- npm이 식별 토큰의 영구 숫자 ID를 검증하지 않았기 때문에, 일치하는 슬러그를 새로 등록한 누구나 단기 게시 인증 정보를 받아 서명된 정식 버전을 푸시할 수 있었다.
- 보안 연구진은 AI 코딩 에이전트가 검증되지 않은 패키지를 한 달에 수십에서 수백 개씩 자동 설치하기 때문에 이러한 취약점의 영향 범위가 더욱 커진다고 지적했다.

**요약**

- SAP disclosed a critical CVSS 10.0 vulnerability (CVE-2026-89111) in its Cloud SDK for Python that could send an application's OAuth2 client credentials to an attacker-controlled server.
- The SSRF flaw occurs when multi-tenant applications process tenant subdomains without proper validation, routing credentials to unauthorized endpoints.
- Although an initial fix was released in version 0.45.2, several subsequent versions and older releases re-introduced or lacked the necessary validation checks.

**번역**

- SAP는 파이썬용 클라우드 SDK에서 애플리케이션의 OAuth2 클라이언트 인증 정보를 공격자가 제어하는 서버로 전송할 수 있는 CVSS 10.0의 치명적인 취약점(CVE-2026-89111)을 공개했다.
- 해당 SSRF 결함은 멀티 테넌트 애플리케이션이 테넌트 하위 도메인을 적절히 검증하지 않고 처리할 때 발생하며, 이로 인해 인증 정보가 비정상적인 엔드포인트로 라우팅된다.
- 버전 0.45.2에서 최초 수정이 이루어졌으나, 이후 출시된 일부 후속 버전과 구버전 릴리스에서 필요한 유효성 검사 누락이 다시 발생했던 것으로 나타났다.
