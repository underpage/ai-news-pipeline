- **태그**: 부정
- **출처**: InfoWorld
- **링크**: [원문 기사](https://www.infoworld.com/article/4241474/attackers-compromised-42-github-repositories-by-using-files-too-large-to-be-searched.html)

**요약**

- JFrog Security Research revealed that attackers compromised 42 third-party GitHub repositories by embedding large polymorphic payload blobs that evades standard GitHub search and API detections.
- The malicious files targeted autonomous coding agents and IDEs using execution hooks, using an npm worm campaign that stole developer credentials and poisoned CI/CD publishing configurations.
- Security researchers recommended treating the worm installation as a host compromise, advising teams to audit configurations for AI assistants and rotate all related cloud and repository credentials.

**번역**

- JFrog 보안 연구소는 공격자들이 표준 깃허브 검색 및 API 탐지를 회피하는 대용량 다형성 페이로드 블롭을 삽입하여 42개의 서드파티 깃허브 저장소를 침해했다고 밝혔다.
- 악성 파일은 실행 훅을 통해 자율 코딩 에이전트와 IDE를 겨냥했으며 개발자 자격 증명을 탈취하고 CI/CD 배포 설정을 오염시키는 npm 웜 캠페인을 활용했다.
- 보안 연구원들은 해당 웜 설치를 호스트 침해로 간주할 것을 권고하며 팀들에게 AI 어시스턴트 설정을 점검하고 관련 클라우드 및 저장소 자격 증명을 모두 교체할 것을 조언했다.
