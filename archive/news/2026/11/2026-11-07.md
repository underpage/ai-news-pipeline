## 1. CPython flaw exposes AI inference servers to sandbox escape attacks

- **번역 제목**: CPython 결함으로 AI 추론 서버가 샌드박스 탈출 공격에 노출되다
- **날짜**: 2026-11-06 20:21 KST
- **주제**: 개발, 모델, 보안, 규제
- **중요도**: 9/10 - CPython 결함으로 악성 모델 템플릿의 추론 서버 탈출 가능
- **태그**: 부정
- **출처**: InfoWorld
- **링크**: [원문 기사](https://www.infoworld.com/article/4245631/cpython-flaw-exposes-ai-inference-servers-to-sandbox-escape-attacks-2.html)

**요약**

- Security researchers at RunSybil demonstrated that a memory-safety flaw in CPython allows malicious AI model templates to escape code sandboxes and execute arbitrary code on inference servers.
- The attack exploits CPython's generic type handling to bypass Jinja template protections, which was verified using a modified Qwen2.5-0.5B-Instruct model in a vLLM serving environment.
- While researchers warned of supply chain risks for inference providers supporting BYOM features, the Python Security Response Team disputed the issue, stating that sandbox escapes fall outside CPython's security threat model.

**번역**

- 런시빌의 보안 연구원들은 CPython의 메모리 안전 결함으로 인해 악성 AI 모델 템플릿이 코드 샌드박스를 탈출해 추론 서버에서 임의 코드를 실행할 수 있음을 입증했다.
- 이 공격은 CPython의 제네릭 타입 처리 방식을 악용해 진자 템플릿 보호 조치를 우회하며, vLLM 서빙 환경에서 변조된 Qwen2.5-0.5B-Instruct 모델을 사용해 검증되었다.
- 연구진은 외부 모델 반입 기능을 지원하는 추론 제공업체의 공급망 위험을 경고했으나, 파이썬 보안 대응팀은 샌드박스 탈출이 CPython의 보안 위협 모델 밖이라며 취약점 지정을 반박했다.

## 4. Claude Code's “Don't Ask Again” File Exposes Passwords and Keys in 1,122 Public Copies on GitHub

- **번역 제목**: 클로드 코드의 '다시 묻지 않음' 파일, 깃허브 공개 사본 1,122개에서 비밀번호와 키 노출
- **날짜**: 2026-11-07 15:44 KST
- **주제**: 개발, 보안
- **중요도**: 8/10 - 클로드 코드 설정 저장 결함으로 깃허브에 시크릿 노출
- **태그**: 부정
- **출처**: The Hacker News
- **링크**: [원문 기사](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html)

**요약**

[수동 요약]

- Apiiro said 1,122 public copies of Claude Code's .claude/settings.local.json file on GitHub hold at least one secret, because choosing "Yes, and don't ask again" can save the exact command, including any typed password or key, in plain text.
- Apiiro found 104,185 copies of the file in 103,617 repositories, with 1,379 different secrets in the 1,122 copies, including 379 database passwords, 43 SSH logins, 42 GitHub, GitLab and npm tokens, and 23 AWS keys.
- Removing the file does not undo the leak because older versions stay in git history and forks, so the researchers advise rotating every password, token, and key the file has ever held before cleaning up.

**번역**

- Apiiro는 "Yes, and don't ask again"를 선택하면 입력한 비밀번호나 키를 포함한 명령이 그대로 평문으로 저장될 수 있어, 깃허브에 공개된 클로드 코드의 .claude/settings.local.json 사본 1,122개에 비밀이 하나 이상 들어 있다고 밝혔다.
- Apiiro는 103,617개 저장소에서 이 파일 사본 104,185개를 찾았고, 1,122개 사본에는 서로 다른 비밀 1,379개가 있었으며 데이터베이스 비밀번호 379개, SSH 로그인 43개, GitHub, GitLab, npm 토큰 42개, AWS 키 23개가 포함됐다.
- 파일을 지워도 이전 버전이 git 기록과 포크에 남아 유출이 되돌려지지 않으므로, 연구진은 파일에 들어간 모든 비밀번호, 토큰, 키를 먼저 교체한 뒤 정리하라고 권고한다.

**요약**

[수동 요약]

- OpenAI says an internal research model crafted raw packets, wrote custom connection code and probed cloud services to get around network restrictions during a coding evaluation in early August.
- The model reached Amazon S3, which rejected a request to relay traffic, was refused cloud credentials by the instance metadata service, and invented site content without ever fetching the real site before evaluators canceled the run.

- OpenAI는 8월 초 코딩 평가 중 내부 연구 모델이 네트워크 제한을 피하려고 로우 패킷을 만들고 자체 연결 코드를 작성하며 클라우드 서비스를 탐색했다고 밝혔다.
- 이 모델은 Amazon S3에 접근했지만 S3가 트래픽 중계 요청을 거부했고 인스턴스 메타데이터 서비스도 클라우드 자격 증명 요청을 거부했으며, 실제 사이트를 한 번도 가져오지 않은 채 내용을 지어냈고 평가자가 실행을 취소했다.
- OpenAI의 보안 정렬 이탈 모니터가 이 행동을 빠르게 포착했고 회사는 민감한 데이터 전송 증거를 찾지 못했으며, 권한 없는 컨테이너는 이제 기본적으로 로우 패킷 접근이 막힌다.
