## 3. AI coding agents are installing MCP servers that will never be patched

- **번역 제목**: AI 코딩 에이전트가 영원히 패치되지 않을 MCP 서버를 설치하고 있다
- **날짜**: 2026-11-03 14:45 KST
- **주제**: 에이전트, 개발, 보안
- **중요도**: 7/10 - 코딩 에이전트가 방치된 MCP 서버를 설치하는 위험
- **태그**: 부정
- **출처**: Help Net Security
- **링크**: [원문 기사](https://www.helpnetsecurity.com/2026/11/03/mcphantom-deprecated-mcp-servers/)

**요약**

[수동 요약]

- AI coding agents are installing deprecated MCP servers from archived repositories that will never be patched, a pattern Glow Labs calls MCPhantom.
- Four high-severity vulnerabilities were found in those reference servers, including a remote code execution bug in the Puppeteer server, and the deprecated packages have been downloaded from npm more than 17.3 million times since July 2025.
- The servers never appear in a dependency file and have no CVEs, so EDR, SCA and software inventory miss them, while pre-execution hooks are the fix that works today.

**번역**

- Glow Labs 연구에 따르면 AI 코딩 에이전트가 GitHub MCP 설정 요청에 보관 처리된 저장소의 폐기된 MCP 서버를 설치하는 사례가 확인됐으며, 이를 MCPhantom이라 부른다.
- 해당 참조 서버들에서 고위험 취약점 4건이 발견됐고 가장 심각한 것은 Puppeteer 서버의 원격 코드 실행 버그지만, 저장소가 2025년 5월 보관 처리돼 수정이 나오지 않으며 폐기된 패키지는 7월 이후 npm에서 1730만회 넘게 내려받았다.
- 이 서버들은 의존성 파일에 나타나지 않고 CVE도 없어 EDR, SCA, 소프트웨어 인벤토리가 잡아내지 못하며, 실행 전 훅을 쓰는 보안 업체의 대응이 지금 가능한 방법으로 제시됐다.

**요약**

[수동 요약]

- VulnCheck said a maximum-severity flaw in Siemens SIMATIC IoT2050 Advanced devices, CVE-2026-58115 (CVSS 10.0), is under active exploitation.
- The missing authentication in the Node-RED HTTP interface lets an unauthenticated remote attacker create malicious flows and run arbitrary code with maximum privileges, and Siemens fixed it in versions 4.3.4.1 or later.
- As of October 30, 2026, VulnCheck observed attempts to download and run a Linux bot on its honeypots, and some requests planted an exec-node backdoor that survives a reboot.

**번역**

- VulnCheck는 지멘스 SIMATIC IoT2050 Advanced 장치의 CVSS 10.0 취약점 CVE-2026-58115가 실제 공격에 악용되고 있다고 밝혔다.

- VulnCheck는 10월 30일 기준 허니팟에서 리눅스 봇을 내려받아 실행하려는 공격을 관찰했고, 일부 요청은 다운로더 없이 exec 노드로 나중에 명령을 실행하는 백도어를 심어 재부팅 후에도 남는다고 설명했다.

- **링크**: [원문 기사](https://www.infoq.com/news/2026/11/torchtpu-native-pythorch-tpu/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)

**요약**

[수동 요약]

- Google, in collaboration with Meta, open-sourced TorchTPU, a native PyTorch backend for Google TPUs.
- It improves on PyTorch/XLA by prioritizing eager execution and needing only minor changes such as replacing cuda with tpu and nccl with tpu_dist, and Google claims its DeferAndFuse mode can be 50% or more faster than Strict Eager.

**번역**

- 구글이 메타와 협력해 구글 TPU용 네이티브 PyTorch 백엔드인 TorchTPU를 오픈소스로 공개했다.
- 기존 PyTorch/XLA의 소스 수정 부담과 긴 컴파일 지연, 즉시 실행 모드 미지원을 개선해 cuda 장치를 tpu로, nccl을 tpu_dist로 바꾸는 정도의 수정으로 PyTorch 작업을 실행할 수 있으며, 새 DeferAndFuse 모드는 Strict Eager보다 50% 이상 빠를 수 있다고 구글은 밝혔다.
- 구글은 약 5000개 Hugging Face 모델로 호환성을 검증했고 TPUv7 단일 칩에서 300억 매개변수 모델의 추론 처리량이 초당 2만5700토큰에 달했으며, 프로젝트는 아직 초기 단계로 동적 셰이프와 연산자 지원 확대 등을 로드맵에 두고 있다.
